# База знаний

Проверенные факты и грабли про Claude Code, Claude Desktop и облачные папки, добытые исследованием
2026-09-02 и сверенные по живой машине и бинарям. Запись без строки в этом индексе не существует —
добавили файл, добавьте и строку. Архитектурные решения живут в [spec/architecture.md](../spec/architecture.md):
здесь «как оно себя ведёт на самом деле», там «что мы поэтому выбрали».

Каждая запись прошла верификатора: утверждение, не найденное в первоисточниках и не подтверждённое
машиной, удалено или помечено «не проверено». Метки исследователей `[verified]/[likely]/[unverified]`
перенесены смыслом.

## claudeCode — поведение CLI

- [nativeCrossDevice.md](claudeCode/nativeCrossDevice.md) — нативного переноса локальной сессии Claude Code/Desktop на другую машину нет (проверено 2026-09-02: CLI 2.1.232, Desktop 1.40609.1 с CLI 2.1.255, CHANGELOG до 2.1.258): Remote Control — окно в живой процесс, Continue in Web/--teleport — сводка через облако, /desktop — та же машина, экспорт/импорт Desktop — в коде за фиче-флагом с неизвестным статусом; reconnection record RC живёт в самом транскрипте и .claude.json; CLAUDE_CODE_PROJECT_DIR_NAME — одно имя на запуск; issues #22648/#28791/#73639 без ответа Anthropic
- [nativeMemory.md](claudeCode/nativeMemory.md) — своя память Claude Code по бинарю 2.1.260: три уровня (файловая авто-память, сторы `CLAUDE_MEMORY_STORES` с `memory-watcher`, серверная через `CLAUDE_CODE_MEMORY_API_*`) плюс командный и организационный с ACL по группам и лимитами; предохранители синхронизации (пауза после серии отказов, удержание массового удаления); ключевое для нас — стор монтируется на каталог и **отказывается** синхронизировать непустой (`mount_dir_unmanifested_nonempty`), то есть войны за `memory/` не будет; у владельца серверная часть выключена целиком; чем это меняет позиционирование этапа 5
- [configDirLayout.md](claudeCode/configDirLayout.md) — раскладка `~/.claude` на 2026-09-02 (CLI 2.1.232 / Desktop-CLI 2.1.255), сверенная по бинарю и живой машине: инвентарь по классам горячее/общее/path-keyed/runtime; `.claude.json` — 57 KB кешей, ноль переносимых полей, переписывается поминутно, seedTrust туда нельзя; Keychain и `.credentials.json` ключуются `CLAUDE_CONFIG_DIR` и недокументированной `CLAUDE_SECURESTORAGE_CONFIG_DIR`; зашитый в бинарь список machine-local (`rOE`); симлинки `projects/<enc>` работают по основному пути, но слепы для фолбэк-сканов (первая сессия в новом cwd создаёт реальный каталог); два свипа-удалителя; стор Desktop и порча дескрипторов.
- [transcriptFormat.md](claudeCode/transcriptFormat.md) — формат JSONL-транскрипта CLI 2.1.219/2.1.232/2.1.255 (проверено live 2026-09-02): кодировка `projects/<enc(cwd)>`, рождение файла после SessionStart (+16 мс после хука), запись open/append/close без удержанного fd, четверть–треть строк без `uuid` (состояние, не сообщения), выбор листа при resume — ветвь последнего `last-prompt` (не max `timestamp`), таблица различий писателя и читателя 2.1.232/2.1.255/2.1.258, штатные немонотонности и сироты в одномашинных файлах, сайдкары, размеры (логический ≠ на диске), правила слияния
- [projectDirEncoding.md](claudeCode/projectDirEncoding.md) — точная формула каталога `projects/<enc>` из strings 2.1.232/2.1.255 (UTF-16-юниты, `[^a-zA-Z0-9]`→`-`, >200 → 200 + `-` + base36(|hash|), хэш `(t<<5)-t+unit|0` по полной строке); на вход CLI подаёт `NFC(realpath(cwd))` (измерено 2026-09-02: NFD-каталог → NFC в stdin хука и в enc); контракт `CLAUDE_CODE_PROJECT_DIR_NAME` `[A-Za-z0-9_-]{1,64}` минус device-имена с тихим откатом; таблица эталонов; что из этого следует для предсказания enc реконсилером
- [hooksLifecycle.md](claudeCode/hooksLifecycle.md) — жизненный цикл хуков Claude Code для синка (2.1.232/2.1.255, проверено на живой машине 2026-09-02): SessionStart завершается до рождения транскрипта (+16–34 мс stream-json, ~4 с в -p), stdin/env хука, таймаут SessionStart и SessionEnd (1500/60000 мс + failsafe +5000/+3500), UserPromptSubmit как единственный гейт ввода, Desktop спавнит CLI с user-настройками и белым списком env, CLAUDE_CODE_SKIP_PROMPT_HISTORY (хуку не передаётся), retention- и rmdir-свипы (#86952, #41458), реестр sessions/ и dead-owner; Windows-часть и сценарии судей помечены как непроверенные
- [promptCache.md](claudeCode/promptCache.md) — prompt cache глазами ролика Нейропросвещения (2026-08-21) и бинаря 2.1.260: множители ×1.25/×2/×0.1 и что ломает префикс (модель, effort, fast mode, compact, инструменты); главный совет ролика устарел — на подписке часовой TTL уже автоматический (`CLAUDE_CODE_PROMPT_CACHE_TTL`), `ENABLE_PROMPT_CACHING_1H=1` нужен только сабагентам; флаги `DISABLE_PROMPT_CACHING*`/`FORCE_PROMPT_CACHING_5M` выключают кэш; три точки касания движка — хуки не ломают префикс, managed `settings.json` разносит флаг, поля свежести кэша на resume пока не читаются
- [resumeAndRelocation.md](claudeCode/resumeAndRelocation.md) — замеры 2026-09-04 в изолированном конфиге (CLI 2.1.258 и 2.1.232): resume из другого каталога транскрипт **не** переносит (файл остаётся под `enc` исходного cwd, поздние строки несут новый cwd, каталог нового пуст); `SessionStart` в интерактивном TTY выходит до появления и транскрипта, и самого каталога `projects/<enc>` — «ссылка первым шагом» выполнима буквально; `Stop` не срабатывает при ходе, кончившемся ошибкой (приходит только `SessionEnd`), поэтому коммит обязан висеть на обоих; правило листа (`ветвь последнего last-prompt`) подтверждено на headless `--resume`, но найдена дедупликация читателя по `message.id`: две записи с одним `message.id` схлопываются, и ветвь с чужим листом исчезает для читателя — union по `uuid` этого не видит
- [forkResumeMeasured.md](claudeCode/forkResumeMeasured.md) — замеры 2026-09-09 и 09-10 на CLI 2.1.260 в изолированном конфиге: какую ветвь разошедшейся сессии клиент показывает на самом деле. Модель предсказывала сторону листа последнего `last-prompt`, драйвер печатал это владельцу — но все три пути возобновления (неинтерактивный `-p`, настоящий tty, бинарь под entrypoint Desktop) продолжили от последней `user`-записи в порядке файла, а контрольный замер с `last-prompt` последней строкой ничего не изменил: поле называет реальный факт, но не точку возобновления. Здесь же ловушка `CLAUDE_CODE_CHILD_SESSION`: CLI, запущенный из сессии, молча перестаёт писать транскрипт, и замер выглядит осмысленным нулём. Границы: только 2.1.260, сам интерфейс Desktop не кликали
- [memoryIndexOverwritten.md](claudeCode/memoryIndexOverwritten.md) — наблюдение 2026-09-08: индекс `memory/MEMORY.md` дважды за час откатывался к дефолтному шаблону CLI («# Memory / Nothing remembered yet.») минутами после того, как сессия записала туда список открытых хендоффов; mtime файла предшествует коммиту тика, дефолтный текст в наших крейтах не встречается — пишет подсистема авто-памяти самого Claude Code. Следствие: список открытых потоков в `MEMORY.md` — расходник, поэтому `SessionStart` движка читает `memory/sessions/*.md` напрямую (`status: open` **только** из фронтматтера — в теле хендоффа эта строка встречается как проза)
- [mcpScope.md](claudeCode/mcpScope.md) — память по MCP в других средах (2026-09-13): `claude mcp add` без `-s user` регистрирует сервер только для одного проекта; клиент запускает stdio-сервер в каталоге проекта (замер `lsof`), и сервер берёт проект оттуда — но только существующий: `/tmp` иначе стал бы проектом `tmp`; как подключаются Claude Code, VibeIDE, VibeIDEA

## git — раскладки репозиториев

- [mergeDriverInvocation.md](git/mergeDriverInvocation.md) — когда git 2.50.1 зовёт драйвер слияния и что передаёт (прогоны 2026-09-02…03): только при изменении файла с обеих сторон; add/add → пустой `%O` (тот же вызов, что copy-import); одностороннее удаление применяется без драйвера; удаление против правки — конфликт дерева мимо драйвера; criss-cross строит виртуального предка тем же драйвером; exit ≠ 0 → `UU` и `MERGE_HEAD`, `merge --abort` чист; асимметричный драйвер сходится за одно слияние
- [lineEndings.md](git/lineEndings.md) — куда попадает CRLF (замер 2026-09-10, git 2.50.1): драйверу слияния git отдаёт индекс-форму, `%O`/`%A`/`%B` без `\r` даже при `* text eol=crlf` — значит сквозной гейт «драйвер + CRLF» не может упасть и был удалён; зато рабочее дерево конвертируется, а движок читает именно его, и один `\r` менял личность строки без `uuid`: LF против CRLF давали 16 строк вместо 12, а журнал памяти (ни одного `uuid` на 16 строк) удвоился бы целиком. Правило «терминатор — один `\n`, возврат каретки перед ним снимается» и три гейта под ним; почему правка `dest_is_union_of` не сделана
- [pushScan.md](git/pushScan.md) — чтение push на токены (2026-09-25): запись всего ввода `cat-file` до чтения ответа запирает обоих на 64 КиБ канала — ввод пишет отдельный поток; скан по объектам `rev-list <new> --not --all`, а не по итоговому дереву (токен, добавленный и убранный внутри push); `diff-tree -m` для слияний; вопросы по id, не по пути (перевод строки и не-UTF-8 в имени); потолок без сжатия `contentTooLarge`, скан кусками с хвостом признака
- [repoLayoutEdges.md](git/repoLayoutEdges.md) — что печатает `git rev-parse --git-common-dir` и что лежит в `.git`-файлах (git 2.50.1, 2026-09-02): репо/подкаталог/linked worktree/сабмодуль/worktree из сабмодуля/bare/separate-git-dir; относительные указатели (`--relative-paths`, сабмодули); discovery молча проходит сквозь битый или пустой вложенный `.git` к внешнему репо (exit 0) и слушается утёкшего `GIT_DIR`; Windows-worktree на Mac; коллизия имён по регистру ломает checkout стора на APFS

## toolchain — пак и инструменты кабинета

- [cabinetPitfalls.md](toolchain/cabinetPitfalls.md) — кабинет на start0 (фаза 3, 2026-09-24): `migrate dev` без терминала отказывает при любом предупреждении — `migrate diff` и `deploy`; миграция Postgres не транзакционна и остаётся наполовину, `migrate reset` агенту требует согласия человека; расширения пака открывали транзакции на голом клиенте мимо гардов; ошибка Prisma цитирует исходник, и `toThrow(подстрока)` совпадает с цитатой; `expect().rejects` в bun-types не промис — 28 утверждений не выполнялись; dev-движок в int-тестах уводил `/api/auth/*` на dev-клиент; `eslint --cache` на типах врёт после правки зависимости; Resend 6 отказ возвращает, а не бросает; собранный сервер читает `.env` силами Bun — юниту нужны `WorkingDirectory` и `NODE_ENV`; `ADD COLUMN SERIAL` нумерует старые строки в порядке чтения; `hooks.before` better-auth видит и прямые вызовы (`context.request` их отличает); лимитер better-auth без `trustedProxies` не считает цепочку `X-Forwarded-For`; плагин Point0 проверяет права после разбора ввода — отказ до всего только `.middleware`; индекс записи из JSON отвечает за унаследованные ключи; фильтр fail2ban без якоря читает вписанное запросом; хеш архива сборки меняется каждый раз — личность релиза по содержимому; journald делит записи по переводу строки — поля запроса в журнале сервера памяти экранируются; в int-тестах страница не рендерится; `fetchServer` шлёт запросы `POST`-ом — что меняет, говорит тип точки, а не метод; `set-cookie` better-auth гасит старые куки перед новыми — банке тестов нужна последняя пара по имени; Playwright изредка теряет контекст браузера при закрытии — смотреть на `(fail)`, а не на код выхода; пользователь из `createTestUser` не входит паролем — нужен `newUser`; `raiseAlerts` заменяет весь набор тревог — разовое сообщение только `notifyOwner`; `has_database_privilege` считает право `PUBLIC` правом каждой роли — снимать `PUBLIC` до проверки гранта; `z.undefined()` в объекте Zod 4 — обязательный ключ: формы входа отказывали каждому вошедшему без подписи у поля; `meta` ошибки пака приватный и до формы не доезжает — поле отказа отдельным публичным `field`; ключ перевода шаблоном гейт каталога считает мёртвым
- [oneLineInstall.md](toolchain/oneLineInstall.md) — установка одной строкой и `PATH` (2026-09-27): `install.sh`/`install.ps1` рядом с архивами и файл `latest` вместо разбора `index.json` в `sh`; `install` сам кладёт `~/.vibememory/bin` в `PATH` пользователя; домашняя папка для блока — родитель каталога движка, не `HOME`, иначе тесты дописали бы настоящий `~/.zshrc`; `Invoke-RestMethod` и octet-stream
- [windowsFromMac.md](toolchain/windowsFromMac.md) — Windows-архив собирается на Mac (2026-09-27): цель `x86_64-pc-windows-gnu` через `mingw-w64`, потому что `msvc` требует CRT и SDK Microsoft с принятием лицензии; `.exe` зависят только от системных библиотек Windows (проверено `objdump`); `releaseBuild.ps1` удалён, clippy под Windows остаётся на `msvc`
- [cabinetTables.md](toolchain/cabinetTables.md) — таблицы кабинета без горизонтального скролла (2026-09-25): `Table` пака держал `overflow-x-auto` и `whitespace-nowrap` на каждой ячейке; теперь ячейки переносятся, а в контейнере уже 42rem строка становится карточкой «колонка: значение» — подпись передаётся пропом `label`, потому что CSS не читает текст заголовка; `flex` на `td` ломает сложение; e2e на 375 и 1280 пикселях сразу поймал бейдж шире телефона
- [start0InSubdirectory.md](toolchain/start0InSubdirectory.md) — start0 v0.1.29 в подкаталоге `cabinet/` (спайки фазы 0, 2026-09-23): `1gr14 update` работает из подкаталога, но `git apply` там молча пропускает весь дифф с кодом 0 — только `--directory=cabinet`, атомарно дифф не ляжет никогда (хунки на вырезанное); `init.ts` сделал бы вложенный `git init`; husky в подкаталоге не ставит хуков, а не перехватывает `core.hooksPath`, как думал план; плагин `organization` на Prisma 7 работает, но генерат с `@db.Uuid` против text-id пака роняет миграцию и оставляет её применённой наполовину; start0 source-available — кабинет только в закрытом репозитории; сервер ~200–330 МБ, пулы пака по умолчанию до 24 соединений при 17 доступных, серверу хватает `dist` и пустого `node_modules`
