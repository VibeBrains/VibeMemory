# База знаний

Проверенные факты и грабли про Claude Code, Claude Desktop и облачные папки, добытые исследованием
2026-09-02 и сверенные по живой машине и бинарям. Запись без строки в этом индексе не существует —
добавили файл, добавьте и строку. Архитектурные решения живут в [spec/architecture.md](../spec/architecture.md):
здесь «как оно себя ведёт на самом деле», там «что мы поэтому выбрали».

Каждая запись прошла верификатора: утверждение, не найденное в первоисточниках и не подтверждённое
машиной, удалено или помечено «не проверено». Метки исследователей `[verified]/[likely]/[unverified]`
перенесены смыслом.

## claudeCode — поведение CLI

- [nativeCrossDevice.md](claudeCode/nativeCrossDevice.md) — нативного переноса локальной сессии Claude Code/Desktop на другую машину нет (проверено 2026-09-02: CLI 2.1.232, Desktop 1.40609.1 с CLI 2.1.255, CHANGELOG до 2.1.258): Remote Control — окно в живой процесс, Continue in Web/--teleport — сводка через облако, /desktop — та же машина, экспорт/импорт Desktop — в коде за фиче-флагом с неизвестным статусом; reconnection record RC живёт в самом транскрипте и .claude.json; CLAUDE_CODE_PROJECT_DIR_NAME — одно имя на запуск; issues #22648/#28791/#73639 без ответа Anthropic
- [configDirLayout.md](claudeCode/configDirLayout.md) — раскладка `~/.claude` на 2026-09-02 (CLI 2.1.232 / Desktop-CLI 2.1.255), сверенная по бинарю и живой машине: инвентарь по классам горячее/общее/path-keyed/runtime; `.claude.json` — 57 KB кешей, ноль переносимых полей, переписывается поминутно, seedTrust туда нельзя; Keychain и `.credentials.json` ключуются `CLAUDE_CONFIG_DIR` и недокументированной `CLAUDE_SECURESTORAGE_CONFIG_DIR`; зашитый в бинарь список machine-local (`rOE`); симлинки `projects/<enc>` работают по основному пути, но слепы для фолбэк-сканов (первая сессия в новом cwd создаёт реальный каталог); два свипа-удалителя; стор Desktop и порча дескрипторов.
- [transcriptFormat.md](claudeCode/transcriptFormat.md) — формат JSONL-транскрипта CLI 2.1.219/2.1.232/2.1.255 (проверено live 2026-09-02): кодировка `projects/<enc(cwd)>`, рождение файла после SessionStart (+16 мс после хука), запись open/append/close без удержанного fd, четверть–треть строк без `uuid` (состояние, не сообщения), выбор листа при resume — ветвь последнего `last-prompt` (не max `timestamp`), таблица различий писателя и читателя 2.1.232/2.1.255/2.1.258, штатные немонотонности и сироты в одномашинных файлах, сайдкары, размеры (логический ≠ на диске), правила слияния
- [projectDirEncoding.md](claudeCode/projectDirEncoding.md) — точная формула каталога `projects/<enc>` из strings 2.1.232/2.1.255 (UTF-16-юниты, `[^a-zA-Z0-9]`→`-`, >200 → 200 + `-` + base36(|hash|), хэш `(t<<5)-t+unit|0` по полной строке); на вход CLI подаёт `NFC(realpath(cwd))` (измерено 2026-09-02: NFD-каталог → NFC в stdin хука и в enc); контракт `CLAUDE_CODE_PROJECT_DIR_NAME` `[A-Za-z0-9_-]{1,64}` минус device-имена с тихим откатом; таблица эталонов; что из этого следует для предсказания enc реконсилером
- [hooksLifecycle.md](claudeCode/hooksLifecycle.md) — жизненный цикл хуков Claude Code для синка (2.1.232/2.1.255, проверено на живой машине 2026-09-02): SessionStart завершается до рождения транскрипта (+16–34 мс stream-json, ~4 с в -p), stdin/env хука, таймаут SessionStart и SessionEnd (1500/60000 мс + failsafe +5000/+3500), UserPromptSubmit как единственный гейт ввода, Desktop спавнит CLI с user-настройками и белым списком env, CLAUDE_CODE_SKIP_PROMPT_HISTORY (хуку не передаётся), retention- и rmdir-свипы (#86952, #41458), реестр sessions/ и dead-owner; Windows-часть и сценарии судей помечены как непроверенные
- [resumeAndRelocation.md](claudeCode/resumeAndRelocation.md) — замеры 2026-09-04 в изолированном конфиге (CLI 2.1.258 и 2.1.232): resume из другого каталога транскрипт **не** переносит (файл остаётся под `enc` исходного cwd, поздние строки несут новый cwd, каталог нового пуст); `SessionStart` в интерактивном TTY выходит до появления и транскрипта, и самого каталога `projects/<enc>` — «ссылка первым шагом» выполнима буквально; `Stop` не срабатывает при ходе, кончившемся ошибкой (приходит только `SessionEnd`), поэтому коммит обязан висеть на обоих; правило листа (`ветвь последнего last-prompt`) подтверждено на headless `--resume`, но найдена дедупликация читателя по `message.id`: две записи с одним `message.id` схлопываются, и ветвь с чужим листом исчезает для читателя — union по `uuid` этого не видит

## claudeDesktop — приложение и его стор сессий

- [sessionStore.md](claudeDesktop/sessionStore.md) — стор карточек Claude Desktop (`claude-code-sessions/<acct>/<org>/local_*.json`, Mac — симлинк в OneDrive): поля дескриптора и их «горячесть», загрузка/дедуп конфликт-копий, сопоставление с транскриптом по `cliSessionId` через спавн встроенного CLI `--resume`, слепота сканов к симлинкам и правило единственности id, порча карточек (`transcriptUnavailable`, `clearStaleResumeHandle`), bring-home-копии, запрет симлинков под конфиг-корнем, junction в MSIX на Windows; цифры стора на 2026-09-02 (165→166 карточек, 67/353 дегидрированных транскриптов), сверены верификатором по живой машине и бандлам.
- [probeSessions.md](claudeDesktop/probeSessions.md) — Desktop спавнит неинтерактивные CLI-«вспышки» ~300 мс в `$HOME`: без транскрипта и промптов, но с полным стартом и вызовом хуков (211 событий телеметрии, `tengu_run_hook` ×2); на машине владельца 30 таких следов из 90 `session-env`. Отсюда пустой стор по имени домашней папки и правило: `$HOME` — в `ignoreCwd`, а не хардкод в движке. Проверено, что это не планировщик VibeSter, не cron, не Cowork и не ручной запуск

## git — раскладки репозиториев

- [mergeDriverInvocation.md](git/mergeDriverInvocation.md) — когда git 2.50.1 зовёт драйвер слияния и что передаёт (прогоны 2026-09-02…03): только при изменении файла с обеих сторон; add/add → пустой `%O` (тот же вызов, что copy-import); одностороннее удаление применяется без драйвера; удаление против правки — конфликт дерева мимо драйвера; criss-cross строит виртуального предка тем же драйвером; exit ≠ 0 → `UU` и `MERGE_HEAD`, `merge --abort` чист; асимметричный драйвер сходится за одно слияние
- [repoLayoutEdges.md](git/repoLayoutEdges.md) — что печатает `git rev-parse --git-common-dir` и что лежит в `.git`-файлах (git 2.50.1, 2026-09-02): репо/подкаталог/linked worktree/сабмодуль/worktree из сабмодуля/bare/separate-git-dir; относительные указатели (`--relative-paths`, сабмодули); discovery молча проходит сквозь битый или пустой вложенный `.git` к внешнему репо (exit 0) и слушается утёкшего `GIT_DIR`; Windows-worktree на Mac; коллизия имён по регистру ломает checkout стора на APFS

## rust — ядро на Rust

- [crossPlatformPaths.md](rust/crossPlatformPaths.md) — грабли typed-path 0.12.3 (`derive`-эвристика, UNC без хвоста не absolute, `normalize` съедает ведущие `..`, путь констант), globset 0.4.20 (платформозависимый `backslash_escape`, `foo/**` ≠ `foo`, индексы по возрастанию), serde и serde_json на строках JSONL (`rename_all_fields`; `Cow` не заимствует; struct читается из JSON-массива позиционно — нужен гейт на `{`; что именно делает строку непрозрачной; замеры слияния 28 МБ / 64 МиБ), cargo/clippy 1.97 (пофилдное наследование workspace, глубина `include_str!`, `allow-*-in-tests` не для хелперов, гейт «без I/O» через `disallowed-methods`), `.gitattributes` для паритета на Windows

## design — ограничения движка

- [jsonlMergeInvariants.md](design/jsonlMergeInvariants.md) — почему слияние транскриптов устроено именно так: порядок файла влияет только на `last-wins`-состояние и на выбор видимой ветви; якорем может быть лишь запись с `uuid` (байт-идентичные блоки состояния дают неверную ветвь в 28–30 случаях из 54); кратность безuuid-строк — максимум, а не сумма; база решает членство, но предки выживших записей не удаляются; законы слияния, включая «закон второй машины» вместо ложного поглощения
- [desktopGuard.md](design/desktopGuard.md) — почему guard карточек Desktop устроен как храповик: экспорт не понижает `cliSessionId` и не выпускает `transcriptUnavailable`, импорт требует трёх измерений этой машины (предсказанная ссылка не годится), незнакомые поля едут нетронутыми, путь вне объявленных корней не переводится; цена каждого решения и что осталось открытым
- [memoryRecords.md](design/memoryRecords.md) — почему память — записи с причинностью, а не файлы с часами: журнал JSONL сливается готовым драйвером, `parent` вместо часов (две версии от одного родителя обе остаются), удаление не выводится из отсутствия файла, импорт молчит на нетронутой проекции; чем оплачено каждое решение и что осталось открытым
- [engineConstraints.md](design/engineConstraints.md) — что движок обязан и чего никогда не делает: 64 фатальные находки трёх судейских панелей (cloud-first 19, local-hot 24, git 21), сведённые в правила с «почему и откуда»; перепроверено на живой машине 2026-09-02 (ссылки и реальный каталог в projects/, живые pid и lsof, транскрипт, git-края worktree/сабмодуль/подкаталог, строки бинарей 2.1.232/2.1.255, доки hooks/CHANGELOG), спорное помечено «не проверено»/«[likely]», противоречия (#41458 vs fail-closed) оставлены обеими версиями.
- [migrationInbox.md](design/migrationInbox.md) — переезд как повторяемый импорт-слияние: облачная папка становится входящим лотком, пока в неё пишет другая машина; плейсхолдер по `st_blocks`, источник без единой записи, конфликт-копии с дефисными hostname и суффиксом с заглавной, карточки Desktop в outbox своей машины; дефект гейта `sessions`, найденный первым dry-run по реальному архиву
- [firstRealMigration.md](design/firstRealMigration.md) — первая живая миграция Mac 2026-09-05: докачка OneDrive чтением (×12 параллельно), живые сессии пишут во время apply → защита `switch` по реестру `sessions/<pid>.json`, `pgrep` слеп к Desktop, `enc` от `realpath` (`~/Projects` — симлинк), resume через симлинк работает только из cwd проекта, стор без хуков движка, полное правило «кто что коммитит», porcelain под обрезающим runner'ом, дисциплина правок и гейта
- [oldSchemeIntents.md](design/oldSchemeIntents.md) — раскопки перед удалением `init.sh`/`sync-repo`: пять замыслов старой схемы `-ALL-` (путь-независимое имя, горячее локально, ссылка вне облака, сравнение по множествам uuid а не байтам, память сливается по смыслу) и чем каждый закрыт в движке; два открытых пункта старого roadmap закрыты драйверами и doctor; что намеренно не переносится
- [firstHostSetup.md](design/firstHostSetup.md) — первый хост стора вживую: «Server accepts key» + «Permission denied» это парольная фраза без агента; на свежей Debian нет git; пустой последний аргумент через ssh исчезает (`${3:-}`); большой первый push обрывается и не возобновляется, а дробление по коммитам бесполезно, когда вся масса в одном коммите — работает `rsync --partial` файлов пакетов (и `openrsync` на macOS не знает `--info=progress2`); своп 2 ГиБ и лимиты `index-pack`; еженедельный `gc` в cron при `gc.auto=0`
