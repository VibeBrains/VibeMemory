# Память по MCP в других средах: область регистрации и проект по каталогу (2026-09-13)

## Ловушка: `claude mcp add` без `-s` — только этот проект

Мануал советовал `claude mcp add vibememory …` без области.
Claude Code записал сервер в `Local config (private to you in this project)` — только для каталога, где команду запустили.
В любом другом проекте, в том числе в сессии агента VibeIDEA, памяти не было.
Правильно: `claude mcp add -s user …` — `User config (available in all your projects)`.
Сделано на этой машине штатной командой; `.claude.json` при этом правит сам `claude mcp`, не движок.

## Замер: с каким каталогом клиент запускает stdio-сервер

`lsof -d cwd` у живого `vibememory-mcp` из сессии Claude Code: каталог проекта сессии.
На этом держится проект по умолчанию: сервер разрешает свой `cwd` теми же правилами имён, что хук `SessionStart` (`project::resolve` — одна функция на двоих).

## Находка живой проверки: каталог — ещё не проект

Первая версия брала любое имя, которое дают правила.
Сервер, запущенный в `/tmp`, объявил себя в проекте `tmp` — и запись без `project` создала бы мусорный проект.
Теперь проект по каталогу берётся, только если `store/projects/<имя>` уже есть; иначе запись требует `project` явно.
Проверено вживую: VibeIDE и VibeIDEA называют свои проекты, `/tmp` и домашний каталог — молчат.

## Кто как подключает

| Среда | Как | Состояние |
|---|---|---|
| Claude Code | `claude mcp add -s user` | подключено, `Connected` |
| VibeIDE | свой MCP-клиент агента, `~/.vibeide/mcp.json`, stdio `command`/`args` | запись вписана; в самой IDE не проверено; хендофф — находить сервер самим |
| VibeIDEA | своего клиента для чужих серверов нет, ACP-агентам в `session/new` уходят только инструменты IDE | хендофф: свой stdio-клиент и сервер памяти в `session/new` |
