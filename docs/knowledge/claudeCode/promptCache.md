# Prompt cache в Claude Code: что стоит лимитов и где рычаги (2026-09-08)

Источник — ролик «Срочно проверь Claude на /usage. Там ФЛАГ, который съедает лимиты»
(Нейропросвещение, 2026-08-21, 15:32), разобранный по авто-субтитрам; кадры получить не удалось
(YouTube отдал 403 на видеопоток). Утверждения автора ниже помечены как утверждения; что сверено
по бинарю Desktop-CLI 2.1.260 (`strings` установленного `claude`) — названо фактом. Смысл записи
не в пересказе, а в том, что **главный совет ролика за три недели устарел наполовину**, и в том,
где у движка вообще есть точки касания с кэшем.

## Как работает (утверждения автора, согласуются с публичной ценой API)

- Множители к цене входа: обычный ввод ×1; запись в 5-минутный кэш ×1.25; запись в часовой ×2;
  чтение из кэша ×0.1. Автор переносит долларовую арифметику API на лимиты подписки «в тех же
  пропорциях» — это его допущение, документально не подтверждено.
- Часовой кэш окупается с третьего запроса, 5-минутный — со второго. Дальше каждый ход в живом
  кэше стоит десятую часть.
- TTL считается от **начала** ответа модели, не от конца: ответ, который думался 4 минуты,
  оставляет минуту на следующий вопрос до истечения 5-минутного кэша. *Не проверено.*
- Что ломает кэш (перечитывание всего контекста по полной цене): смена модели; смена effort;
  fast mode — один раз за разговор, дальше переключение бесплатно; MCP — только если инструменты
  попадают в префикс (по умолчанию отложены, в контекст идут имена); плагины почти никогда;
  запрет целого инструмента; `/compact`; обновление CLI.
- Кэш не делится между worktree одного репозитория: у каждого свой префикс (cwd и git-статус в
  системном промпте) — следствие устройства, а не отдельное правило.
- На выходные токены рычаг один — effort, и выбирать его в начале сессии.

## Приёмы (утверждения автора)

- `/clear` в конце задачи дешевле `/compact`: compact — сам по себе крупный запрос по всей
  истории. Rewind возвращает в уже построенный префикс.
- `CLAUDE.md` короче 200 строк — «совет основателя Claude Code», файл пересчитывается каждый раз.
- CLI сервиса всегда экономнее его MCP. Раз в полгода вычищать скиллы и хуки, возвращать только то,
  без чего стало хуже (`skill-doctor`).
- Скиллы-«экономайзеры» контекста дают 5–10 %, не таблетка.
- Где смотреть: `/usage` → Behavior flags (CLI сам подсвечивает поведение, съедающее ≥10 %),
  `/insights` — отчёт о стиле работы.
- Кому актуально: подписка ×1 — не спасёт (лимиты съедает выход), ×5 — самое ценное, ×20 —
  «забейте».

## Что сверено по бинарю 2.1.260 — и что из ролика уже не так

Строки из установленного `claude` (Desktop CLI 2.1.260), дословно:

> `CLAUDE_CODE_PROMPT_CACHE_TTL` — Prompt cache TTL for the main conversation (interactive, `-p`
> and SDK turns, plus the helpers that run inline with it): "5m" or "1h". **Unset = automatic:
> 1 hour on a Claude subscription within its usage limits**, 5 minutes on an API key, Bedrock…

> `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` — "5m" or "1h". Unset = automatic (**5 minutes unless
> `ENABLE_PROMPT_CACHING_1H=1`**). The `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` environment
> variable takes precedence.

Следствия:

- **Для основного разговора на подписке часовой кэш включён автоматически.** Совет ролика
  «поставь `ENABLE_PROMPT_CACHING_1H=1`» для него больше не нужен — сессия Claude Code сама
  сообщает модели: «This session's requests use a 1-hour Anthropic prompt-cache TTL».
- **Флаг остался нужен сабагентам:** без него у них 5 минут. Актуально тому, кто гоняет `Agent`
  и workflows.
- В бинаре есть и рычаги, **выключающие** кэш: `DISABLE_PROMPT_CACHING`,
  `DISABLE_PROMPT_CACHING_{OPUS,SONNET,HAIKU,FABLE,MYTHOS}`, `FORCE_PROMPT_CACHING_5M`. Попав в
  `env` файла `settings.json`, они «съедают лимиты» буквально — и через managed copy уедут на все
  машины.
- Хук `SessionStart` на `resume`/`fork` с 2.1.251 получает четыре поля свежести кэша:
  `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired`,
  `estimated_cache_write_usd` (см. [hooksLifecycle.md](hooksLifecycle.md)). Движок их пока не читает.

## Точки касания движка с кэшем

Кэш серверный и ключуется содержимым префикса; «добавить кэш в VibeMemory» невозможно. Но:

1. **Хуки движка кэш не ломают** — проверено по коду 2026-09-08: `SessionStart` пишет
   `additionalContext` один раз на старте, `UserPromptSubmit` только блокирует (без контекста),
   `Stop` и `SessionEnd` в stdout не пишут. За каждый ход в префикс ничего не подмешивается.
   Про `CLAUDE.md`, который тик может обновить посреди сессии: по бинарю 2.1.260 CLI перечитывает
   его только по явному `add-dir … reload` и по `watchPaths`, которые хук должен сам вернуть — наши
   хуки их не возвращают, строк про автоматическое перечитывание при изменении файла в бинаре нет.
   Значит обновлённая копия подхватится на следующем старте сессии, а префикс текущей не тронет.
   *Вывод по строкам бинаря, не измерение расхода.*
2. **`settings.json` — managed copy**, значит выставленный на одной машине `ENABLE_PROMPT_CACHING_1H=1`
   приезжает на остальные с тиком, а `doctor` ловит в `env` флаги, выключающие кэш (шаг
   `PromptCacheEnv`). Оговорка дня: до 2026-09-08 доставка копий не работала вовсе — сверка была
   обещана спекой и текстом сообщения, но не написана; разбор —
   [design/managedCopies.md](../design/managedCopies.md).
3. **Поля свежести на resume** — движок мог бы при возобновлении (особенно переехавшей с другой
   машины сессии) сказать одной строкой, что кэш протух и первый ход перечитает контекст.
