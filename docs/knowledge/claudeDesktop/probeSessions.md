# Desktop запускает CLI-«вспышки» в домашнем каталоге (2026-09-06/07)

## Факт

Claude Desktop время от времени спавнит **неинтерактивную CLI-сессию длиной около 300 мс** с
рабочим каталогом `$HOME`. Она не пишет транскрипта и не задаёт ни одного промпта, но проходит
полный старт: читает управляемые настройки, грузит навыки, ищет каталоги, биндит UDS-сокет и
**вызывает хуки**.

Разобрано по `~/.claude/telemetry/1p_failed_events.<sid>.*.json` сессии
`cbbf78d2-66e0-49b8-bba3-2a3d0c220c56` (6 сентября, 05:03:31.227 → 05:03:31.516 UTC):

- `entrypoint: claude-desktop`, `client_type: claude-desktop`, `is_interactive: false`,
  `terminal: non-interactive`, CLI 2.1.260, agent SDK 0.3.260;
- 211 событий за 289 мс: `tengu_skill_loaded` ×137, `tengu_feature_ok` ×34,
  `tengu_plugin_enabled_for_session` ×4, `tengu_dir_search` ×3, `tengu_uds_startup_bind`,
  **`tengu_run_hook` ×2** (в 05:03:31.313 и 05:03:31.501 — это наши `SessionStart` и `SessionEnd`);
- в реестре `sessions/<pid>.json` её нет (процесс умер раньше, чем кто-либо посмотрел), в
  `.claude.json` записи о проекте `/Users/borodatych` тоже нет, в `history.jsonl` — ноль промптов.

На машине владельца таких следов **30 из 90** каталогов `session-env` (остальные 60 —
настоящие сессии с транскриптами). Каждый след — пустой каталог `session-env/<sid>/` на 0 байт
плюс, иногда, файл телеметрии.

## Почему это важно движку

Хук `SessionStart` отрабатывает на каждой такой вспышке и делает ровно то, что обязан: `$HOME` —
не git-репозиторий, значит имя стора берётся по имени папки, и появляется стор `borodatych` со
ссылкой на него. Ни одной записи в него никогда не попадёт.

**Ответ — `ignoreCwd`, а не догадки в коде.** Домашний каталог вносится в конфиг рядом с `/`;
хук тогда молчит и ничего не создаёт (проверено живым прогоном 2026-09-07). Захардкодить «дом
игнорировать» нельзя: кто-то работает в `~` по-настоящему, и решать это владельцу, а не движку.

## Чем это НЕ является (проверено, чтобы не осталось догадок)

- **Не планировщик VibeSter.** `ru.vibester.worker.plist` действительно ищет `claude`, но в его
  логах на этой машине — `«Claude Code не найден»`, и `--version`-проба сессии не создаёт.
- **Не cron** — пустой; **не Cowork/scheduled** — их сессии лежат в
  `local-agent-mode-sessions` и имеют собственный тип; **не ручной запуск** — в `~/.zsh_history`
  вызовов `claude` из дома нет.
