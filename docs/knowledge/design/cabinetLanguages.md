# Языки кабинета (2026-09-25)

Решение владельца 25.09.2026: базовый язык — русский, по умолчанию интерфейс на русском всегда, английский — вторым,
переключатель `ru | en` в верхней панели. Правило записано в глобальные правила, раздел «Локализация».

## Устройство

- Русский — в коде (`cabinet/src/modules/i18n/ru/<область>.ts`), остальные языки — файлы `locales/<код>.json`.
  Ключ, которого нет в файле, говорит по-русски.
- `Key` — `keyof typeof ru`: неизвестный ключ не компилируется, и половина гейта («ключ без строки») достаётся даром.
- Язык — cookie `locale` через `CookieStore` пака, как тема: один и тот же `localeCookie.get()` работает на сервере
  (из запроса) и в браузере. У вошедшего выбор пишется ещё и в `user.locale` — по нему уходят письма.
- `t()` читает язык при каждом вызове, поэтому зовётся при отрисовке, а не на уровне модуля: константа модуля
  вычисляется один раз и застывает на языке первого запроса.
- Переключение перезагружает страницу. Слова читаются один раз при отрисовке, и новый язык — новая страница, а не
  заплатка на старой: так схемы форм, заголовки и тексты в замыканиях не остаются на прежнем языке.
- Сообщения zod — по языку запроса через `z.config({ localeError })`, который смотрит `currentLocale()` на каждом
  сообщении: общий `z.config` один на процесс, а запросы на разных языках идут параллельно.
- Отказы сервера переводит сервер: `refuse(t('…'))` в языке запроса. Логика по тексту не решает — тесты сверяют код
  (`meta.code`) или `t(ключ)`.
- Письма вне запроса: `translate(locale, …)` с языком получателя; тревоги владельцу — `notifyOwner({ message: (tr)
  => … })`, где `tr` — перевод на язык владельца.
- Элемент внутри фразы (`<code>`, ссылка) — `withNodes(t('…'), { name: <code/> })`: фраза остаётся одним ключом,
  и каждый язык ставит элемент туда, куда требует порядок слов.

## Гейт

`modules/i18n/test/catalog.unit.test.ts` разбирает исходники TypeScript API и падает на тексте в JSX, на подписи в
текстовом пропе или поле объекта (`label`, `message`, `subject`, `lines`…), на заголовке `.head('…')`, на строке в
`refuse`/`AppError`/`toast`, на мёртвом ключе, на файле языка без ключа или с лишним ключом и на разных подстановках.
Код в `<code>`/`<pre>` не переводится. Файлы не интерфейса перечислены в гейте с причиной (мониторы Axiom, проверки env,
журнал задач, имена шрифтов). Мутации — голый текст в разметке и в пропе, ключ без перевода, мёртвый ключ, чужая
подстановка, голый отказ — гейт ловит все.

## Грабли

- SSR-страницы в int-тестах не рендерятся: им нужен клиентский сервер разработки. Язык страницы проверяется в e2e.
- Поле даты читало ввод `new Date(value)`, а дата на русском так не читается: нужен `parseDate` по языку страницы.
- Разные исполнители перевели account как «аккаунт» и «учётка» — термины сведены к «учётке», как в документации.
  Слово «сессия» оставлено за сессиями агентов, браузерные — «сеансы».
- `section.tsx` пака держал карту размеров в поле `h1: '2xl'`, и гейт принимал её за заголовок — карта вынесена в
  константы, гейт не ослаблен.
