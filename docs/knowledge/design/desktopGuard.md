# Почему guard дескрипторов Desktop — храповик, а не синхронизация (2026-09-03)

Карточка вкладки Code — единственный артефакт, который **портит третья сторона**. Транскрипт
пишет CLI, память пишем мы, а дескриптор Desktop переписывает целиком при каждом фокусе и по
своему усмотрению стирает из него привязку к транскрипту. Отсюда все решения ниже; факты про
поведение приложения — [claudeDesktop/sessionStore.md](../claudeDesktop/sessionStore.md).

## Решения и чем оплачены

- **Экспорт — храповик, а не «последняя версия побеждает».** Карточка может получить транскрипт,
  но не потерять: `clearStaleResumeHandle` стирает `cliSessionId` при промахе резюме, и обратного
  механизма в приложении нет. Экспортировать это — разнести необратимую порчу на все машины за
  минуты. **Цена:** пока порча не починена, в outbox лежит версия старее локальной, и её
  `lastFocusedAt`/`completedTurns` на других машинах отстают. Осознанно: неточный счётчик дешевле
  потерянной привязки.
- **`transcriptUnavailable` не покидает машину.** Это вердикт про **этот** диск: приложение
  ставит пометку, только когда доверяет своему `CLAUDE_CONFIG_DIR`, а транскрипт может лежать на
  другой машине или за симлинком, к которому сканы приложения слепы. **Цена:** карточка, у
  которой транскрипт действительно потерян везде, будет вечно держаться в экспорте — её видно
  в `doctor` по причине `markedUnavailable`.
- **Импорт требует трёх измерений, а не предположений.** Каталог существует, транскрипт в сторе,
  и ссылка **подтверждена** `transcript_path` этой машины. Предсказанная реконсилером ссылка
  гейт не проходит: на промахе резюме Desktop стирает `cliSessionId`, то есть неудачный импорт
  стоит не «попробуем позже», а необратимой потери. **Цена:** карточка чужой машины появляется
  на такт-два позже, чем могла бы. Тип `MachineFacts` заведён ровно для того, чтобы вызывающий
  не мог подсунуть в гейт свой план вместо замера: булево, вычисленное из намерений, от
  измеренного не отличить.
- **Незнакомые поля переносятся нетронутыми.** Формат дескриптора не документирован вовсе —
  только код бандла, — и следующий релиз добавит ключ. Движок здесь курьер: разбираются шесть
  полей, остальное едет как есть и проверяется круговым тестом. **Цена:** ключ, который окажется
  машинно-локальным (счётчик, путь), уедет вместе с карточкой, пока мы не узнаем о нём и не
  внесём в разбор.
- **Путь вне объявленных корней не переводится и потому не экспортируется.** Корень в
  `config.json` — это заявление владельца «этот каталог означает то же на другой машине».
  Без заявления любое переписывание пути — угадывание, а угаданный `cwd` даёт отказ
  `prepareSpawnCwd` и стёртую привязку. **Цена:** карточки скрэтч-сессий и раннера остаются
  локальными, пока владелец не объявит корень.
- **Самый длинный подходящий корень.** Вложенные корни (`/Users/x` и `/Users/x/Projects`) иначе
  дали бы разный портативный путь в зависимости от порядка обхода; ничья по длине разрешается по
  имени, чтобы две машины не разошлись в том, каким корнем назван один каталог.

## Что осталось открытым

- Перечитывает ли Desktop стор без рестарта — не проверено; если нет, импортированные карточки
  появляются после перезапуска приложения.
- Ни одного `observed`-кейса: стор дескрипторов лежит в облачной папке с дегидрированными
  файлами, читать её нельзя. Форма полей взята из опубликованных частот по 165 файлам, значения
  синтетические — [manuals/desktopFixtures.md](../../manuals/desktopFixtures.md).
- Политика приложения «components under the config root may not be symlinks» может ужесточиться:
  сегодня она терпит запись транскриптов через ссылку `projects/<enc>`, а завтра карточка может
  начать требовать реального каталога.
