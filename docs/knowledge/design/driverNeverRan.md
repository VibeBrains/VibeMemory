# Драйвер слияния, который ни разу не запускался (замер 2026-09-11)

Драйвер слияния JSONL — то, что сводит транскрипт, продолженный на двух машинах. Он написан,
покрыт фикстурами и законами, зарегистрирован `install` в `.git/config` стора и проверен
сквозными тестами с настоящим git. На этой машине git **не мог его запустить ни разу**.

## Измерение

```
строка драйвера в .git/config стора:  vibememory merge-driver jsonl %O %A %B %P
PATH тика (launchctl print):          /usr/bin:/bin:/usr/sbin:/sbin
command -v vibememory в терминале:    не найден
```

Трёхстороннее слияние с этой строкой в окружении тика:

```
vibememory merge-driver jsonl .merge_file_… 'projects/P/s.jsonl': vibememory: command not found
CONFLICT (content): Merge conflict in projects/P/s.jsonl          → UU
```

С абсолютным путём та же операция даёт `Merge made by the 'ort' strategy`, все три записи на
месте.

## Почему этого не видел никто

**Стор ни разу не сливался.** 1299 коммитов, ноль merge-коммитов, один автор. Пока пишет одна
машина, каждая интеграция — fast-forward, и драйвер git не нужен вовсе. Он понадобился бы в первый
же раз, когда две машины изменят один файл, — ровно тогда, когда подключится GPD. Тик сделал бы
`merge --abort`, ушёл бы в back-off, и машины молча разошлись бы.

**Гейт проверял другую строку.** `merge_driver_git.rs` регистрировал драйвер сам — абсолютным
путём тестового бинаря — и сливал в окружении разработчика. Строку, которую пишет `install`, не
исполнял ни один тест. Тот же класс, что в [memoryNeverMetReality.md](memoryNeverMetReality.md):
гейт доказывал, что код соответствует нашему представлению, а не тому, что стоит на машине.

## Что изменено

- Строка драйвера строится из раскладки машины:
  `VIBEMEMORY_DIR='<движок>' '<бинарь>' merge-driver jsonl %O %A %B %P`. Абсолютный путь здесь
  уместен: `.git/config` не коммитится и принадлежит машине. Каталог движка едет вместе со строкой
  по той же причине, что в хуках: карантин и журнал слияний принадлежат движку, поставившему
  драйвер.
- Строка прежней установки распознаётся по хвосту `merge-driver <имя> %O %A %B %P` и заменяется,
  как заменяются старые хуки. Чужой драйвер — конфликт, движок его не трогает.
- Тесты конфигурируют репозиторий **тем, что пишет `install`** (`install::git_settings`,
  `GITATTRIBUTES`), кладут бинарь туда, куда указывает строка, и сливают **так, как сливает тик**:
  `env_clear`, `PATH` launchd, свой дом.
- У `doctor` новый шаг «merge drivers start from git's shell». Строка драйвера с `--version` вместо
  аргументов слияния запускается через git-алиас, то есть тем же шеллом, которым git запускает
  драйвер (на Windows это `sh` из поставки Git for Windows — вживую не проверено), а на macOS ещё и
  в окружении тика. При отказе видно, что сказал шелл: для этого у `git::run_with_timeout`
  появился вариант `run_capturing`, сохраняющий stderr.

## Оговорка про тестовый харнесс

В тестах, где `apply` проходит весь план, «движком» становится сам тестовый харнесс: `install`
копирует `current_exe`. На `--version` он отвечает не как движок, и проба падала бы. Такую оговорку
проект уже делал для проверки после копирования (`install_binary`), но там признак — имя
запущенной программы. Для пробы этого мало: гейт самой пробы тоже запускается из харнесса и кладёт
заглушку руками, и её надо запускать. Поэтому признак — заметка о происхождении
`bin/vibememory.source`: проба пропускается, только если установленный файл — копия именно той
программы, что запущена сейчас, **и** запущен не движок. На машине владельца имена совпадают, и
ничего не хешируется.

## Подделки

Десять, все ловятся: драйвер голым именем; без кавычек; кавычка внутри без экранирования;
обратные слеши не заменены; без дома — относительный путь; прямое чтение `HOME`; проба глотает
отказ; строка прежней установки считается конфликтом; оговорка только по имени; проба не
подключена к плану.

## Правило

> **Гейт обязан исполнять ту строку, которую пишет продукт, в том окружении, в котором её
> исполнит продукт.** Тест со своей, более удобной строкой проверяет код, которым никто не
> пользуется.

## Проверено на живой машине (2026-09-11)

После трёх коммитов движок переустановлен на этой машине обычным `install`. Он сделал ровно
семь шагов: две строки драйвера (старые голые заменены), бинарь движка и сервера памяти, подпись,
проба драйверов, хуки. Шестнадцать шагов уже стояли на месте.

- `doctor` из установленного движка — 23 шага `ok`, код выхода 0, среди них
  `merge drivers start from git's shell`.
- В `.git/config` стора:
  `VIBEMEMORY_DIR='/Users/borodatych/.vibememory' '/Users/borodatych/.vibememory/bin/vibememory' merge-driver jsonl %O %A %B %P`.
- Хуков в `settings.json` по одному на событие, все в кавычках: строки прежней установки
  заменены, а не добавлены вторыми.
- Утреннее воспроизведение повторено со строкой, которую записал `install`, в окружении тика
  (`env -i`, `PATH` launchd): `Merge made by the 'ort' strategy`, три записи, ни одного маркера
  конфликта. Утром на том же месте был `command not found`.
