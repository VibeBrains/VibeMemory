# Маршрут «папка → команда» на живой машине (2026-09-27)

Первая живая проверка сессий команды нашла три расхождения между маской в `stores.<id>.cwd` и тем, что задумал человек.
Ни одно не давало ошибки: сессия молча уходила в личный стор.

## Регистр

Маска `/Volumes/Storage/Caches/vibememory/teamTest/**` не совпала с каталогом `/Volumes/Storage/Caches/VibeMemory/teamTest`.
`cd` по маске работал: APFS находит каталог в любом регистре.
Claude Code сообщает cwd в регистре диска, а POSIX-маска сравнивалась байт-в-байт.

Решение: регистр — свойство файловой системы, а не синтаксиса пути.
`CaseRule::HOST` — без учёта регистра на macOS и Windows, с учётом на Linux; ядро получает правило параметром, фикстуры задают его полем `case`.
`canonicalize` на macOS возвращает написание с диска — `doctor` предлагает маску в нём.

## `dir/**` без самого `dir`

`globset` не берёт корень поддерева: `acme/**` не совпадает с `acme`.
Спека конфига это честно записывала («нужны обе строки»), а пример `stores` в той же спеке писал одну строку.
Сессия, открытая в корне проекта, — самый частый случай, и он промахивался.

Решение: `dir/**` компилируется в две глобы — поддерево и сам корень — для всех трёх видов масок (`stores.cwd`, `nameOverrides`, `ignoreCwd`), чтобы правило чтения путей осталось одним.
На живом конфиге владельца ни одна маска на старом поведении не держалась.

## Привязка не переставляется

Первая сессия в папке привязала `~/.claude/projects/<enc>` к личному стору ещё при неверной маске.
После исправления маски хук ответил правильным стором, но ссылку не тронул — это правило: под живой сессией перелинковка теряет её.
Лечится `vibememory project move`; `doctor` теперь называет такие проекты сам.

## Команда вместо ручной правки

Маршрут пишется командой `vibememory route add`, а `project move` делает это сам.
Спека конфига записывала принцип «этот конфиг движок не переписывает никогда: он ваш».
Переписать файл целиком через `serde_json::Value` значило бы переставить ключи по алфавиту и потерять оформление владельца, а включать `preserve_order` в `serde_json` нельзя: признак один на всю сборку и меняет порядок всех JSON-объектов движка.
Поэтому `vibememory_core::json_edit` находит в тексте диапазон значения ключа верхнего уровня и меняет только его — остальные байты файла те же.

## Один сервер памяти

До маршрута память команды без стора на машине (`memory`) шла через HTTP-сервер `vibememory-<команда>`, зарегистрированный в Claude Code, рядом с локальным `vibememory`.
У владельца в одной сессии было два сервера памяти — `vibememory` и `vibememory-personal` — и агент сам выбирал, куда писать.
Теперь локальный сервер в каталоге с маршрутом на такую команду сам ходит на её хост: запросы идут через `curl`, как у `connect`, — в бинаре нет TLS, а `rustls` через `ring` принёс бы C-код и сломал бы сборку под Windows без линкера.
Токен уходит в `curl` через файл конфигурации с правами владельца, который удаляется, когда сервер останавливается: аргументы процесса видит каждый пользователь машины.
Регистрации `vibememory-<команда>` движок только читает из `.claude.json` — при `CLAUDE_CONFIG_DIR` файл лежит внутри этого каталога, а не в домашнем — и называет лишние в `doctor`.
