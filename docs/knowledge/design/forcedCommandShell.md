# Вход ключом машины: принудительная команда и `pre-receive` (фаза 2, 2026-09-23)

Машина участника ходит на хост ssh-ключом под `vmgit`, и оболочки у неё нет. Каждая строка
`~vmgit/.ssh/authorized_keys` — `restrict,command="/srv/vibememory/bin/vibememory-mcp shell mk_<id>"`,
а что просил клиент, сервер читает из `SSH_ORIGINAL_COMMAND`. Код — `crates/vibememory-mcp/src/{shell,receive,hostops}.rs`,
спека — [hostShellSpec.md](../../manuals/hostShellSpec.md). Здесь — то, что выяснилось по дороге.

## stderr команды принадлежит клиенту

Контракт отказа — код первой строкой stderr: `vibememory: <код>`. Тик участника ищет его в выводе
`git push`, где git показывает stderr хука с приставкой `remote: `.

Строку журнала хоста команда пишет в syslog (`/dev/log`, его читает journald). Первая версия при
отсутствии syslog писала её в stderr — и сквозной тест на Mac, где `/dev/log` нет, поймал это:
строка журнала вставала **перед** кодом, и первая строка переставала быть кодом.

Правило: у команд, чей stderr — клиента (`shell`, `pre-receive`, сервер памяти по ssh), журнал —
syslog или никуда. У команд юнитов и оператора (`access-apply`, `status`) — syslog или stderr, его
забирает journald юнита.

## `SSH_ORIGINAL_COMMAND` — текст из сети

Команда разбирается ровно в четыре формы до того, как тронут хоть один репозиторий. Путь стора
принимается только как `teams/<слаг>.git` или абсолютный под `/srv/vibememory/teams`, в кавычках или
без, а слаг проходит правило имён снимка — в нём нет места `..`, `/`, кавычкам и `;`. git запускается
по пути, собранному из слага на хосте, а не по пути клиента: `git upload-pack /srv/vibememory/teams/<слаг>.git`.

Каталог удалённой команды `<слаг>.deleted-<дата>.git` — тоже не путь стора: он не отдаётся никому.

## Второй файл ключей мимо принудительных команд

По умолчанию sshd Debian читает `.ssh/authorized_keys` **и** `.ssh/authorized_keys2`. Строки второго
файла прошли бы мимо `restrict,command=…`. Блок `Match User vmgit` теперь несёт
`AuthorizedKeysFile .ssh/authorized_keys` — ровно тот файл, который пишет применение снимка. Пункт
был в плане фазы 0 и тогда не был сделан; закрыт в фазе 2.

## Как проверить всю цепочку без хоста

Клиент git ходит по ssh командой из `GIT_SSH_COMMAND`. Подставной скрипт берёт последний аргумент —
команду, которую git просит выполнить, — кладёт в `SSH_ORIGINAL_COMMAND` и запускает
`vibememory-mcp shell <ключ>` так же, как sshd. С `GIT_SSH_VARIANT=simple`: иначе git сперва
вызывает команду с `-G`, выясняя, OpenSSH ли это, и такой вызов был бы лишним отказом в журнале.

Так тест `host_commands.rs` проходит настоящие clone, push, `pre-receive` и отказы на Mac: хук стора
в тесте переписан на этот бинарь и этот каталог, а текст хука, который ставит `storeInit.sh`,
проверяется отдельно.

## Что `pre-receive` берёт у git

- Изменённые пути — `git diff-tree -r --name-only --no-renames -z <старое> <новое>`: разница
  деревьев `main` до и после push, а не всё дерево и не каждый коммит. `-z` — чтобы имя с переводом
  строки не разорвало список.
- Push, создающий `main`, сравнивается с пустым деревом. Его id берётся у самого репозитория —
  `git hash-object -t tree --stdin` на пустом входе: так он верен и для SHA-256-репозитория.
- Пока хук решает, объекты push лежат в карантине, путь к нему — `GIT_QUARANTINE_PATH` (git 2.11+).
  Его размер и есть входящий пакет; размер стора считается без него. Git-подпроцессы хука видят
  объекты карантина через унаследованное окружение.
- `receive.fsckObjects=true` на сторах команд: дерево с элементом `..` или `.git` сломало бы — или
  хуже — checkout всех остальных участников. Проверка стоит на приёме, а не в хуке.

## Что показали живые гейты (2026-09-23, хост vibememory.ru)

- git дополняет строки `remote:` пробелами справа — `remote: vibememory: pathDenied` приходит с
  хвостом из пробелов. Разбор кода в тике обязан обрезать строку, иначе код не совпадёт.
- Пустая команда (`ssh vmgit@… ""`) — клиент ssh печатает «Pseudo-terminal will not be allocated…»
  и следом получает `commandDenied`: терминал `restrict` не даёт, а оболочки нет.
- Отозванный ключ до `shell` не доходит вовсе: применение убирает его строку из `authorized_keys`,
  и sshd отвечает `Permission denied (publickey)`. Код `unknownKey` остаётся на окно между новой
  публикацией снимка и его применением, а для `pre-receive` — на push, начатый до отзыва.
- Строка аудита вызова инструмента по ssh уходит в syslog с тегом `vibememory-mcp`, как у HTTPS, но
  не в журнал юнита: искать её — `journalctl -t vibememory-mcp`, а не `-u vibememory-mcp`.

## Гейты и их мутации

Решения фазы — под четырьмя фикстурами (`originalCommands`, `preReceiveUpdates`, `applyPlans`,
`host/status` и `statusAnswer`), и каждый гейт читает коды из самой спеки. Десять мутаций: экспорт
`memory`-стора участником, каталог удалённой команды как путь стора, квота «ровно заполнена»,
машина с именем-префиксом, удаление `main`, новый стор на месте удалённого, переименование поверх
существующего каталога, удалённая команда в списке команд отчёта, `storeNames` чужих участников,
строка ключа без `restrict`.

Девять пойманы с первого раза. Выжившая — «каталог удалённой команды — путь стора» — показала дыру
в фикстуре, а не в коде: слаг удалённой команды всегда давал `teamGone`, и подмену было не видно.
Кейс `retiredDirectory` — живой слаг с чужим каталогом `.deleted-*` — её закрыл.

## `git init --shared=group` сам ставит `receive.denyNonFastForwards`

Замечено на пробном прогоне `storeInit.sh --adopted` по свежему пути: у нового репозитория с
`--shared=group` git сам записывает `receive.denynonfastforwards = true`. Для личного стора на хосте
это не важно — он создан задолго до `storeInit.sh`, и `receive.*` у него нет (гейт фазы 0).
