# Сессии чужих агентов

**30.09.2026**, повод — DeepSeek Harness (DSH).
На машине владельца два агента, и оба хотят одну память.

## Что было

Сессии DSH в стор не попадали, и `history_search` их не находил.
В стор уезжало только то, что агент сохранил в память руками.
Ход работы, из которого потом берутся выводы, терялся.

Мост Claude-хуков в DSH есть, но `transcript_path` в нём пустая строка.
Хук `stop` молча выходил с кодом 0: `canonicalize("")` падает, и это читалось как «сессия ещё ничего не написала».
Собственный лог DSH — последовательность zstd-кадров со своими записями (`user/message`, `assistant/message`, `tool/call`…).
Путь к нему: `~/.dsh/sessions/<enc>/session-<uuid>/session.v4.jsonl.zstd`.
Проверено на этой машине: 1491 кадр в сессии Promed.
Каталог сессии называется `session-<uuid>`, а не голым UUID, как было сказано в заявке.

## Решение: плоский JSONL, формат чужого лога движок не читает

*Для DSH отменено 01.10.2026 — раздел «Пресет DSH: лог читает движок» ниже.
Для остальных агентов решение в силе.*

- **Формат принадлежит агенту.** `session.v4` — внутреннее устройство DSH; сменят версию, и читатель в движке начнёт молча пропускать сессии.
  Приводит формат обёртка самого агента, она живёт и меняется вместе с ним.
- **Один вход для всех.** `vibememory session put` принимает сессию любого агента.
  Формат описан для модели: [manuals/foreignSessionSpec.md](../../manuals/foreignSessionSpec.md).
- **Без новых зависимостей.** Для zstd нужен крейт, а в сборке сейчас нет ни одной C-зависимости: Windows собирается на Mac.

## Обязательные поля и почему

- **`type`** — поиск берёт только `user` и `assistant`.
- **`uuid`** — слияние опознаёт запись по нему.
  Строки без `uuid` слияние ключует байтами: исправленная строка на другой машине осталась бы рядом со старой, а удалить её нельзя.
- **`timestamp` в UTC с `Z`** — строки двух машин расставляются сравнением этих строк как текста.
  Смещение `+03:00` сравнивалось бы неверно, миллисекунды эпохи (как хранит DSH) — не строка.
- **`message.content`** — то, что читает поиск.

Файл проверяется целиком до записи, отказ называет номер строки.
Ошибка формата, найденная на входе, — сообщение агенту.
Та же ошибка неделю спустя — поиск, который молча ничего не находит.

## Где лежит: `projects/<проект>/agents/<агент>/<сессия>.jsonl`

Claude Code считает своей сессией каждый `*.jsonl` верхнего уровня проекта (`researchReport.md`).
Чужой файл там попал бы в `/resume` Claude Code.
Подкаталоги проекта у Claude Code называются по id сессий, и имя `agents` с ними не пересекается.
Одинаковые id у разных агентов не сталкиваются.
`history_search` читает оба уровня и отдаёт поле `agent`.
Глубже уровень не идёт: `<sid>/subagents/*.jsonl` — копии Claude Code, а не сессии проекта.
Гейт в `git_memories.rs` падает, если фильтр глубины снять.

## Живость без процесса

У Claude Code отметка живости несёт процесс агента (`liveness.md`).
У `session put` процесса нет, поэтому отметка снимается сама через час после последнего вызова или сразу по `--end`.
Файл пишется вне клона и переносится внутрь переименованием: тик коммитит всё, что находит под `projects/`, и недописанный файл не должен попасть к нему.

## Токен без клиента

DSH сначала взял токен на имя `deepseek`, а клиента под этим именем не было.
`doctor` показывал зелёное.
Теперь сервер памяти при старте пишет время в `~/.vibememory/clients/<агент>`.
`doctor` у каждого токена говорит, запускался ли сервер под его именем.
Сервер отказывается стартовать на имени не по правилу slug: раньше проверка срабатывала только на хосте, при первом обращении.

**Что в заявке не подтвердилось.**
Там сказано: «при расхождении имён сервер молча работает с локальным стором».
Токен читается только для проекта команды, чья память живёт на хосте, и там без токена сервер отказывает с командой `connect` в тексте.
Личный стор токена не требует вовсе: «подключено, но пусто» у DSH значило, что сессий DSH в сторе не было.

## Агент без своих хуков: обёртку зовёт тик

**01.10.2026**, повод — вторая заявка DSH.
`session put` работал, но звать его было нечем.
Мост Claude-хуков в DSH прописан и не срабатывает: в логе сессии ни одной записи `hook/invoked`, причина уходит в консоль DSH.
DSH завёл своё расписание, и смерть этой самоделки не видел никто.

**Решение: регистрация агента и шаг тика, а не новый демон.**
- Тик уже стоит в планировщике каждой ОС и переживает перезагрузку.
  Второй резидентный процесс — ещё одна установка, ещё один файл расписания на Windows и ещё одна смерть без свидетелей.
- Тик отдаёт изменившийся лог обёртке агента, а не читает его сам: решение «формат принадлежит агенту» остаётся в силе.
- Регистрация машинная, `~/.vibememory/agents.json`: каталог логов и обёртка у каждой машины свои, в стор они не едут.

**Неочевидное:**
- **Логи до регистрации — история.** Регистрация запоминает каталог как есть.
  Иначе первый проход отдал бы обёртке все сессии агента разом и держал тик тем дольше, чем длиннее история.
- **Упавший лог не помечается увиденным** и пробуется снова, а остальные логи агента ждут за ним: та же обёртка упала бы на них по той же причине.
- **Оба канала вывода обёртки читаются, пока она работает.** Обёртка, заполнившая канал, иначе ждала бы читателя вечно и выглядела бы зависшей.
- **«Молчит» считается от последнего успешного `put`, а не от времени файла в сторе.**
  `put` переписывает файл и при неизменном содержимом, так что время файла двигается и у работающей, и у неработающей связки.
  Каждый успешный `put` пишет отметку в `~/.vibememory/agents/<агент>.put`, отдельно от состояния тика: обёртку зовёт тик, и два писателя одного файла гонялись бы.
- **Отсчёт ведётся от позднего из двух: последнего `put` и регистрации.** Иначе агент, отдавший сессию месяц назад руками, считался бы молчащим сразу после регистрации.

## Версия сервера памяти

Утром у DSH работал сервер памяти прошлой версии: `history_search` возвращал пусто, и отличить «сессий нет» от «эта сборка чужих сессий не знает» было нечем.
Теперь отметка `clients/<агент>` хранит время и версию запуска.
`doctor` предупреждает, если клиент последний раз запускал сервер версией старше движка на диске.
Отметка старого формата, с одним временем, читается как раньше: про версию она ничего не доказывает и предупреждения не даёт.

## Пресет DSH: лог читает движок

**01.10.2026**, решение владельца: «нужно учесть, чтобы у других такой проблемы с DeepSeek не было».
После 0.5.0 тик звал обёртку, но обёртку каждому пользователю DSH всё равно пришлось бы писать: zstd-кадры, перевод записей, вырезание токенов, запускалка под планировщиком.
У DSH на это ушло два дня, у каждого следующего ушло бы столько же.

**Решение: `session agent add --agent dsh-desktop --preset dsh [--backfill]`, лог читает сам движок.**
- Причины старого решения проверены по фактам:
  - **«сменят версию — читатель молча пропустит».** Версия стоит в заголовке лога и в имени файла.
    Незнакомая версия — громкий отказ «формат DSH vN неизвестен этому движку: vibememory update», `doctor` красный.
    Молчать нечему.
  - **«zstd — новая зависимость, а C-зависимостей нет».** `ruzstd` 0.9 — чистый Rust, тянет только `twox-hash`.
    Windows по-прежнему собирается на Mac.
- Для остальных агентов правило «формат принадлежит агенту» остаётся: пресет — исключение по числу пострадавших, а не новый принцип.

**Проверено:**
- `ruzstd` распаковал все три живых лога DSH на машине байт в байт как `node` 24 `zlib.zstdDecompressSync`, включая 1850 кадров на 11 255 754 байта.
- Перевод движка сошёлся с обёрткой DSH (`vibememory-session-put.mjs`) запись в запись на тех же трёх логах: 3, 3007 и 10 записей.
- Фикстура `fixtures/foreign/dshLogs.json` — кадры, сжатые `node`, а ожидания посчитаны отдельной реализацией на JS (`buildDshLogs.mjs`).

**Неочевидное:**
- **`serde_json` по умолчанию теряет последний знак дробного числа.**
  В логе Promed `delayMs: 1968.196277261476` превращалось в `…4759`.
  Включён `float_roundtrip` во всём workspace: перевод не должен менять данные чужого лога.
- **Последний кадр живого лога бывает недописан** — он отбрасывается, следующий проход возьмёт его целым.
  Так же отбрасывается оборванная последняя строка.
  Нечитаемая строка в середине — уже порча лога, а не запись под нами.
- **Рядом с логом лежит `session.lock`.** Логом считается только `session.v<цифры>.jsonl.zstd` — и при выдаче, и при расчёте «молчит».
  Лог `v5` в этот список попадает намеренно: пропустить его значило бы молчать.
- **Пустой лог и лог из одного заголовка** — сессия только началась.
  Это не сбой: лог помечается увиденным, его следующая запись сделает его новым.
- **Сбой одного лога не держит остальные.** У обёртки упавший лог останавливает агента: та же обёртка упала бы на остальных.
  У пресета причина бывает своя у каждого лога — чаще всего папки проекта больше нет, и правила имён не могут назвать проект.
  С `--backfill` таких старых сессий много, и один такой лог держал бы всю историю вечно.
  Поэтому: неизвестная версия и нечитаемый файл по-прежнему останавливают агента, остальное откладывает только этот лог.
  Отложенный лог не пробуется каждый проход, а только после следующей записи; `doctor` называет его и причину, но красным не становится.
- **Идентификатор записи не должен повторяться** — `foreign::check` отказывает на повторе.
  Повторов в живых логах нет, но если `data.id` повторится, запись получает `<id сессии>-<seq>`, а на самый крайний случай — ещё и свой номер.
- **Токены вырезаются распознавателем движка** (`token::redact`), тем же, что держит файл с токеном на машине.
  Замена детерминированная: один и тот же лог даёт один и тот же файл и не делает лишних коммитов.

## Codex: пресет по живым логам (2026-10-08)

- **Лог** — `~/.codex/sessions/<год>/<месяц>/<день>/rollout-<время>-<id>.jsonl`, JSONL без сжатия: `{timestamp, type,
  payload}`. Заголовок — первая `session_meta`; у ответвлённой сессии (`forked_from_id`) следом идёт заголовок родителя
  и его история — брать первый
- **Каждая реплика записана дважды:** событием `event_msg` (`user_message`, `agent_message`) и `response_item`
  `message`, причём во втором — вперемешку с инструкциями, которые Codex шлёт модели (`role: developer`). Разговор
  берётся из событий, иначе поиск находил бы всё дважды и с системным текстом
- **Своих id у событий нет** — `uuid` из номера записи в логе: лог только растёт, номер не меняется
- Проверено на всех 21 живом логе машины владельца: 547 реплик, все приняты проверкой `session put`. Фикстуры —
  синтетические тексты в форме живых записей (`fixtures/foreign/codexLogs.json`)
- **Cursor не сделан:** на машине его нет, а чаты он держит в SQLite — без живых данных и без зависимости от SQLite
  пресет был бы догадкой
- **Путь из лога агента не разворачивает симлинки.** Хук получает cwd из оболочки, которая ссылку уже развернула,
  а лог Codex хранит путь, как его открыл человек: `~/Projects/…` — ссылка на другой диск. Имя проекта тогда
  отказывает («repository layout mismatch»). Разворачивать путь нужно в каждой точке входа, которая берёт cwd не из
  оболочки: сервер памяти (18.09) и `foreign_session::hand_over` (08.10)
- **Агенты оставляют сессии во временных папках, которые потом удаляют** — у Codex это автоматизации
  `~/Documents/Codex/<дата>/…`. Такая сессия не ляжет никогда; `doctor` считает их одной строкой
