# Жизнь бесплатной команды: правила отдельно, архив — у хоста

2026-09-26, фаза 4б, блок В.

## Решения

- **Правила — чистая функция** (`lifecycle/rules.ts`): факты о команде на входе, один шаг на выходе. Письма, база и
  архивы — в `sweepTeams`, который только исполняет шаг. Так каждая ветка проверяется unit-тестом, а мутации
  правил ловятся без базы
- **Без недельного письма не удаляем.** Задача, пропустившая дни, увидит команду сразу на 70-м дне простоя — и
  сначала пошлёт последнее письмо со сроком через неделю. Дата в письме — позднейшая из «60 дней простоя» и
  «неделя от письма»
- **Активность — три источника.** Запрос агента (сервер памяти касается файла `activity/<слаг>` не чаще раза в 10 минут —
  чтение не должно превращаться в запись на каждый запрос), коммит и вход участника. Агент, который только читает
  память, — живой клиент
- **Архив собирает хост, отдаёт кабинет.** Кабинет не читает сторы команд — они у `vmgit`. Общий каталог
  `exports` с группой `vmaccess` и sticky-битом: каждая сторона удаляет только свои файлы — кабинет свой
  `.request`, хост свои `.zip` старше 30 дней. Архив пишется в `.part` и переименовывается: полузаписанный zip
  кабинет не увидит
- **Ссылка — это право.** Архив отдаётся по секрету без сессии: письмо приходит, когда команды уже нет. Для письма
  секрет выпускается заново — тот, что в строке, никому не показывался

## Грабли

- **Мутация, которая не применилась, выглядит как выжившая.** `cargo fmt` разнёс условие по строкам, и шаблон
  замены не совпал — тест «пропустил» мутацию, которой не было. Из этого чуть не вырос ложный «баг» про время
  файла: перезапись пустого файла время меняет (проверено). Перед выводом «мутация выжила» — убедиться, что код
  действительно изменился (`grep` по результату замены)
- **Схема отчёта хоста в кабинете строгая** (`strictObject`): новое поле хоста без кабинета, который его знает,
  сломает чтение отчёта. Порядок выкладки — сначала кабинет, потом хост
- **Каталог в `ReadWritePaths` должен существовать до старта юнита.** Кабинет, выложенный раньше хоста, упал: его юнит
  назвал `/srv/vibememory/exports`, а каталог создаёт выкладка хоста. Несколько минут кабинет не отвечал. Теперь
  каталог создают оба скрипта (`install -d` идемпотентен), и порядок выкладки для каталогов не важен; для схемы
  отчёта он по-прежнему «сначала кабинет»

## Очередь за бесплатным местом (26.09.2026)

Отключать бесплатную команду ради платной — по очереди `reclaimOrder`, а не наугад и не по дате создания.
Одной «последней активности» мало: она не отличает брошенную команду от отпускника и заходящего раз в месяц.
Поэтому второй признак — частота: дни с активностью за окно, которые ежедневный обход копит в `team_active_day`.
Обход видит только последний момент использования, но идёт раз в сутки, поэтому отметка его дня и есть подсчёт дней.
Решение владельца: редкое использование хуже перерыва — отпускник после частой работы среди мёртвых уходит последним.
Грабли теста: «сейчас» фиксировать после выдачи гранта, иначе платная команда ещё не платит и попадает в очередь.
