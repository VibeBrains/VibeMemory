# Диск хоста переполнился, и синхронизация встала молча (2026-09-12…13)

## Что увидели

Обзор хоста перед задачей про HTTP-доступ: `/dev/vda1 9,9G 9,7G 0 100%`.
Стор весил 5,5 ГиБ, при первой настройке — около 600 МиБ.
Последний push, дошедший до хоста: 12.09 в 15:28; на Mac к утру 13.09 накопился 291 неотправленный коммит.
Тик при этом показывал `consecutiveFailures: 0`, `doctor` был зелёным.

## Три причины, одна за другой

**1. Входящие push распаковывались в отдельные объекты.**
У git `transfer.unpackLimit` по умолчанию 100: push меньше ста объектов раскладывается отдельными файлами, без дельт.
Транскрипт растёт и коммитится снова и снова, каждая версия (до 19 МиБ) ложилась на диск целиком.
Замер по дням: 12 МиБ 07.09, затем 677, 528, 501, 1461, 1656 МиБ в день; итого 4,75 ГиБ отдельных объектов при 608 МиБ в пакетах.

**2. Упаковка хоста не умеет сжать транскрипты.**
Для экономии памяти при первой настройке стоит `core.bigFileThreshold=8m`: для объектов больше 8 МиБ git не ищет дельты.
Еженедельный `gc` в воскресенье 04:17 упал на полном диске; ручной `git repack -d` с 2,6 ГиБ свободного места дописал пакет до 1,4 ГиБ и не закончил бы.
Те же 11 882 объекта на Mac, где порог по умолчанию, упаковались в **135,6 МиБ за 24 секунды**.

**3. Отказ push движок не считал провалом.**
`push()` в тике возвращал `bool`; отказ удалённой стороны был неотличим от «нечего отправлять» и не попадал в `problems`.
Тот же класс, что драйвер слияния (`driverNeverRan.md`): сломанное выглядит работающим.

## Как вытащили

- Мусор упавших операций — 19 карантинов входящих push и недописанные пакеты — удалён, журнал systemd ужат, кэш apt очищен: около 500 МиБ.
- Своп-файл на 2 ГиБ временно убран: так появилось место для упаковки, и упаковка на хосте всё равно оказалась бесполезной — см. причину 2.
- Пакет собран на Mac из объектов, список которых взят с хоста, проверен `verify-pack`, перенесён `rsync --partial` (сначала `.pack`, `.idx` последним — git не видит пакет без индекса), на хосте `git prune-packed`.
- Итог на хосте: отдельных объектов 0, в пакетах 738 МиБ, `rev-list --objects --all --missing=print` — ноль недостающих, диск занят на 27% (свободно 7,2 ГиБ), своп возвращён.

## Что изменено, чтобы не повторилось

- `transfer.unpackLimit=1` на хосте и в `hostBootstrap.sh`: входящий push остаётся пакетом с дельтами, посчитанными на машине-отправителе.
- Упаковка каждую ночь вместо раз в неделю; строка прежнего бутстрапа заменяется, а не остаётся рядом.
- Отказ push — провал цикла стора: сообщение с тем, что сказал хост, и back-off.
- Проверка места на хосте: `doctor` показывает строку `disk` и падает ниже 1 ГиБ или 10%; тик раз в день, тем же часовым механизмом, что проба зеркала, оставляет сессии предупреждение.

## Правило

> Порог, поставленный ради памяти машины, меняет не только память. `core.bigFileThreshold=8m` выглядел безобидной экономией, а выключил дельты ровно для тех файлов, из которых стор состоит.
