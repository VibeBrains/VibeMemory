# Сервер памяти на хосте: по ssh и по HTTPS (2026-09-13)

## Зачем и почему без рабочей копии

Машине без своего стора память нужна с хоста.
На хосте стор — только голый репозиторий; рабочая копия — ещё гигабайт на диске, который переполнился 12.09 (`hostDiskFull.md`).
Поэтому сервер работает прямо с git: чтение — `ls-tree`/`cat-file` из `main`, запись — коммит через временный индекс и `update-ref` со старым значением.
Push, пришедший между чтением и записью, остаётся на месте, запись повторяется поверх, до пяти раз.
Время транскрипта — последний коммит, который его менял: у голого репозитория нет времени изменения файлов.

## Сборка под Linux на Apple Silicon

- Образ `--platform linux/amd64` падает с `exec format error`: эмуляции amd64 в Docker на этой машине нет
- Работает кросс-компиляция в родном arm64-контейнере `rust:1.97-bookworm`: `gcc-x86-64-linux-gnu`, цель `x86_64-unknown-linux-gnu`; glibc та же, что на Debian 12 хоста
- Docker Desktop не монтирует `/private/tmp` — сборка видит пустой каталог и пишет `could not find Cargo.toml`; исходники монтировать из `/Volumes/...` только на чтение, результат — в `target/linux-cross`

## Развёртывание

`infra/hostMcp.sh`: бинарь с проверкой запуска и заменой переименованием, токен 256 бит один раз и никогда в вывод, systemd-сервис на `127.0.0.1:8787` (`ProtectSystem=strict`, запись только в стор), Caddy с сертификатом, наружу только `/mcp`.
Первый прогон упал на `apt-get install caddy`: dpkg держали автообновления; скрипт идемпотентный, повтор прошёл.

## Живая проверка

По ssh: рукопожатие, 6 инструментов, `memory_search` — 5 записей, `history_search` — та же реплика из сессии 10.09, что локально.
По HTTPS: без токена и с чужим — `401`, с токеном — `200`, `Origin` — `403`, `GET` — `405`, другой путь — `404`, уведомление — `202`, поиск — 5 записей; сертификат Let's Encrypt до 12.12.2026.
_Запись на живом сторе не проверялась_, чтобы не оставлять тестовую запись в настоящей памяти; путь записи закрыт гейтами, включая запись поверх устаревшей вершины.

## Токен и транскрипты

Транскрипт сессии агента уезжает в стор и в зеркало на GitHub.
Токен, показанный в сессии, оказался бы в истории git навсегда.
Поэтому токен нигде не печатается: скрипт его не выводит, клиенту он передаётся командой `$(ssh vibememory cat vibememory/mcp-token)`.
