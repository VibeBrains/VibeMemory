# Учётки хоста и права личного стора (2026-09-23)

Фаза 0 этапа 6: сервер памяти переезжает из учётки владельца `vm` (у неё sudo) в `vmgit` — без
sudo, без пароля, без терминала. Чтобы `vmgit` писал в личный стор владельца, стор становится
групповым. Как это устроено — [manuals/hostSetup.md](../../manuals/hostSetup.md), шаг 2.

## План велел открыть группе весь стор — это была бы дыра до root

План (§2.2) предписывал `chmod -R g+rwX` на `store.git`. Тогда `vmgit` мог бы переписать
`store.git/config` или положить файл в `hooks/`. Оба исполняет git владельца: ночная упаковка идёт
от `vm`, push с Mac принимает `vm`, хук зеркала запускается от `vm`. Через `core.fsmonitor`,
`core.hooksPath` или сам хук это исполнение кода от `vm`, а у `vm` sudo. Отдельная учётка без sudo
не защищала бы ни от чего: дыра в сервере памяти, который смотрит в интернет, вела бы к root.

Сделано по наименьшим правам:

| Что | Группе | Почему |
|---|---|---|
| `objects/` и всё внутри | запись, setgid | запись памяти кладёт объекты и создаёт каталоги `objects/xx` |
| `refs/` и всё внутри | запись, setgid | блокировка и переименование, которыми двигается `refs/heads/main` |
| каталог стора | чтение, 2750 | запись в каталог позволяет подменить `config` переименованием |
| `config`, `hooks/`, `HEAD`, `info/` | только чтение | исполняется или читается git владельца |

Проверено отказами: из-под `vmgit` запись в `config`, файл в `hooks/` и файл в корне стора —
`Permission denied`. Запись памяти проходит: `hash-object -w`, `mktree`, `commit-tree`,
`update-ref` — новые каталоги `objects/xx` сами получают группу и setgid.

**Цена — `vmgit` не может удалять ссылки.** Удаление блокирует `packed-refs` в корне стора:
`Unable to create 'store.git/packed-refs.lock': Permission denied`. Серверу памяти удаление не
нужно — он только двигает `main` вперёд.

**`core.sharedRepository=group` на `config` не распространяется**: запись настройки владельцем
оставила `config` с режимом 644. Иначе каждая новая настройка снова открывала бы дыру.

## Три ловушки идемпотентности

«Второй прогон не меняет ничего» — гейт фазы. Его проверяет снимок режима, владельца, группы и
времени изменения каждого пути до и после прогона: 98 путей, ноль изменений. Чтобы дойти до нуля,
пришлось закрыть три вещи.

**`[ "$(cat файл)" = "$текст" ]` не совпадает никогда**, если текст кончается переводом строки:
подстановка команды его отрезает. Скрипт упаковки перезаписывался на каждом прогоне с самого
начала, 17.09 тоже — вывод «записан» оба раза никто не прочитал. Та же ловушка сидела в сравнении
хука зеркала. Сравнение — `printf '%s' "$текст" | cmp -s - файл`.

**Упаковка сама создаёт `info/refs` с групповой записью.** `git repack` зовёт
`update-server-info`, а тот при `sharedRepository=group` пишет файл 664 — вне `objects/` и `refs/`.
Скрипт снимал бит, упаковка ставила снова. Файл нужен только «тупому» HTTP-протоколу, которого у нас
нет, поэтому упаковка идёт с `-n` и файла не трогает.

**`git config key value` переписывает файл, даже если значение то же.** `storeInit.sh` пишет
значение только когда оно отличается.

## ssh склеивает аргументы

`ssh host 'bash -s' -- "$a" "$b" "$c"` отдаёт удалённой оболочке одну строку `bash -s -- a b c`.
Пустой аргумент в ней исчезает, и все следующие сдвигаются на место влево. Раньше пустым был только
последний аргумент (`--mirror`), и потеря была безвредной; пятый аргумент после него уехал на место
четвёртого, и скрипт упал на «путь storeInit.sh не передан». Правка — каждый аргумент экранируется
для удалённой оболочки: `ssh host "bash -s -- $(printf '%q ' "$a" "$b" "$c")"`.

## Хук pre-receive — не в фазе 0

`storeInit.sh` без `--adopted` должен ставить репозиториям команд хук `pre-receive`, который вызывает
`vibememory-mcp pre-receive`. Этой подкоманды до фазы 2 нет, а хук без исполнителя отвергал бы любой
push. Поэтому в фазе 0 скрипт ставит командам только `receive.*`, а хук войдёт в него вместе с
подкомандой и её тестами.
