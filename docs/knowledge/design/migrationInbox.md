# Механизм переезда: облачная папка как входящий лоток (2026-09-05)

Решение для этапа 3, когда одна машина (Mac) переезжает в стор, а другая (GPD, Windows) ещё
работает из `~/OneDrive/.claude` и переедет позже (этап 4).

## Правило

`vibememory migrate --from <папка>` — не однократный перенос, а **повторяемый импорт-слияние**:

- транскрипт, которого в сторе нет, копируется и сверяется по sha256; тот, что уже есть, сводится
  union'ом по записям (тот же драйвер, что в тике) — новые записи другой машины приезжают,
  ничего из стора не теряется;
- всё остальное при расхождении идёт в keep-both: версия стора остаётся, чужая ложится в карантин
  один раз (повторный прогон узнаёт уже лежащие байты и не плодит `.1`, `.2`);
- источник не трогается ни байтом, ни mtime: OneDrive перезаливает изменённый файл и подкладывает
  другой машине конфликт-копию;
- плейсхолдер Files On-Demand узнаётся по `st_blocks == 0` при `st_size > 0` и останавливает apply
  **до** первого чтения — иначе чтение тянет файл из сети или, что хуже, отдаёт усечённый.

Отсюда порядок для двух машин: Mac переезжает → папка остаётся у GPD → Mac повторяет `migrate`
по расписанию или перед `tick`, пока GPD жива на облаке → GPD клонирует стор, прогоняет тот же
`migrate` по своей копии папки (для неё это `%USERPROFILE%\\OneDrive\\.claude`) и переключается →
папка архивируется. Ни один момент этой цепочки не требует, чтобы обе машины остановились сразу.

## Карточки Desktop и суффиксы копий

Конфликт-копия OneDrive называется `<stem>-<Hostname>.<ext>`, и hostname сам содержит дефисы
(`GPD-WIN-MAX2`). Резать по последнему дефису нельзя — первый dry-run это и показал. Правило:
перебирать дефисы слева, брать первый, при котором сосед `<base>.<ext>` существует; суффикс обязан
содержать заглавную букву, потому что записи памяти — kebab-case, и `store-naming.md` рядом с
`store.md` — две записи, а не копия.

Копия карточки Desktop с чужим hostname — версия **той** машины и уходит в её outbox
(`machines/<Hostname>/desktop/`), а не в наш. Карточка без `cliSessionId` или с
`transcriptUnavailable` чинится из любой копии, где id есть: Desktop стирает id на промахе резюме и
никогда не возвращает сам.

## Что нашёл первый dry-run по настоящей папке

За 0,4 с по 4306 файлам: 2163 к переносу (930 МиБ), 109 в архивном сторе `-`, 2041 плейсхолдер,
один отказ гейта — файл 64 МиБ в `tool-results`. И дефект гейта экспорта: правило
`AnySegment("sessions")` отказывало `memory/sessions/*.md` — 39 хендоффов `save-session`. Реестр
живых сессий живёт только в корне конфига, правило сужено до `TopLevel`; `.key` запрещён везде
по-прежнему. Урок общий: **computed-ожидание фикстуры — это гипотеза, и первый прогон по реальным
данным её проверяет**; кейс `sessions-inside-allowed` был именно такой гипотезой и переписан.
