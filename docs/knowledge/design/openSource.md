# Открытый код: AGPL, кабинет отдельно, консоль хоста

**03.10.2026**, решение владельца: «отдаём open source, а кто не хочет заморачиваться — пусть идёт к нам».
Организациям важно развернуть продукт у себя, частным людям — нет.

## Лицензия: AGPL-3.0

- **MIT отвергнута:** по ней можно взять код, закрыть свои доработки и продавать хостинг, ничего не отдав
- **FSL и BSL отвергнуты:** запрет на конкурирующий сервис формально делает лицензию «не open source», и это отпугивает
- **AGPL:** пользоваться и ставить у себя бесплатно, в том числе внутри компании; кто даёт изменённую версию людям по
  сети, обязан открыть изменения. Закрытый конкурент на нашем коде невозможен
- Тем, кому AGPL не подходит, продаётся отдельная лицензия. Поэтому `CONTRIBUTING.md` просит у автора вклада право
  распространять его и под другой лицензией — без этого двойное лицензирование чужих правок невозможно
- Решено перевести на AGPL и VibeIDE с VibeIDEA

## Кабинет не открывается

Кабинет — пак start0, его лицензия прямо запрещает публиковать исходники («You may not republish… redistribute»).
Решение «кабинет только в закрытом репозитории» было записано ещё при вендоринге
([start0InSubdirectory.md](../toolchain/start0InSubdirectory.md)).

**Как разделили, сохранив историю:**
- История кабинета — `git subtree split --prefix=cabinet` → приватный `VibeBrains/VibeMemoryCabinet` (59 коммитов)
- История продукта — `git filter-branch --index-filter 'git rm -r --cached cabinet' --prune-empty` → 239 коммитов
  без единого файла кабинета
- Старый репозиторий переименован в `VibeMemory-archive` и остался приватным: полная копия на случай ошибки
- Локально `cabinet/` стал вложенным репозиторием и строкой в `.gitignore`: пути, тесты кабинета и `hostCabinet.sh`
  не изменились — скрипт и так брал номер сборки через `git -C cabinet`

**Грабли:**
- `VibeBrains` на GitHub — учётная запись, а не организация. `gh repo create VibeBrains/…` от `borodatych` отказывает
  с «cannot create a repository for VibeBrains», хотя `gh` залогинен в обе: нужен токен `VibeBrains`
  (`GH_TOKEN=$(gh auth token -u VibeBrains)`), а `borodatych` — коллаборатор с правом `push`
  (`admin` для репозитория учётки GitHub не принимает: «Cannot assign permission of admin»)
- Новый репозиторий с тем же именем не наследует коллабораторов старого: доступ выдаётся заново
- Ссылки документов на `cabinet/…` ломают гейт документации в открытом клоне — они заменены текстом

## Консоль хоста вместо кабинета

Без кабинета права задавались только ручной правкой `access.json` — для компании это не управление.

**Решение: `vibememory-mcp admin` пишет тот же снимок, что кабинет.**
- Документ правится как JSON, а не через типы снимка: у типов нет сериализации, и порядок полей кабинета не нужен —
  хеш снимка сравнивается только с самим собой
- Каждое изменение прогоняется через `access::check` до записи: консоль не может положить то, что хост отвергнет
- Версия 2 и `serial + 1`: хост не применяет снимок, который не новее; рукописная версия 1 становится версией 2 на
  первом изменении
- Файл пишется рядом и переименовывается поверх, с владельцем, группой и режимом прежнего: его читает `vmgit` из группы
  `vmaccess`
- Применение — не дело консоли: path-юнит `vibememory-access-apply.path` срабатывает на изменение файла
- На хосте с кабинетом консоль отказывает: второй писатель терял бы изменения при следующей публикации кабинета

**Гранты вместо кодов.** Клиент умел только `connect --cabinet` с кодом. Вместо второго пути консоль выдаёт ровно тот
ответ, который кабинет даёт на код, а `connect --grant` пропускает его через тот же `claim::read_answer` и дальше по
тому же пути. Поле `cabinet` гранта — адрес самого хоста: от него проверяются `mcpUrl` и прочие адреса.

**Ключ машины ждёт между шагами.** У кабинета ключ делается на время одного запроса (`.pending-<pid>`). Здесь между
`--key-request` и `--grant` проходит переписка с владельцем хоста, поэтому ключ ждёт в `stores/.pending-grant`, и
повторный запрос показывает тот же ключ, а не новый: иначе зарегистрированный ключ разошёлся бы с ключом машины.

Тесты — `crates/vibememory-mcp/tests/admin_console.rs` на базовом снимке `fixtures/access/accessSnapshots.json`,
включая полный круг: грант консоли → `read_answer` → токен пускает `Snapshot::admit`.
