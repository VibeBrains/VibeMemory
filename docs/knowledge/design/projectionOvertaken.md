# Проекцию обогнала запись через MCP — и тик принимал её за правку человека

Найдено 2026-09-25 сессией VibeIDE на её памяти: три записи, несколько раз подряд.

## Что было

1. Тик проецирует запись: в `<id>.md` лежит версия R, в поле `version` — `R`
2. Агент меняет запись через MCP `memory_update`: в журнале версия N с родителем R, файл не тронут
3. Следующий тик импортирует каталог раньше, чем проецирует: файл сравнивался с **текущей** записью N
4. Файл ≠ N — значит правка; родитель правки берётся из файла — R
5. У R два ребёнка, N и «правка» со старым текстом, — rival-версия, которой никто не писал

Каждый `memory_update`, менявший текст, на следующем тике рождал соперницу.
Той же дорогой возвращалась забытая запись: `memory_update`, затем `memory_delete`, и нетронутый файл версии R
читался как правка, одновременная с удалением.

## Почему так вышло

Файл говорит, из какой версии он написан, — для этого поле `version` и заведено.
Но проверка «трогали ли файл» сравнивала его не с этой версией, а с последней: пока писал только тик, это было одно и то же.
MCP-сервер пишет в журнал мимо проекции, и между двумя тиками файл законно отстаёт от записи.
Случай удаления уже чинили (`deleteResurrected.md`) и тоже частным правилом: свёртка помнила одну версию — ту, что видело удаление.

## Что сделано

- Свёртка хранит все версии журнала по `uuid` (`Memory.versions`); журнал и так читается целиком
- Файл — правка, только если он отличается от версии, которую называет
- Совпал с ней: у живой записи файл перепишет проекция, у забытой он уходит в `stale` и удаляется
- Версии нет в журнале (файл написан руками или строка ещё не доехала) — прежнее сравнение с текущей записью
- Частное правило удаления (`Forgotten.seen`) стало ненужным и удалено: общее его покрывает

## Попутно: rival-файлы копились

Файл `<id>.rival-<версия>.md` писался, но никогда не убирался.
Проекция выбирает основной версией первый лист по `(updatedAt, uuid)`, и роли листов меняются: новая запись от основной
делает бывшую соперницу основной, а её rival-файл остаётся лежать.
Теперь нетронутый rival-файл версии, которая больше не соперница, уходит в `stale`.
Правленый остаётся на месте: это чей-то текст, а читать rival-файлы как правки импорт не умеет — по замыслу.

## Чего это не решает

Свести расхождение по-прежнему нечем: правка `<id>.md` закрывает только основную версию, соперница остаётся листом.
Нужно событие с несколькими родителями — пункт в [roadmap](../../roadmap.md).

## Проверка

Четыре кейса в `fixtures/memory/memoryScenarios.json`:
- `importProjectionOvertakenByLaterWriteIsNotAnEdit` — `observed`, воспроизводит отчёт VibeIDE
- `importForgottenAfterLaterWriteIsStale`
- `importRivalFileOfFormerRivalIsStale`
- `importEditedRivalFileStays`

Мутации: сравнение с текущей записью роняет три новых кейса и старый `importForgottenProjectionIsNotAnEdit`;
без уборки rival-файлов падает третий, без проверки «не трогали» — четвёртый.
