# Правила и навыки для всех агентов: что проверено и что решено (2026-10-07)

Повод — владелец, поработав с DeepSeek Harness: память и сессии он видит, а правила и навыки нет, и приходилось
объяснять заново. Модель — [spec/rulesAndSkills.md](../../spec/rulesAndSkills.md), формат —
[manuals/rulesSpec.md](../../manuals/rulesSpec.md).

## Что читают агенты — проверено, а не предположено

- **DSH, правила** (бандл `app.asar`, плагин `dsh-agent-instructions`): `$DSH_HOME/AGENTS.md` — глобальный; в проекте
  цепочка `AGENTS.md`, `CLAUDE.md`, `*.local.md` от корня `.git`; бюджет 65 536 байт на всё, при переполнении первым
  целиком выпадает глобальный — разбор в [sharedRules.md](sharedRules.md)
- **DSH, навыки** (плагин `dsh-skill-filesystem`): корни по рангу — `<проект>/.dsh/skills`, `<проект>/.agents/skills`,
  свои `customSkillDirs`, `$DSH_HOME/skills`, `$DSH_AGENTS_HOME` или `~/.agents/skills`. Навык — `<name>/SKILL.md`
  или плоский `<name>.md` в корне; вложенные `**/SKILL.md` не ищутся; `name` в kebab-case и `description`
  обязательны, иначе навык пропускается с предупреждением. Каталоги отслеживаются: новый навык виден со следующего
  шага модели
- **DSH, MCP**: инструменты и resources (`resources/list`, `resources/read`) клиент умеет; prompts — не найдено
- **Claude Code** (документация, 07.10): `~/.claude/rules/*.md` и `.claude/rules/*.md` — правило файлом, поле `paths:`
  грузит его только при работе с этими файлами; `AGENTS.md` читается сам, если рядом нет `CLAUDE.md` (с 2.1.277);
  `@path`-импорты до глубины 4; навыки — `~/.claude/skills`, `.claude/skills`
- **Codex**: `~/.codex/AGENTS.md` и `~/.codex/skills` — **не проверено**: на этой машине только каталог данных
  `~/.codex`, бинаря нет
- **`~/.claude/skills/synced/`** — то, что Claude Code сам синхронизирует с claude.ai; через ссылку `~/.claude/skills`
  оно лежит в личном сторе, но другим агентам не раскладывается

## Решения

- **Правило — запись с постоянным `id`**, а не раздел монолита: без `id` сравнение и перекрытие возможны только
  файлом целиком. Решение владельца 07.10 пересмотрело утреннее «один `CLAUDE.md`»
- **Канон — стор, файлы агентов — копии.** Личные правила в `config/rules/` (этот каталог тик уже коммитит), командные
  — `rules/` и `skills/` стора команды, проектные — `projects/<проект>/rules|skills`
- **Метки `vibememory:rule <id>@<версия>` делают правку у агента правкой правила.** Версия — FNV-1a заголовка и
  нормализованного текста: правка у агента видна, когда текст ≠ версии метки, а правка в сторе — когда версия правила
  ≠ версии метки. Обе сразу — конфликт: версия агента в карантин, файл переписан из стора
- **«Устарел» — по истории git стора, не по датам.** Текст блока проекта либо совпадает с одной из версий правила, либо
  нет; часы машин не сравниваются
- **База для слияния «своего варианта»** — версия с наибольшим числом общих строк, при равенстве старейшая: иначе
  правка одной строки с двух сторон тихо сходилась бы как «чистая», а не как конфликт. Поймано фикстурой
- **Уровень записи — слово человека, и сервер это проверяет:** `rule_save` без `level` отвечает `levelRequired`
- **Командные правила — у владельца и админов, на хосте:** `pre-receive` отвечает участнику `rulesDenied`,
  `proposals/` открыты всем
- **Режимы проекта меняют его файлы только по согласию:** `merge` и `override` включает человек; блоки «только в
  проекте» не трогаются никогда
- **Разрезка `CLAUDE.md`** — все разделы в правила; в навыки только названные владельцем и никогда абсолютные: навык
  грузится по задаче, а абсолютное правило должно быть в силе всегда. Первая версия эвристики отправляла в навыки всё
  длиннее 2 КБ, включая абсолютный запрет атрибуции, и помечала `absolute` по слову в тексте — исправлено до выпуска

- **Выключенный агент получает свой файл обратно, а не остаётся с замороженным.** Движок, переставший писать
  `~/.codex/AGENTS.md` по `rules.agents`, оставил бы там правила на день выключения, и агент слушался бы старых.
  Поэтому выключение — тоже раскладка: правки из файла забираются, части движка уходят, строки человека остаются,
  файл только из частей движка удаляется, ссылки на навыки снимаются
- **Предложение — не правило.** `rule move … --to team` кладёт предложение, и удалить исходник сразу значило бы
  оставить правило нигде до принятия; исходник остаётся, команда называет, как его снять потом
- **Статичные проблемы файлов — в `doctor`, не в тик.** Испорченный файл правила или навык, который агент отвергнет,
  не меняется от запуска к запуску: тик повторял бы одно и то же в журнал каждым запуском. Навык человека под именем
  хранимого виден только рядом с каталогами агентов, поэтому `doctor` смотрит и их

## Грабли

- **`rule move` на тот же уровень удалил бы правило:** запись ложится на место исходника, а потом исходник удаляется.
  Поймано перечиткой диффа до коммита; одинаковые уровни — отказ до чтения файла
- **Записи ссылок без корней хранят абсолютный путь**, а `Roots::to_local` понимает только `{КОРЕНЬ}/путь` — раскладка
  проектов молча ничего бы не нашла на машине владельца; запасной ход тот же, что у импорта тика
- **Два блока одного правила в разных файлах проекта** уходили в карантин под одним именем, и второй затирал первый;
  имя теперь несёт файл
- **Тест бинаря с `HOME` во временном каталоге и `VIBEMEMORY_DIR=$HOME/.vibememory`** — это «настоящий» движок для
  `install`, и он зарегистрировал бы расписание в launchd; в тестах каталог движка не `$HOME/.vibememory`
- **Проверка линта цепочкой `cargo clippy … | grep "^error" && git commit`** коммитит при ошибке: `grep` находит
  строку и возвращает успех. Только `if … | grep -q "^error"; then …; else commit; fi`
