# Общие правила для всех агентов (2026-10-07)

Память, история и навыки были общими для всех агентов машины, а правила — нет. `~/.claude/CLAUDE.md`
читает только Claude Code. Его копия `<store>/config/CLAUDE.md` ездила между машинами, но ни один
другой агент её не искал. Дыру нашла сессия DeepSeek Harness в VibeSnipe 02.10: правила она узнала
только потому, что владелец назвал путь, а проект держал их ручную копию в `.vibe/rules/`, которая
молча отставала от глобального файла.

## Что читает DSH — проверено по его бандлу

Источник — строки `app.asar` из `DeepSeek Harness.app`, плагин `@deepseek-ai/dsh-agent-instructions`
0.2.0-rc.2:

- **Глобальный файл — `$DSH_HOME/AGENTS.md`**, по умолчанию `~/.dsh/AGENTS.md`
  (`USER_GLOBAL_FILE = "AGENTS.md"`). `CLAUDE.md` в `~/.dsh` он не ищет.
- **В проекте** DSH читает и `AGENTS.md`, и `CLAUDE.md` (`DEFAULT_INSTRUCTION_FILE_CANDIDATES`)
  плюс `AGENTS.local.md` и `CLAUDE.local.md`. Цепочка идёт от корня проекта (`.git`) до рабочего
  каталога, от широкого к узкому. Поэтому проектные `CLAUDE.md` DSH уже видит — не хватало только
  глобальных правил.
- **Бюджет — 65 536 байт на всю цепочку** (строка `agent-instructions` в `dsh-base`, поле `maxBytes`).
  При переполнении сначала **целиком выбрасывается самый широкий файл**, а это как раз глобальный.
  Модель получает строку `Workspace instruction budget …`, человек — ничего. Глобальные правила
  весят около 50 КБ, у VibeIDE свои `CLAUDE.md` и `AGENTS.md` — ещё 46 КБ, и без поднятого бюджета
  в этом проекте DSH остался бы без правил.
- Бюджет поднимается строкой профиля в `~/.dsh/profiles/<профиль>/cordis.patch.yml`: запись с
  `id: agent-instructions` заменяет строку бандла. Её печатает `mcp-config dsh`, значение —
  `DSH_INSTRUCTIONS_BUDGET` (256 КиБ).

## Решения

- **Канон один — `<store>/config/CLAUDE.md`.** На темы его не дробим: каждому агенту нужен целый
  файл, а отдельный репозиторий правил стал бы вторым механизмом синхронизации рядом со стором.
  Решение владельца 07.10.
- **Файл агента — ещё одна управляемая копия того же файла стора.** `managed::Copy` — пара «файл на
  машине → файл в `config/`»: копии `~/.claude` и файлы инструкций агентов сводятся одним и тем же
  трёхсторонним слиянием ([managedCopies.md](managedCopies.md)). Отсюда без нового кода:
  - правка в любой копии доезжает до остальных — через стор, за один-два тика;
  - две правки, сделанные порознь, — конфликт с карантином, а не перезапись;
  - токен в файле не уезжает.
  Однонаправленная проекция «стор → агент» молча стирала бы правку, сделанную там, где правила
  читает DSH.
- **Агент живёт на машине, когда есть его каталог** (`Preset::home`). Каталог агенту движок не
  создаёт: на машине без DSH не появится `~/.dsh`. Список агентов — таблица пресетов в
  `agents.rs`, и путь к файлу инструкций записан в том же месте, где путь к логам.
- **Домашний каталог передаётся явно** (`Layout::home`, `tick::Machine::home`). Тест, который нашёл
  бы `~/.dsh` сам, писал бы в настоящий файл владельца. В тестах там `None` или каталог теста.
- `DSH_HOME` движок не читает: тик идёт под планировщиком, без переменных оболочки. DSH,
  запущенный с другим `DSH_HOME`, файла не получит — так же, как с `VIBEMEMORY_DIR` в
  [mcpClients.md](mcpClients.md).

## Правила проекта и глобальные

Решение владельца 07.10:

- Проектное правило уточняет глобальное и при конфликте побеждает.
- Исключение — разделы с пометкой «абсолютно» (атрибуция, секреты): их проект не переопределяет.
- В проекте не держат ручную копию глобальных правил: `.vibe/rules/`, `AGENTS.md` и `CLAUDE.md`
  проекта содержат только проектное.

Метка «кто сделал» в roadmap (у VibeSnipe — `DSH`) нужна для перепроверки, а не для авторства.
Поэтому она ставится без имени агента: «⚠ перепроверить». Так метка не становится атрибуцией
ассистента, если roadmap публичный.

## Что дальше

Следующий агент со своим глобальным файлом — новая строка в таблице пресетов: каталог и имя файла.
Путь к его файлу берётся из самого агента, как здесь из бандла DSH, а не из памяти: предположения
о поведении клиентов в этом проекте уже не раз оказывались неверными.
