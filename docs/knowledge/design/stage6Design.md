# Проектирование этапа 6: панель проектов, судьи и критик, который нашёл то, что судьи пропустили

Дата: 2026-09-16. Результат — [spec/stage6Plan.md](../../spec/stage6Plan.md), проект плана на
≈ 56 рабочих дней (выпускаемый режим `memory` — ≈ 39), двадцать решений владельца.

## Как шло

1. **Основание** — один агент собрал факты из `idea.md`, `architecture.md`, roadmap, кода сервера
   памяти, скриптов хоста, прецедента VibeSter (`saas.md`, `monetization.md`, `railway.md`) и
   лицензии start0. Плюс факты, снятые командой до старта: хост 2 vCPU / 1340 МБ / 2,4 ГБ свободно,
   `/home/vm` 0700, легаси-токен — 64 hex без префикса, в workspace нет ни одного TLS-крейта.
2. **Четыре проекта** с разных углов: MVP-first, изоляция по построению, продукт и деньги,
   эксплуатация. **Три судьи** по четырём линзам (принципы, реализуемость, безопасность, отдача).
   Победил проект «изоляция по построению» у всех трёх (29, 30, 31 из 40): единственный, где
   границы команд, ключи и токены не держатся на дисциплине кабинета. Судьи же велели урезать
   объём — режим `memory` первым, `sync` вторым выпуском — и привить единицу продажи из
   продуктового проекта и служебного пользователя без sudo из эксплуатационного.
3. **Синтез** в формате владельца: решения, целевая схема, планируемые изменения, фазы с гейтами.
4. **Критик полноты** после синтеза — и вот главное.

## Что нашёл критик, чего не нашли судьи

Четыре блокера **по построению**, при том что план был «принят» тремя судьями:

- в новой `memory`-команде первую запись сделать некуда: правило «запись не создаёт проект»
  против отсутствия списка проектов в снимке и запрета push;
- участник не может получить бинарь (канала раздачи и подписи нет) и не может выполнить `connect`
  (HTTPS-клиента в Rust нет — ни одного TLS-крейта);
- командные сторы режима `memory` — в единственной копии на диске, который переполнялся дважды;
- первая публикация снимка кабинетом снимает доступ у владельца, если базу не засеять строкой
  легаси-токена.

Плюс 22 пробела и 14 противоречий: порядок фаз (бэкап Postgres до установки Postgres), «правило
без исполнителя» (пятый случай за неделю — `mode: sync` у `personal`, который никто не исполняет),
чёрный список экспорта для каталога, который экспорт не видит, `member`, объявленный и тут же
отменённый для версий движка.

**Судьи оценивают, критик проверяет.** Судья сравнивает проекты между собой по линзам и не обязан
доказывать, что победитель собирается; критик читает один план против кода и основания и ищет,
где он не сойдётся. Панель без критика выпустила бы план с четырьмя блокерами и зелёными оценками.

## Как сходились правки

Пять раундов «правка → критик». Каждый раунд закрывал все замечания предыдущего и находил новые —
кодового уровня, всё мельче: `git -C` под другим пользователем упирается в `dubious ownership`
(git 2.39.5 на хосте), драйверы слияния не ставятся на клон командного стора, `shell status` без
области показывал бы чужие команды, глоб `<handle>-*` при дефисе в имени захватывает чужие
транскрипты. Объём плана после третьего раунда пришлось запереть (160 КБ — предел), иначе
каждое закрытие добавляло раздел.

Критерий остановки: блокеров ноль, оставшееся — локально для одной фазы. Остаток записан в план
разделом 8, а не гоняется ещё кругом: последний критик нашёл три пункта там, где предыдущий —
восемь, и все три закрываются в своей фазе за час.

## Факты, без которых план был бы неверен, и как они нашлись

Все — командой, не чтением:

| Факт | Чем проверен | Что изменил в плане |
|---|---|---|
| `/home/vm`, `~/vibememory`, `store.git` — 0700 | `stat` на хосте | групповые права рекурсивно, `/home/vm` → 710, иначе демон под `vmgit` не пройдёт |
| легаси-токен — 64 hex без `vmt_` | `wc -c` файла | сервер узнаёт легаси-строку по формату, а не по `tokenId` |
| TLS-крейтов нет | `Cargo.toml` трёх крейтов | `connect` ходит `curl` подпроцессом, как всё внешнее — `git` и `ssh` |
| `export::decide` видит только `~/.claude/` | `export.rs:241` | «чёрный список для `~/.vibememory/tokens`» был бы пустым тестом; настоящий риск — фрагмент с токеном в управляемой копии `settings.json` |
| git 2.39.5 на хосте | `git --version` | `safe.directory` в `hostBootstrap.sh`, код хоста — только `--git-dir` |
| `/usr/bin/sha256sum` на macOS нет | `ls` | строка установки per ОС |
| `prepare` пака = `husky` + `agents:link` | `package.json` v0.1.29 | оба шага вырезаются при вендоринге |
| лицензия start0 — подписка, редистрибуция запрещена | `LICENSE.md` пака | self-hosted поставка кабинета — только собранным `dist/` |

## Цена

Три оркестрации: 10 + 7 + 5 агентов (плюс 5 повторных после лимита сессии), ≈ 4 млн токенов
субагентов, около четырёх часов стены. Промпт по безопасности в тот же день — 94 агента и 9,5 млн
токенов: 35 находок трёх скептиков, каждая проверена двумя независимыми агентами, 29 подтверждены.
