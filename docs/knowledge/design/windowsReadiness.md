# Готовность движка к Windows: что проверено на Mac и что осталось GPD (2026-09-11)

Этап 4 стоял с пометкой «заблокирован железом». Часть его заблокирована по-настоящему: всё, что
исполняется только на Windows. Другая часть проверяется на Mac — компиляция под
`x86_64-pc-windows-msvc` и чистые функции, которые строят для Windows строки, пути и файлы.

## Замер компиляции

Зависимости чисто Rust (в lock нет ни `cc`, ни `libc`, ни `windows-sys`), поэтому
`cargo check --target x86_64-pc-windows-msvc` работает на Mac целиком. Нужна только цель
(`rustup target add x86_64-pc-windows-msvc`), линкер не нужен.

- Продуктовый код (lib и bin всех трёх крейтов) собирается и проходит `clippy -D warnings`.
- Тесты не собирались: 7 прямых вызовов `std::os::unix::fs::symlink` в трёх файлах.
- `clippy.toml` даёт под Windows-целью три предупреждения конфигурации: пути `std::os::unix::…` из
  списка гейта чистоты там не существуют. Windows-пути туда добавлять нельзя — они дали бы такие же
  предупреждения в основном гейте на Mac. Оставлено как есть.

## Найдено и исправлено, часть 1

| Находка | Было | Стало |
|---|---|---|
| Домашний каталог | `HOME` читался в пяти местах; без него `layout()` брал пустую строку, и `.vibememory` создавался в текущем каталоге. На Windows `HOME` есть только внутри Git Bash: хуки его видят, задача Планировщика — нет | одна функция `install::home_dir()` на `std::env::home_dir()` (на 1.97.1 не устаревшая ни на одной цели — замер); нет дома и нет переменных — ошибка, а не относительный путь; гейт в `platform_hygiene.rs` не пускает прямое чтение `HOME` обратно |
| Команда хука | `VIBEMEMORY_DIR={путь} {путь} hook …` без кавычек: ломается на пробеле везде и на обратных слешах под Git Bash | оба пути — одинарные кавычки POSIX, на Windows с прямыми слешами; гейт исполняет строку через `sh -c` с пробелом и кавычкой в пути |
| Имя бинаря | `bin/vibememory` без `.exe`, а `CreateProcess` без расширения ищет `vibememory.exe` | `EXE_SUFFIX` |
| Драйвер слияния | голое имя; это дефект и на Mac — [driverNeverRan.md](driverNeverRan.md) | абсолютный путь в кавычках |

## Что осталось

- Ссылки каталогов: код делает `symlink_dir`, которому нужны администратор или Developer Mode.
  Записанное ограничение требует junction, а `std::os::windows::fs::junction_point` в 1.97.1
  нестабилен (замер: `E0658`).
- Путь стора Desktop захардкожен под macOS.
- Расписание — только launchd.
- Проверки Git Bash в `doctor` нет.

На Mac ничем не проверяется: junction под живым CLI; какой из двух путей Desktop стоит на GPD;
консольное окно от задачи Планировщика; строка хука с Windows-путём вживую под Git Bash; resume в
обе стороны.
