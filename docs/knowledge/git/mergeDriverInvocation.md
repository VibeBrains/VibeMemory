# Когда git зовёт драйвер слияния и что ему передаёт (git 2.50.1, 2026-09-02…03)

Проверено прогонами в scratch-репозиториях на этой машине; контракт — `man gitattributes`,
раздел «Defining a custom merge driver». Нужно для драйвера `vibememory-jsonl`
([architecture §3](../../spec/architecture.md)) и для политики тика.

## Контракт

`merge.<name>.driver = vibememory merge-driver %O %A %B` — три временных файла: общий предок,
текущая версия, входящая. Драйвер обязан **перезаписать `%A`** результатом и выйти с кодом 0
(чисто) или ненулевым (конфликт). Код > 128 git трактует как крах драйвера: слияние становится
ошибкой, а не конфликтом. `%L` — размер маркера конфликта, `%P` — путь результата, `%S`/`%X`/`%Y`
— метки предка и голов. `merge.<name>.recursive` задаёт драйвер для внутреннего слияния
нескольких общих предков; если не задан, используется тот же драйвер.

## Когда драйвер вызывается, а когда нет

| Ситуация | Драйвер | Что делает git |
|---|---|---|
| Файл изменён с обеих сторон | **вызывается** | результат берётся из `%A` |
| Изменён только на одной стороне | нет | берётся изменённая версия (в том числе **удаление**) |
| Файл создан с обеих сторон (add/add) | **вызывается**, `%O` — файл нулевой длины | то же |
| Удалён на одной стороне, изменён на другой | нет | конфликт дерева (`DU`/`UD`), рабочая копия остаётся с версией изменившей стороны |
| Criss-cross (два общих предка) | вызывается **дополнительно** для построения виртуального предка | результат внутреннего слияния становится `%O` финального |
| Драйвер вышел ненулевым | — | `UU`, `MERGE_HEAD` на месте, `git merge --abort` возвращает дерево чистым |

Следствия для движка:

- Пустой `%O` — не особый режим: `merge_jsonl(b"", ours, theirs)` — тот же вызов, которым
  пользуется copy-import на SessionStart.
- Одностороннее удаление строки внутри файла до драйвера не доходит: git берёт версию изменившей
  стороны целиком. Поэтому «union, который никогда не уважает удаление» давал бы разный исход в
  зависимости от того, дописывала ли вторая машина, — и правило членства по базе выбрано именно
  из-за этого.
- `forget <sid>` (удаление файла) против дописи на другой машине даёт конфликт дерева **без**
  вызова драйвера: политика — abort тика и явная команда, а не молчаливое разрешение.
- Асимметрия драйвера (хребет — `ours`) не порождает «вечного пинг-понга»: при одном `origin`
  проигравший push сливает коммит победителя один раз, вторая машина получает fast-forward,
  деревья совпадают. Проверено прогоном criss-cross: три вызова драйвера (два слияния плюс
  виртуальный предок), одинаковые деревья на обеих сторонах.
- `recursive` не задаётся: виртуального предка строит тот же драйвер. Ложных «удалений» это не
  создаёт, но не потому, что предок — подмножество сторон (он им не является: наш union уважает
  удаления), а потому, что merge-base по определению предок обеих голов — отсутствие в голове
  строки, которая есть в предке, всегда означает настоящее удаление, а не раннюю ветку.

Не проверено: поведение под Git Bash на Windows (CRLF в `%O`/`%A`/`%B` при `* -text`), поэтому
кейсы на CRLF помечены `unverified` до этапа 4.
