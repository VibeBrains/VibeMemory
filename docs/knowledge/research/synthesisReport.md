## 1. Вердикт

Делаем git-транспорт с приватным remote (победитель «native-or-different-transport»), но с переставленными приоритетами: ссылка `projects/<enc(cwd)>` создаётся SessionStart-хуком первым шагом и без сети, коммит — сразу на Stop, всё кроме транскриптов и `memory/` идёт per-machine «outbox»-каталогами (идея дизайна 2, конфликтов нет по построению), а разъезд транскрипта ловится не таймером, а UserPromptSubmit-гейтом свежести. «Симлинк всей папки как раньше» (CloudRoot) отвергнут фактами: OneDrive не сливает, а плодит копии (4 конфликт-копии дескрипторов Desktop лежат в сторе прямо сейчас), дегидрирует (сегодня 67 из 353 транскриптов в `-ALL-` имеют `blocks=0` — VibeIDE 27/80, BuzzBang 9/11, VibeReel 9/10), расплющивает ссылки внутри дерева, ставит `+R` под Bun-`mkdir` на Windows и держит `.credentials.json` с 8 mcpOAuth-токенами в облаке с 6 июля; при этом нативного переноса сессии у Anthropic нет (Remote Control — окно в живой процесс, teleport — сводка в облако, `CLAUDE_CODE_PROJECT_DIR_NAME` — одно имя на запуск). Git даёт то, чего OneDrive не даёт принципиально: детерминированное слияние append-only JSONL по uuid, полную историю (ничего не теряется тихо), отсутствие reparse-точек и дегидрации, и запись только там, где мы её разрешили.

Проверено на этой машине сейчас: `~/.claude/projects` — 28 ссылок, 0 реальных каталогов; `CLAUDE_CONFIG_DIR=/Users/borodatych/.claude` в zshrc/profile/launchctl; Desktop спавнит CLI 2.1.255 с `--setting-sources=user,project,local --settings {}` — пользовательские хуки для Desktop-сессий применяются; два живых Desktop-процесса (6278 VibeSweep, 11657 Promed), `lsof` — 0 открытых `.jsonl` (CLI пишет open/append/close, не держит fd); оба живых транскрипта заканчиваются `\n`, 0 неразбираемых строк; `init.ps1:8` и `init.cmd:10` всё ещё ставят `CLAUDE_CONFIG_DIR` в OneDrive; в OneDrive лежат Windows-реестры `sessions/20712.json`, `21460.json`; git 2.50.1, python3 3.9.6, node 24 есть; gitleaks и git-lfs нет (и не понадобятся); VibeSweep — не git-репо; launchd `StartInterval` пропускает интервал во сне (man launchd.plist) — триггера «по пробуждению» на Mac нет.

## 3. Механизм

**Репо.** `~/ClaudeSync` (Mac: `/Users/borodatych/ClaudeSync`; Win: `C:\Users\borodatych\ClaudeSync` — загрузочный том, не OneDrive, не `/Volumes/Storage`). Remote — приватный bare-репо по SSH; хост — параметр `config.json` (GitHub private достаточно при исключении ≥45 МБ; self-hosted снимает и это). LFS не используется вообще (ломает union-драйвер и квоту). Git-конфиг ставит `install`: `core.autocrlf=false`, `core.filemode=false`, `core.symlinks=false`, `core.longpaths=true` (Win), `core.precomposeunicode=true` (Mac), `core.fsmonitor=true`, `core.untrackedCache=true`. `.gitattributes`: `* -text`, `* merge=claudesync-keepboth`, `**/*.jsonl merge=claudesync-jsonl`. Два драйвера, оба детерминированы, маркеров `<<<<` не бывает; при исключении в драйвере — `git merge --abort`, запись в лог, `additionalContext` на следующем старте.

**Имя стора.** `git rev-parse --path-format=absolute --git-common-dir` → `basename(dirname(commondir))` (worktree и подкаталоги VibeDub/server → `VibeDub`; сабмодуль `.git/modules/<x>` → `<x>`); вне git — `basename(cwd)`; `cwd=/` → `root`. `nameOverrides` в `config.json` для коллизий.

**Хуки** (в общем `config/settings.json`; на Windows команды идут через Git Bash, `$HOME`=`%USERPROFILE%`):

- `SessionStart` (все matcher) → `"$HOME/ClaudeSync/bin/claudesync" hook session-start`, timeout 10, **без сети**: (a) `enc = basename(dirname(transcript_path))` — кодировку не переизобретаем; (b) если `projects/<enc>` отсутствует → `mkdir` стора + `.keep`, создать ссылку; ссылка на другой target → починить; **реальный каталог** → copy-import в стор по uuid, а rename в ссылку только при `source=startup`, когда `<session_id>.jsonl` там ещё нет и в `~/.claude/sessions/*.json` нет живого pid с этим cwd (проверка pid+procStart; реестр не читается → считать живым); иначе pending для tick; (c) записать enc/name/cwd в `machines/<id>/links.json`; (d) `exit 0` всегда; stdout — только JSON `additionalContext` при проблеме (отложенный merge, N неудачных push, карантин памяти). Проверено ранее: транскрипт рождается после выхода хука (Desktop stream-json: +16 мс, `-p`: +4 с), CLI ждёт хук.
- `UserPromptSubmit` → `claudesync hook prompt`, timeout 15: гейт свежести — на первом промпте сессии и далее если с прошлой проверки >5 мин: `git fetch` (таймаут 5 с; офлайн → пропуск с пометкой); если `origin/main` меняет `projects/*/<sid>.jsonl` или `machines/*/live.json` показывает этот sid живым на другой машине (heartbeat <30 мин) → слить файл на диске (union) и **заблокировать промпт** (`decision: block`, текст: «сессию продолжили на `<машина>` в `<время>`: закрой и открой заново — транскрипт уже обновлён»). Это единственное место, где допускается ритуал, и только в гонке. Вне гонки — no-op за миллисекунды.
- `Stop` → `claudesync hook stop`, `async: true`: **commit немедленно** (снимок транскрипта берётся до последнего `\n`, драйвер дополнительно отбрасывает неразбираемые строки), heartbeat в `live.json`, хвост в `tails.json`, экспорт `tasks/`, `history`, дескрипторов Desktop (с guard, см. 4), затем push в фоне с дебаунсом 20 с. «Закрыл крышку» теряет секунды, не ходы.
- `SessionEnd` → `claudesync hook session-end`, timeout 60: commit синхронно, снятие heartbeat, push отсоединённым процессом.
- `CLAUDESYNC_SKIP=1` + `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1` — для машинных прогонов VibeDub (транскрипты и history не пишутся вовсе; переменная есть в 2.1.255).

**tick** (Mac LaunchAgent `com.borodatych.claudesync`: RunAtLoad + StartInterval 120 — интервал во сне пропускается, значит худший лаг после пробуждения ≈2 мин; Windows Task Scheduler: при входе, при разблокировке, каждые 2 мин, скрытое окно): (1) `fetch`; (2) `merge origin/main`, но только если входящий diff не трогает `projects/*/<sid>.jsonl` / `<sid>/**` сессий, живых **на этой машине** (реестр `sessions/*.json` + pid/procStart; fail-closed); при `MERGE_HEAD`/unmerged — никогда не коммитить, `merge --abort`; (3) push, если dirty; (4) реконсилер: для каждого `machines/*/links.json` × локальные корни из `config.json` — если переведённый cwd существует, гарантировать ссылку `projects/<enc(local cwd)>` → стор (фолбэк-сканы CLI и Desktop не видят ссылок — ссылка обязана существовать заранее); (5) импорт `tasks/` для неживых sid, `history` под mkdir-локом CLI (`history.jsonl.lock`, stale 10 с, дедуп `timestamp\0sessionId`), дескрипторов Desktop (гейты в 4); (6) push-guard: удалённые в рабочей копии файлы `projects/**` восстанавливаются `git checkout --`, удаление только через `claudesync forget <sid>`; (7) стейл-лок (`~/.claude-sync/lock` с pid, `index.lock`) снимается по проверке живости владельца.

**Смена пути репо:** первый `claude` в новом cwd → хук создаёт новую ссылку на тот же стор (имя от git), старый реальный каталог (если возник) сливается по uuid на tick. Нулевые действия.

**Новая машина:** предпосылки → `git clone` → `~/.claude-sync/config.json` (id, корни, remote) → `claudesync install` (ссылки по всем известным `links.json`, копии конфигов, реальный Desktop-стор + импорт дескрипторов, таймер) → `claudesync doctor`. Один раз, дальше ничего.

## 4. Известные провалы

- **Конфликт-копии `.claude.json`** — файл больше не покидает машину. Единственный shared-write формат — транскрипты (union по uuid + стабильная сортировка по timestamp, безuuid-строки — побайтно) и `memory/*.md` (keep-both в карантин, никогда «новее побеждает»). Всё остальное — outbox одного писателя. Слияние машин по `.claude.json` не требуется: переносимых полей там нет (allowedTools/mcpServers пусты, permissions живут в общем settings.json).
- **Расплющивание ссылок OneDrive** — OneDrive в схеме нет; все ссылки живут в `~/.claude` (снаружи репо) и смотрят внутрь; `core.symlinks=false`, в репо ссылок нет. Doctor проверяет отсутствие reparse-точек и текстовых «ссылок» (<4 КБ, содержимое — путь) на пути.
- **Разъезд транскрипта при перелинковке живой сессии (08.08)** — ссылка никогда не переключается под живой сессией (правило: startup + свой транскрипт ещё не существует + нет живых pid с этим cwd, иначе copy-only + pending); merge не трогает файлы живых локальных сессий; вилка «продолжили на B, потом ввели на A» блокируется UserPromptSubmit-гейтом по heartbeat/tails; в оставшемся случае union сохраняет обе ветви, а `additionalContext` честно говорит: CLI покажет цепочку от листа с max(timestamp), вторая ветвь в файле, но не в разговоре (`/rewind` или fork).
- **Пустые каталоги** — `.keep` в каждом сторе; ссылки не проходят сквозь rmdir-свипер; `cleanupPeriodDays: 3650` в общем settings.json (сегодня 17 транскриптов >30 дней уцелели только потому, что свип не ходит через симлинки — недокументированно); doctor валидирует settings.json (невалидный → дефолт 30 дней, #41458); git-история — второй слой; push-guard не коммитит удаления.
- **Windows на старой схеме** — `CLAUDE_CONFIG_DIR=%USERPROFILE%\.claude` (setx + Desktop Settings), `.claude.json` переезжает из OneDrive локально, `.credentials.json` удаляется (relogin), junction `claude-code-sessions → OneDrive` снимается, Desktop-стор — реальный каталог в userData действующей установки (MSIX или Squirrel — обслуживаются оба, лишнюю удалить), ссылки `projects/D--Projects-…` — junction без привилегий, `+R`/reparse исчезают вместе с OneDrive.
- **Порча дескрипторов Desktop** (20 помечены `transcriptUnavailable`, 16 без `cliSessionId`) — guard на **экспорт**: дескриптор, потерявший `cliSessionId` или получивший `transcriptUnavailable` относительно последней экспортированной версии, не экспортируется, а локально чинится из outbox (shadow `cliSessionId`); импорт только когда переведённый cwd существует, транскрипт в сторе есть и ссылка создана. Новые дескрипторы импортируются в любое время (Desktop не перепишет то, чего не загружал), обновления известных — тоже, с оговоркой, что копия из памяти Desktop может победить косметически (title/lastFocusedAt).

## 5. Нативная кросс-девайс функция

Нет. Remote Control — окно в живой процесс на исходной машине (транскрипт на серверах Anthropic только пока соединение живо); teleport/«Continue in Web» — новая облачная сессия из сводки, из CLI пушить нельзя; `/desktop` — та же машина; auto memory официально machine-local; `CLAUDE_CODE_PROJECT_DIR_NAME` (2.1.234+) — одно имя на запуск, не per-repo, к Desktop неприменимо; экспорт/импорт сессий в Desktop существует в коде за фиче-флагом (`claude-3p-export.json`, источник `terminalCli`), для аккаунта не включён. Issues #22648/#28791/#73639 без ответа Anthropic. Remote Control оставляем как есть (дополнение «с телефона»), помня, что запись `bridge-session` внутри транскрипта при `--resume` на другой машине переподключит мост — при закрытой сессии на A это желаемое поведение.

## 6. GAIM

Нет: хранит только «факты памяти» через MCP-SaaS без self-hosting, не покрывает транскрипты, `--resume`, tasks, history и список Desktop. Нативная auto memory (`projects/<name>/memory/`) синхронизируется этой схемой побайтно, GAIM дублировал бы её и уводил приватные факты третьей стороне.

## 9. Остаточные риски

- Формат JSONL и дескрипторов Desktop объявлен внутренним: драйвер обязан иметь тест-гейт; при неразбираемых записях — байтовый режим, при исключении — abort, не порча.
- Гейт свежести ловит только когда есть сеть и heartbeat доехал; офлайн-резюм на обеих машинах по очереди даёт вилку, которую union сохраняет, а CLI показывает одну ветвь.
- Открытая вкладка Desktop на A неделями: heartbeat протухнет (>30 мин), защита остаётся только у UserPromptSubmit-гейта по `tails.json` при следующем вводе в A — работает, но зависит от доставки push с B.
- Windows-сторона не проверена вживую (хуки Desktop-CLI через Git Bash, junction под реальным каталогом, pid reuse — сглажено procStart).
- Перечитывает ли Desktop стор дескрипторов без перезапуска — открыто; если нет, карточки с другой машины появляются после рестарта Desktop.
- Идентичность по basename: одноимённые не-git каталоги (VibeSweep — не git) на двух машинах сольются в один стор; `nameOverrides` — ручной предохранитель.
- Политика Desktop «components under the config root may not be symlinks» сегодня терпит ссылки `projects/<enc>` (текущая сессия так и пишет), но может ужесточиться; doctor следит за `PlantDetectedError`, запасной план для CLI — `CLAUDE_CODE_PROJECT_DIR_NAME` через обёртку.
- Транскрипты на remote открытым текстом: приватность = приватность remote и SSH-ключей; секреты в выводе инструментов уезжают туда же (gitleaks — только предупреждение в `status`, не блокировка).
- Файлы ≥45 МБ остаются локальными и на второй машине отсутствуют (сегодня один tool-result).
- Python 3.9 на Windows — новая зависимость; при раздражении та же спека собирается одним Rust-бинарём без смены схемы.
