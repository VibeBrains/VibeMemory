# Кабинет на start0: грабли Prisma, тестов и сборки (фаза 3, 2026-09-24)

Каждый пункт — наблюдение с прогоном, не догадка.

## Prisma

**`migrate dev` не работает без терминала, когда у него есть предупреждение.**
Новая уникальная колонка у непустой таблицы — предупреждение, и `migrate dev` отказывает в неинтерактивной среде даже с `--create-only`.
Путь: `prisma migrate diff --from-config-datasource --to-schema <schema> --script -o <каталог>/migration.sql`, затем `migrate deploy`; ноль дрейфа проверяется тем же `diff --exit-code`.

**Миграция на Postgres не транзакционна.**
Упавшая на третьем операторе миграция оставила созданными пять enum и запись «не завершена».
`migrate reset` для агента Prisma требует согласия человека в `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` — подделывать его нельзя.
Починка тестовой базы без сброса: `TRUNCATE` всех таблиц, как делает `cleanDb` перед каждым прогоном, `DROP TYPE` наполовину созданных типов, `migrate resolve --rolled-back <имя>`, `deploy`.

**Расширения, открывающие транзакции, должны получать огороженный клиент.**
Пак передавал `findManyAndCount` и `retryTransactions` голый `_prisma`, и `$transaction` открывался на нём.
Query-расширения — гарды — внутри такой транзакции не действуют: `tx.team.delete` проходил.
Поймано тестом и мутацией.

**Ошибка Prisma цитирует строки исходника вокруг вызова.**
Тест ждал `toThrow('never deleted')`, а упал бы на внешнем ключе — и всё равно прошёл: в цитате исходника рядом стояло само `'never deleted'`.
Сверять сообщение с начала (`toStartWith`, `/^…/`), не подстрокой.

**Запрос Prisma ленив.**
`expect(prisma.team.delete(…)).rejects` получает `PrismaPromise`, а не `Promise`, и выполнения не происходит.
Оборачивать: `(async () => await prisma.team.delete(…))()`.

**`ADD COLUMN … SERIAL` нумерует старые строки в порядке чтения таблицы.**
Для журнала публикаций порядок — смысл, поэтому миграция написана руками: номера по `row_number() OVER (ORDER BY "publishedAt")`, потом последовательность с продолжением, `OWNED BY` и `NOT NULL`.
Дрейфа нет — `migrate diff --exit-code` видит ту же `autoincrement()`.

## better-auth и Point0

**`hooks.before` better-auth срабатывает и на прямой вызов `auth.api.*`.**
Отличить запрос от своего кода можно по `context.request`: у прямого вызова его нет.
Так закрыты admin-эндпоинты для запросов, а сид и тесты создают пользователей по-прежнему.

**Лимитер better-auth не считает попыток, если в `X-Forwarded-For` две записи.**
Без `advanced.ipAddress.trustedProxies` `getIPFromHeader` доверяет только заголовку из одной записи и иначе отдаёт `null` — ключа лимита нет.
С `trustedProxies: ['127.0.0.1', '::1']` цепочка срезается справа до первого чужого адреса — клиента за Caddy.

**Плагин Point0 с `.ctx` проверяет права после разбора ввода.**
Не-админ на admin-мутацию с пустым телом получал `422` и описание схемы, а не `403`.
Отказ до всего — `.middleware` на базе: она оборачивает запрос раньше, чем точка читает ввод.

**Сокращение `.lets.query()` работает только под компилятором Point0.**
Проба вне тестового прелоада падает `lets[type] notation can not work without compiler` — даже с явной формой `lets('query', 'имя')`, если сам корень собран сокращением.

**`fetchServer` шлёт запрос `POST`-ом, хотя точка объявлена `GET`.**
Первый вариант «имперсонация только смотрит» отказывал любому запросу к точке с методом не `GET` — и закрыл чтение `myTeams`, пришедшее `POST`-ом.
Что точка меняет, говорит её тип (`mutation`, `action`), а не метод запроса.

**Индекс записи из JSON ничего не говорит об отсутствии.**
`host.teams[slug]` для слага `constructor` вернул бы унаследованную функцию, а `slug in report.teams` — `true`.
Линт это чует (`no-unnecessary-condition`: TypeScript сужает индекс до «всегда есть»); для данных извне — `Object.hasOwn` или `Map` из `Object.entries`.

## Тесты Bun

**`expect(promise).rejects` в bun-types не промис.**
С `await` его запрещает `await-thenable`, без `await` утверждение выполняется после конца теста, и его провал теряется.
28 таких утверждений прошли бы молча — заменены помощником `rejectionOf` (`src/test/lib/utils.ts`).

**В int-тестах dev-движок уводит всё, что не точка, на dev-клиент.**
`/api/auth/*` отвечал `302` на `localhost:8000`, корневые middleware не выполнялись, а тест пака «публичная регистрация не создаёт учётку» проходил на редиректе.
Переключатель движка `POINT0_PREVENT_REDIRECT_TO_DEV_CLIENT=true` в `src/test/setup/int.ts`; теперь тест ждёт настоящий `400 EMAIL_PASSWORD_SIGN_UP_DISABLED`.

**В int-тестах страница не рендерится.**
SSR страницы просит у dev-клиента `index.html` и падает «Unable to connect»: в int-режиме dev-сервера нет.
Проверки поведения страниц — в e2e на собранном сервере, а чистые функции страниц (шаблон пути для журнала) — модульными тестами.

**e2e нужен хост, иначе кабинет не делает ничего.**
Без владельца кабинет не публикует (`noOwner`), а без отчёта хоста о текущем снимке не создаёт команду — e2e упал на первом же погашении кода.
Стенд `src/test/setup/e2e.ts` сеет владельца так же, как хост (рукописный снимок, отчёт о нём, импорт), и держит заместителя службы хоста: раз в 200 мс он «применяет» `access.json` и пишет `host.json`.

**`set-cookie` better-auth сначала гасит старые куки, потом ставит новые.**
Ответ `impersonate-user` несёт `session_token=` с `Max-Age=0` и следом новый `session_token`; склейка всех пар в один `cookie` отдала серверу первую, пустую, и тест получил `401`.
Банка тестов держит последнее значение каждого имени и выкидывает погашенные — как браузер.

**Playwright иногда не находит контекст браузера при закрытии.**
`Target.disposeBrowserContext: Failed to find context` — «ошибка между тестами» при всех зелёных тестах и код выхода 1; повторный прогон на той же сборке чист.
Это гонка закрытия у харнесса, не поведение кабинета: смотреть, есть ли `(fail)`, а не только код выхода.

**Журнал читается подменой методов `console`.**
Консольный синк logtape держит объект `console` и берёт метод при каждой строке — тест гигиены журнала видит всё, что пишет сервер.

## Линт и сборка

**`eslint --cache` с правилами на типах врёт после правки зависимости.**
Кэш по содержимому файла не знает, что поменялись типы импортируемого модуля: `no-unnecessary-condition` держал ошибку, которой уже не было.
Сомнение — прогон без кэша.

**Константа из серверного модуля в изоморфном файле ломает клиентскую сборку.**
`Import denied on side "client" … server-only` — границы пароля переехали в свой изоморфный модуль `modules/auth/password.ts`.

## Письма и запуск

**Resend 6 не бросает исключение на отказ — возвращает `{ error }`.**
`createEmail` пака писал «Email sent» на недошедшее письмо; для гейта «письмо дошло» это ложь.
Теперь `send` проверяет поле и отвечает `'sent'`, `'skipped'` или `null`.

**Фильтр fail2ban без якоря читает то, что вписал запрос.**
В проде журнал — JSON-строки, и в каждой строке запроса лежат его user-agent и путь.
Фильтр `claim refused from <HOST>` без привязки находил эти слова в user-agent и банил тот адрес, который запрос назвал.
Строка для джейла пишется отдельно в stderr, фильтр привязан к концу строки, адрес — только IP-литерал, `usedns = no`.
Проверено мутацией: без якоря тест на JSON-строке с подложенным user-agent падает.
То же у сервера памяти: journald делает запись из каждой строки, и перевод строки в имени инструмента из запроса начинал запись, которую фильтр читал как отказ с любым адресом.
Поля из запроса экранируются; тест прогоняет фильтр из `hostMcp.sh` по враждебной строке.
Подделка в тесте обязана закрываться переводом строки: хвост формата после неё ломает якорь, и без этого мутация «убрать экранирование» выживает.

**Хеш архива сборки меняется при каждой сборке, хеш содержимого — нет.**
`hostCabinet.sh` сравнивал `shasum` архива `tar.gz` с тем, что выложено, и каждый прогон выкладывал тот же коммит заново и перезапускал службу: tar пишет время файлов, gzip — своё.
Сборка при этом детерминирована — две сборки подряд дали одинаковое содержимое `dist/`.
Личность релиза теперь — хеш распакованного дерева (имена и содержимое файлов), и второй прогон честно «без изменений».
Там же шаг ролей каждый раз ставил пароль и выдавал права, печатая `NOTICE`: теперь пароль проверяется входом через временный passfile, права — `pg_has_role`, и меняется только недостающее.

**Собранный сервер читает `.env` силами Bun, не Point0.**
`preload` в собранном процессе ничего не делает, а Bun загружает `.env` и `.env.<NODE_ENV>` из рабочего каталога.
Юниту systemd нужны `WorkingDirectory` и `Environment=NODE_ENV=production` — иначе прод-процесс берёт каскад разработки.
