# Установка одной строкой и `PATH` (2026-09-27)

Первая версия страницы «Скачать» давала на каждую систему четыре строки: скачать архив и сумму, сверить, распаковать, `./vibememory install`.
Владелец назвал это длинным и пугающим, а после установки `vibememory` не находилась по имени: `install` клал программы в `~/.vibememory/bin`, но в `PATH` эту папку не добавлял, и мануал лишь советовал сделать это руками.

## Как устроено

- `infra/install.sh` (POSIX `sh`, `curl`, `tar`) и `infra/install.ps1` (PowerShell с `tar.exe` Windows 10+) лежат рядом с архивами; `hostRelease.sh` кладёт их в каталог выпусков вместе с файлом `latest` — одна строка с новейшей версией
- Установщик не разбирает `index.json`: `sh` без `jq` этого не умеет, а `latest` плюс имя архива по правилу `vibememory-<версия>-<цель>.tar.gz` дают всё нужное
- Сумма сверяется с `<архив>.sha256` с того же хоста; не сошлась — выход с кодом 1 и ничего не поставлено
- `install` получил шаг `OnPath`: блок между `# >>> vibememory >>>` и `# <<< vibememory <<<` в `.zshrc` / `.bash_profile` (bash на macOS — логин-оболочка) / `.bashrc` / `.profile`, на Windows — пользовательская переменная `Path` через `[Environment]::SetEnvironmentVariable(…, 'User')` (`setx` обрезает до 1024 символов)

## Грабли

- Домашняя папка для блока — родитель каталога движка, а не `HOME` из окружения: тесты ставят движок во временную папку, и шаг, читавший `HOME`, дописал бы настоящий `~/.zshrc` владельца. На Windows пользовательский `Path` меняется, только если движок лежит в самом `%USERPROFILE%`
- `Invoke-RestMethod` отдаёт файл с `application/octet-stream` байтами — текст читается через `Invoke-WebRequest` и явное декодирование
- В PowerShell `curl` — псевдоним другой команды; установщик на PowerShell обходится без него
- Проверка `install.sh` без риска для машины: `VIBEMEMORY_DIR` во временную папку, `HOME` туда же, `VIBEMEMORY_DL=file://…` на локальный каталог выпусков — `curl` читает `file://`
