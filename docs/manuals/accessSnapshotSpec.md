# Спека снимка прав `access.json`

> Скопируйте этот файл целиком своей LLM и попросите собрать `access.json` для вашего хоста
> VibeMemory: кто в какой команде, какие токены агентов и ssh-ключи машин действуют.
> Здесь описаны **все** поля и **все** правила проверки. Закомментированный образец —
> [`crates/vibememory-mcp/defaults/access.sample.jsonc`](../../crates/vibememory-mcp/defaults/access.sample.jsonc).

## Назначение

Снимок прав — единственное, что хост знает о командах. Его пишет кабинет, читают сервер памяти
(кого пускать по HTTPS) и применятель прав на хосте (какие репозитории завести и какие ssh-ключи
пустить). Между кабинетом и хостом нет ни сети, ни sudo — только этот файл.

- Путь: `/srv/vibememory/access/access.json`
- Пишет учётка кабинета `vmcab`: сначала временный файл рядом, потом переименование поверх — читатель
  никогда не видит половину файла. Режим 0640, группа `vmaccess`
- Читает учётка сервера `vmgit`. Сервер перечитывает файл, как только меняются его время изменения,
  размер или inode, — без перезапуска
- Первый файл владелец пишет руками по этой спеке — версия `1`; дальше его переписывает кабинет на
  каждое изменение — версия `2`, с номером публикации `serial` и банами `bans`

**Отзыв — это отсутствие.** Токена, ключа или членства нет в снимке — значит, их нет вовсе.
Отдельного поля «отозван» не бывает.

**Снимок читается строго, и при сомнении хост закрывает дверь.** Файла нет при старте — сервер не
запускается. Файл пропал или перестал проходить проверку на ходу — сервер отказывает всем (`503`) и пишет об
этом громкую строку в журнал. Молча продолжить со старыми правами он не имеет права: в новом файле
мог быть отзыв.

**Хост не возвращается к старому решению.** Применив снимок, хост кладёт рядом его копию
`applied-snapshot.json` (учётка `vmgit`, режим 0640). Файл, который не новее копии, не применяется и
не действует: у него меньший `serial` или тот же `serial` при другом содержимом. Так бывает, когда
публикация проиграла очередь и легла поздно или старый файл вернули руками. Сервер памяти,
forced-shell, `pre-receive`, отчёт хоста и ночной бэкап держатся копии, а применятель пишет в отчёт
`serialBehind` ([hostStatusSpec.md](hostStatusSpec.md)). Сервер памяти, кроме того, не опускается ниже
`serial`, который уже загрузил, — даже если между делом файл пропадал. Копия не заменяет пропавший
или битый файл: там мог быть отзыв, и дверь закрыта, пока файл не прочитается. Запись применения
`applied.json` сверяется тоже: если копия не записалась, только она помнит, что применён снимок новее,
и файл старше неё не действует, а вход по ключу и `pre-receive` закрыты до новой публикации. Рукописный снимок без
`serial` старше любого снимка кабинета. Вернуться к нему после кабинета можно, только удалив копию
руками и перезапустив сервер памяти, и это осознанное решение владельца.

## Поля верхнего уровня

| Поле | Тип | Что значит |
|---|---|---|
| `version` | число | `1` — рукописный снимок хоста до кабинета, без `serial` и `bans`. `2` — снимок кабинета, с обоими |
| `serial` | целое ≥ 1 | Только в версии `2`, и там обязательно. Номер публикации: растёт с каждым снимком кабинета. Хост не применяет снимок, который не новее применённого (см. «Назначение») |
| `teamCount` | число ≥ 0 | Сколько команд у кабинета в базе на момент публикации, **включая удалённые**. Не меньше числа команд в `teams`. Базу, восстановленную из дампа, кабинет узнаёт не по нему — одних команд мало, дамп теряет и отозванный токен, и удалённого участника, — а по журналу своих публикаций: снимок на хосте должен быть последним, что записала эта база ([cabinetSetup.md](cabinetSetup.md)) |
| `teams` | объект | Слаг команды → команда. Может быть пустым |
| `tokens` | массив | HTTPS-токены агентов. Может быть пустым |
| `keys` | массив | ssh-ключи машин. Может быть пустым |
| `bans` | массив | Только в версии `2`, и там обязательно; может быть пустым. Кто забанен в кабинете |

## Имена

Слаг команды, `handle` участника, имя машины и имя агента — одно правило: строчные латинские буквы,
цифры и дефис, от 1 до 63 знаков, дефис не первым и не последним. Это имя каталога и аргумент
команд git и ssh: дефис в начале превратил бы имя в ключ команды.

```
^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$
```

Имя проекта подчиняется правилам каталога стора, общим для macOS, Windows и git: не пустое, не
длиннее предела имени файла, не `.`, `..` и `.git` (без учёта регистра), без символов, запрещённых
Windows (`< > : " / \ | ? *`), без управляющих символов, без точки или пробела в конце, не имя
устройства Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1`…`COM9`, `LPT1`…`LPT9`). Два имени проекта,
совпадающие после нормализации NFC и приведения к нижнему регистру, — одно и то же имя: на APFS и
NTFS это один каталог.

## Команда

| Поле | Тип | Правило |
|---|---|---|
| `adopted` | логическое | Необязательно, по умолчанию `false`. `true` — личный стор владельца, существовавший до команд. Такая команда в снимке одна |
| `repo` | строка | Абсолютный путь к голому репозиторию. **Только** у `adopted`, и у неё обязательно. Остальные команды живут в `/srv/vibememory/teams/<слаг>.git`, путь не пишется |
| `mode` | `"memory"` \| `"sync"` | Обязательно у всех, кроме `adopted`; у `adopted` запрещено. `memory` — только сервер памяти, клона у участников нет. `sync` — клон стора, транскрипты, тик |
| `writable` | логическое | Обязательно. `false` — команда удалена: чтение и экспорт работают, запись отвечает отказом с адресом кабинета. Окончание оплаты `writable` не снимает: команда без оплаты пишет в пределах бесплатной квоты, и держит её `quotaBytes` |
| `deleted` | строка `ГГГГ-ММ-ДД` | Необязательно, не у `adopted`. Команда удалена: хост переименует её каталог в `teams/<слаг>.deleted-<дата>.git`. У удалённой команды `writable: false`, пустые `members` и `projects`, и на неё не ссылается ни один токен и ни один ключ |
| `projects` | массив имён | **Только** у `mode: "memory"`, и у неё обязательно (может быть пустым). Запись в проект вне списка отвергается: в `memory` репозиторий пуст, и иначе проект создавала бы первая же запись. У `sync` и `adopted` проекты — то, что лежит в репозитории |
| `limits` | объект | Обязательно. У действующей команды: `maxRecords` и `maxRecordBytes`; у действующей не-`adopted` ещё `quotaBytes`. `seats` необязательно: без него команда принимает сколько угодно членов. У удалённой может быть пустым. Все значения — целые больше нуля |
| `members` | объект | `handle` → `"owner"` \| `"admin"` \| `"member"`. У действующей команды ровно один `owner`; у `adopted` ровно один член, и он `owner`; у удалённой — пусто. Если задано `seats`, членов не больше него |

**Отсутствие команды в снимке — не удаление.** Каталог команды, которой нет в снимке, хост не
трогает и показывает кабинету как «сироту». Удаляет только явный `deleted`. Иначе восстановление
кабинета из старого дампа или пустая база при раннем старте переименовали бы живые репозитории.

Лимиты:

| Ключ | Что ограничивает |
|---|---|
| `maxRecords` | Записей памяти в одном проекте: новая запись сверх предела получает отказ `too_many_entries`, правка существующей — нет |
| `maxRecordBytes` | Байтов в одной версии записи — в строке журнала, как она ляжет в стор. Больше — отказ `entry_too_large` |
| `quotaBytes` | Размер репозитория команды на диске, с историей. Проверяется при push (`quota`) и при каждой записи памяти: версия, с которой стор превысит квоту, получает отказ `quota_exceeded`. Забыть запись можно и сверх квоты — это не освобождает место, история остаётся |
| `seats` | Членов команды; нет — без ограничения |

## Токен

HTTPS-токен одного участника для одного агента. Клиент кладёт его в заголовок
`Authorization: Bearer <токен>`.

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | `tk_` и 8 знаков из алфавита `0123456789abcdefghjkmnpqrstvwxyz` (base32 Crockford, строчные). Легаси-токен — ровно `tk_legacy`. Уникален среди токенов |
| `legacy` | логическое | Необязательно, по умолчанию `false`. `true` — токен, выпущенный до кабинета и не имеющий формы `vmt_…`. Такой в снимке не больше одного, только в `adopted`-команде и только с `id: "tk_legacy"` |
| `sha256` | строка | SHA-256 **всей строки токена** в том виде, в каком она стоит в заголовке после `Bearer `, байты UTF-8, 64 шестнадцатеричных знака нижним регистром. Сам токен в снимок не попадает никогда |
| `team` | слаг | Действующая команда из `teams` |
| `member` | `handle` | Член этой команды |
| `agent` | имя | Кто пишет: `claude-code`, `vibeide`, `vibeidea` или своё. Ложится в поле `agent` каждой записи |
| `role` | `"reader"` \| `"writer"` | `reader` только читает. Не зависит от роли в команде: `member` может держать `writer` |
| `history` | логическое | Доступ к поиску по прошлым сессиям. `true` только у членов с ролью `owner` или `admin` |
| `projects` | `null` \| массив имён | `null` — все проекты команды. Список — только эти. У `memory`-команды каждое имя обязано быть в её `projects` |
| `expiresAt` | `null` \| строка | `null` — бессрочно. Иначе момент UTC в виде `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ`; после него токен отвечает как неизвестный |

Как хост узнаёт токен: строка вида `vmt_<8 знаков>_<секрет>` ищется по `id` `tk_<8 знаков>` и
сверяется отпечатком за постоянное время. Любая другая строка сверяется с единственной строкой
`legacy: true`. Неизвестный, отозванный и просроченный токен получают один и тот же ответ `401`.

## Ключ машины

ssh-ключ одной машины одного участника. С ним машина клонирует стор `sync`-команды, пушит в него и
ходит к серверу памяти по ssh. Ключ машины владельца открывает и его личный стор (`adopted`): новая
машина владельца подключается кодом из кабинета, как участник к команде, а не ключом, вписанным в хост
руками.

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | `mk_` и 8 знаков того же алфавита, что у токена. Уникален среди ключей |
| `member` | `handle` | Чей ключ |
| `machine` | имя | Метка машины у этого участника |
| `storeName` | строка | Ровно `<member>-<machine>`. Имя каталога машины `machines/<storeName>/` в сторе команды и префикс версий её записей. Уникально во всём снимке |
| `teams` | массив слагов | Не пустой. Каждая — действующая команда, в которой `member` состоит. `adopted` — только у ключа её владельца: другого члена у неё нет |
| `publicKey` | строка | `ssh-ed25519 <base64>` одной строкой, без комментария. Base64 раскрывается в блок ключа ed25519 с 32 байтами ключа. Других типов нет. Уникален во всём снимке |

## Бан

Пока бан действует, хост не пускает участника ни по одному его токену и ни по одному ключу, даже если
снимок их перечисляет: токен отвечает как неизвестный, ключ — `unknownKey`. Кабинет и сам не кладёт в
снимок токены и ключи забаненного; строка бана — вторая линия, на случай снимка, который их всё-таки
несёт. Причины бана в снимке нет: она остаётся в кабинете.

| Поле | Тип | Что значит |
|---|---|---|
| `member` | `handle` | Кто забанен. Состоять в какой-либо команде не обязан. Один бан на участника |
| `until` | `null` \| строка | `null` — бессрочно. Иначе момент UTC в виде `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ`; в этот момент бан кончается |

## Проверка: `vibememory-mcp access check <файл>`

Кабинет прогоняет через неё каждый снимок до того, как положить его на место, и каждое изменение
прав — до конца своей транзакции. Первая строка вывода — `ok` или код причины, вторая — что именно не
так. Код выхода: `0` — снимок годен, `1` — нет, `2` — файл не прочитан.

Проверки идут в порядке таблицы, и называется первая сработавшая.

| Код | Когда |
|---|---|
| `snapshotUnreadable` | Файл не прочитан |
| `snapshotMalformed` | Не JSON, поле не того типа, незнакомое поле или незнакомое значение перечисления |
| `unsupportedVersion` | `version` не `1` и не `2` |
| `versionFields` | У версии `1` есть `serial` или `bans`; у версии `2` нет одного из них или `serial` меньше `1` |
| `invalidSlug` | Слаг команды не проходит правило имён |
| `invalidHandle` | `handle` в `members`, `tokens`, `keys` или `bans` не проходит правило имён |
| `invalidMachine` | Имя машины не проходит правило имён |
| `invalidAgent` | Имя агента не проходит правило имён |
| `invalidStoreName` | Имя проекта не проходит правило каталога стора |
| `storeNameCollision` | Два имени проекта одной команды совпадают после NFC и нижнего регистра |
| `invalidDate` | `deleted`, `expiresAt` или `until` бана не в своём формате |
| `adoptedTwice` | Больше одной команды с `adopted: true` |
| `adoptedRules` | У `adopted` нет `repo` или он не абсолютный, либо есть `mode`, `projects`, `deleted`, `quotaBytes` или `seats` |
| `adoptedMembers` | У `adopted` не ровно один член или он не `owner` |
| `repoOutsideAdopted` | `repo` у команды без `adopted: true` |
| `modeMissing` | У не-`adopted` команды нет `mode` |
| `projectsMisplaced` | `projects` у команды не в режиме `memory` или нет `projects` у `memory`-команды |
| `limitsInvalid` | Нет обязательного лимита, лимит не на своём месте или не целое больше нуля |
| `deletedTeamActive` | У удалённой команды `writable: true`, есть члены или проекты, либо на неё ссылается токен или ключ |
| `ownerCount` | У действующей команды не ровно один `owner` |
| `seatsExceeded` | Задано `seats`, и членов больше него |
| `teamCountLow` | `teamCount` меньше числа команд в снимке |
| `invalidTokenId` | `id` токена не в форме `tk_` и 8 знаков и не `tk_legacy` |
| `invalidKeyId` | `id` ключа не в форме `mk_` и 8 знаков |
| `duplicateId` | Два токена или два ключа с одним `id` |
| `invalidDigest` | `sha256` не из 64 шестнадцатеричных знаков нижнего регистра |
| `banTwice` | Два бана одного участника |
| `unknownTeam` | Токен или ключ ссылается на команду, которой нет в снимке (ссылка на удалённую — `deletedTeamActive`) |
| `notAMember` | Участник токена или ключа не состоит в названной команде |
| `historyNotAllowed` | `history: true` у токена участника с ролью `member` |
| `projectOutsideTeam` | Токен `memory`-команды называет проект вне её `projects` |
| `legacyTokenTwice` | Больше одного токена с `legacy: true` |
| `legacyTokenMisplaced` | Легаси-токен не в `adopted`-команде или не с `id: "tk_legacy"`, либо `tk_legacy` без `legacy: true` |
| `storeNameMismatch` | `storeName` ключа не равен `<member>-<machine>` |
| `storeNameTaken` | Два ключа с одним `storeName` |
| `keyWithoutTeams` | У ключа пустой список `teams` |
| `invalidPublicKey` | `publicKey` — не `ssh-ed25519`, не одна строка, не раскрывается в 32 байта ключа или содержит управляющий символ |
| `publicKeyTwice` | Два ключа несут один открытый ключ: sshd взял бы для обоих первую строку, и машина одного входила бы машиной другого |

Коды — часть контракта: их читает кабинет и показывает человеку своими словами. Переименование кода
ломает кабинет так же, как переименование поля.

## Хеш снимка

Хешем снимка считается SHA-256 байтов файла, как они записаны. Хост кладёт хеш последнего применённого
снимка в свой отчёт ([hostStatusSpec.md](hostStatusSpec.md)), и кабинет сверяет его с хешем того, что
публиковал: расхождение видно, а не предполагается.
