# Хост стора: ключ, bare-репозиторий, зеркало

Стор — приватный git-репозиторий на **своём** хосте (`vm@vibememory.ru`). Машины пушат туда и
забирают оттуда; зеркало в приватный GitHub делает сам хост, а не машина, — тогда бэкап не
зависит от того, чья машина пушила последней.

Три шага, три скрипта, все запускаются **на домашней машине**.

## 1. Ключ — `./infra/seedKey.sh`

Единственный шаг, который делает владелец: `ssh-copy-id` спрашивает пароль учётки, и вводите его
вы, прямо в приглашении ssh. Скрипт пароль не видит, никуда не пишет и не передаёт.

```sh
./infra/seedKey.sh                 # vm@vibememory.ru, ключ ~/.ssh/id_ed25519_vibememory
./infra/seedKey.sh --user vm --host vibememory.ru --port 22
```

Создаёт ключ (если нет), копирует публичную половину, добавляет алиас `vibememory` в
`~/.ssh/config` и проверяет вход **только по ключу** (`BatchMode`, пароль запрещён). Повторный
запуск безвреден: ключ переиспользуется, `ssh-copy-id` не дублирует запись, алиас добавляется раз.

**Ключ с парольной фразой нужно один раз положить в агент:**

```sh
ssh-add --apple-use-keychain ~/.ssh/id_ed25519_vibememory
```

Иначе всё неинтерактивное — тик, скрипты — получает `Permission denied` **сразу после** того,
как сервер уже принял ключ (`debug1: Server accepts key`): подписать вход без фразы нечем, а
спросить её некому. Сообщение об этом не говорит ни слова, поэтому проверка встроена в
`seedKey.sh`, а `AddKeysToAgent`/`UseKeychain` он пишет в `~/.ssh/config` сам.

## 2. Репозиторий — `./infra/hostBootstrap.sh`

```sh
./infra/hostBootstrap.sh
./infra/hostBootstrap.sh --mirror git@github.com:owner/vibememory-store.git
```

Заводит `~/vibememory/store.git` (bare, ветка `main`) и ставит настройки, которые для стора
транскриптов не косметика:

- `core.autocrlf=false` — байты остаются байтами; иначе редактор с CRLF задвоил бы блок состояния
  каждой строки;
- `core.filemode=false` — бит исполняемости у машин разный и ничего здесь не значит;
- `gc.auto=0` — сборка мусора на приёме push'а посреди тика не нужна.

С `--mirror` пишется хук `post-receive`, делающий `git push --mirror` в указанный репозиторий.
Недоступное зеркало **не** отклоняет push: приняли, о зеркале написали в stderr. Ключ на сервере
должен уже лежать — но заводить его руками не нужно, это делает шаг 4.

## 3. Привязка машины — `./infra/connectStore.sh`

```sh
./infra/connectStore.sh
```

Добавляет `origin`, пушит `main` **без** force (история сервера главнее локальной) и только после
удачного push записывает `remote` в `~/.vibememory/config.json`. Порядок именно такой: конфиг с
нерабочим remote заставлял бы каждый тик тратить две минуты на неудачу. Чужой `origin`, если он
уже задан и указывает в другое место, скрипт не перенацеливает — разбирается человек.

## Вторая машина

То же самое, кроме шага 2: репозиторий уже есть. `seedKey.sh` → `git clone` стора в
`~/.vibememory/store` → `vibememory install` → `connectStore.sh` (он увидит существующий
`origin` и просто проверит).

## 4. Бэкап в свой приватный репозиторий — `./infra/mirrorSetup.sh`

Необязательный шаг: хост после каждого принятого push копирует стор в приватный репозиторий у
любого git-хостинга. Репозиторий **ваш** — в коде движка не зашит ни один адрес.

```sh
gh repo create <owner>/<name> --private   # или тем же в UI GitLab/Gitea — главное, пустым
./infra/mirrorSetup.sh --repo <owner>/<name>          # github.com
./infra/mirrorSetup.sh --repo <owner>/<name> --host gitlab.com
```

Скрипт заводит на сервере отдельный ключ `~/.ssh/githubMirror` и ssh-алиас `githubMirror`
(не `Host github.com` — глобальная запись перехватила бы любой другой доступ к хостингу с этого
сервера), прописывает `known_hosts` (хук работает без терминала и незнакомый хост не спросит),
регистрирует ключ как **deploy key с правом записи** — сам через `gh`, если он есть и имеет
доступ, иначе печатает ключ и ссылку, — ставит хук и запускает первый залив на сервере фоном.

Первый залив идёт вне хука намеренно: это весь стор целиком (у владельца 619 МБ), а внутри
`post-receive` его ждала бы та машина, чей push его вызвал.

Не GitHub: единственный зависящий от провайдера шаг — регистрация deploy-ключа. GitLab — deploy
key с `can_push=true`, Gitea — снять «Read only», свой сервер — строка в `authorized_keys`.
Остальное не меняется; `--repo` принимает `owner/name`, а адрес хоста берётся из алиаса
`storeMirror` в `~/.ssh/config` на сервере, а сам хостинг задаётся флагом `--host`
(по умолчанию `github.com`).

**Проверка — фактом:** `vibememory doctor` печатает строку зеркала и падает, если голова зеркала
разошлась с головой хоста. Подробности и грабли —
[knowledge/design/mirrorSetup.md](../knowledge/design/mirrorSetup.md).

**Важно:** в зеркало нельзя коммитить руками — `push --mirror` приводит его к состоянию хоста и
сотрёт всё лишнее, включая README, созданный мастером репозитория.
