# Как подключить память VibeMemory к любому агенту

> Мануал «как сделать». Что именно умеет сервер и почему устроен так — в
> [functional.md](../functional.md) и [knowledge/design](../knowledge/README.md).

Сервер `vibememory-mcp` отдаёт по MCP ту же память, которую ведёт движок: он читает журнал
записей в сторе и дописывает в него события. Своей модели у него нет, поэтому память остаётся
одна на всех агентов и на все машины.

## Что нужно заранее

Установленный движок (`vibememory doctor` — все шаги ok). Сервер берёт стор из
`~/.vibememory/config.json`, как и всё остальное; переменная `VIBEMEMORY_DIR` переопределяет
каталог движка, если он лежит не там.

## Сборка и установка

```bash
cargo build --release
vibememory install
```

`install` кладёт сервер рядом с движком, подписывает его тем же сертификатом и проверяет, что
установленное **запускается**.

**Не копируйте бинарь руками.** Перезапись файла, который уже запускали, делает его
недействительным для ядра: macOS убивает каждый следующий запуск сигналом SIGKILL без единого
сообщения, а `codesign --verify` при этом продолжает называть файл валидным. Замер и способ
повторить — [knowledge/design/binaryReplacement.md](../knowledge/design/binaryReplacement.md).

## Claude Code

```bash
claude mcp add vibememory ~/.vibememory/bin/vibememory-mcp -- --agent claude-code
```

Проверить: `claude mcp list` покажет `vibememory`, а в сессии станут доступны инструменты
`memory_search`, `memory_get`, `memory_save`, `memory_update`, `memory_delete`.

## Любой другой клиент MCP

Транспорт — stdio, поэтому конфигурация везде одинакова по смыслу:

```json
{
  "mcpServers": {
    "vibememory": {
      "command": "/Users/<вы>/.vibememory/bin/vibememory-mcp",
      "args": ["--agent", "codex"]
    }
  }
}
```

**`--agent` заполняйте по-разному для разных клиентов.** Это имя попадает в поле `agent` каждой
записи, и памяти оно нужно, чтобы отвечать на вопрос «кто это написал». Без флага сервер
подписывается `mcp` — честно, но бесполезно, когда клиентов несколько.

## Инструменты

| Инструмент | Обязательные параметры | Что делает |
|---|---|---|
| `memory_search` | — | Ищет по словам в заголовке, описании, теле и идентификаторе. Фильтры: `project`, `kind`, `status`. Без `project` ищет по всем проектам. Всегда возвращает `status`. |
| `memory_get` | `id` | Полный текст записи, её ссылки и **версия** — она нужна для `memory_update`. |
| `memory_save` | `project`, `id`, `kind`, `title`, `description`, `body` | Новая запись. Отказывает, если идентификатор занят. |
| `memory_update` | `project`, `id` | Меняет только переданные поля; остальные остаются. Пишет новую версию с родителем — той, которую вы видели. |
| `memory_delete` | `project`, `id` | Просит забыть. Версии остаются в журнале, запись перестаёт показываться. |
| `history_search` | `query` | Ищет по словам в прошлых сессиях. Возвращает проект, сессию, время и выдержку — не транскрипты целиком. Новые первыми. Фильтры: `project`, `limit` (20 по умолчанию, 100 максимум). |

`kind` — одно из `user`, `feedback`, `project`, `reference`. `status` — `active` или `stale`.
Неизвестное значение отвергается, а не считается значением по умолчанию.

## Что сервер намеренно не делает

- **Не пишет markdown.** Проекцию делает движок; два писателя в одни файлы — это потерянные
  правки.
- **Не решает конфликты.** Две правки от одной версии остаются обеими, как и везде в этой
  системе.
- **Не ходит в сеть.** Только локальный стор; HTTP с токеном — отдельная задача для агентов без
  локального стора.

## Почему поиск по истории ограничен

Корпус транскриптов на этой машине — 1959 файлов и 1.7 ГиБ. Поиск идёт **новыми сессиями вперёд**
и читает файл только когда до него дошёл: набрав нужное число совпадений, он останавливается и
остальные не открывает. Поэтому `limit` — не украшение, а то, что отделяет полсекунды от минуты;
а `project`, когда он известен, сужает выборку сильнее всего.

Выдержка обрезается: она нужна, чтобы узнать момент, а не чтобы отдать разговор целиком.

## Если поиск ничего не находит

Проверьте, есть ли журналы: `find ~/.vibememory/store/projects -name memory.jsonl`. Пусто —
значит память на этой машине пока живёт только в markdown и записями не стала; почему так и что
с этим делать, разобрано в
[knowledge/design/memoryNeverMetReality.md](../knowledge/design/memoryNeverMetReality.md).
