# Спека памяти как записей

> Скопируйте этот файл целиком своей LLM и попросите собрать запись памяти или разобрать журнал:
> здесь описан весь формат, читать исходники не нужно.

Память VibeMemory — это **записи**, а не файлы. Файлы `memory/*.md`, которые пишет и читает
Claude Code, — проекция записей: движок их генерирует и импортирует правки обратно. Так одна
память живёт на двух машинах и (позже) у нескольких агентов сразу.

## Где что лежит

| Путь в сторе | Что это |
|---|---|
| `projects/<имя>/memory.jsonl` | журнал: одна строка — одна версия записи или просьба забыть |
| `projects/<имя>/memory/MEMORY.md` | индекс-проекция: строка на запись |
| `projects/<имя>/memory/<id>.md` | проекция записи |
| `projects/<имя>/memory/<id>.rival-<версия>.md` | версия, написанная одновременно с текущей |

Журнал — обычный JSONL с полем `uuid` в каждой строке, поэтому его сливает тот же драйвер, что и
транскрипты: объединение по `uuid`, ничего не теряется. Отдельных правил слияния у памяти нет.

## Строка журнала

Запись новой версии:

```json
{"uuid":"mac-main-2026-09-03T12:00:00Z-store-naming","parent":"mac-main-2026-09-03T10:05:00Z-store-naming","action":"upsert","record":{"id":"store-naming","kind":"project","project":"VibeMemory","title":"Store naming","description":"откуда берётся имя стора","body":"Имя следует из общего git-каталога.","links":["merge-rules"],"agent":"claude-code","createdAt":"2026-09-03T10:00:00Z","updatedAt":"2026-09-03T12:00:00Z"}}
```

Просьба забыть:

```json
{"uuid":"mac-main-2026-09-03T12:30:00Z-store-naming","parent":"mac-main-2026-09-03T12:00:00Z-store-naming","action":"delete","id":"store-naming","agent":"claude-code","updatedAt":"2026-09-03T12:30:00Z"}
```

| Поле | Смысл |
|---|---|
| `uuid` | идентичность **версии**; по нему сливаются журналы двух машин |
| `parent` | версия, которую видел писавший; отсутствует у первой версии |
| `action` | `upsert` или `delete` |
| `record.id` | идентичность записи: `[a-z0-9-]`, до 64 символов, без двойных и краевых дефисов |
| `record.kind` | `user`, `feedback`, `project`, `reference` — неизвестный вид отвергается, а не угадывается |
| `record.project` | к какому проекту относится (по MCP запись приходит без пути) |
| `record.title` | человеческое имя, одна строка — идёт в индекс |
| `record.description` | одна строка «что внутри»: по ней решают, нужна ли запись |
| `record.body` | сама память, markdown |
| `record.links` | другие записи, на которые ссылается тело (`[[id]]`), в порядке появления |
| `record.status` | `active` (по умолчанию) или `stale` — «было правдой, перестало». Поле необязательное: `active` в строку не пишется |
| `record.agent` | кто написал эту версию |
| `record.createdAt` / `record.updatedAt` | время по часам писавшего |

## Документ-проекция

```markdown
---
name: store-naming
title: Store naming
description: откуда берётся имя стора
metadata:
  type: project
  project: VibeMemory
  agent: claude-code
  created: 2026-09-03T10:00:00Z
  updated: 2026-09-03T12:00:00Z
  version: mac-main-2026-09-03T12:00:00Z-store-naming
---

Имя следует из общего git-каталога, а не из рабочего дерева. См. [[merge-rules]].
```

Устаревшая запись выглядит так — в документе поле, в индексе пометка:

```markdown
---
name: cache-ttl
title: Prompt cache TTL
description: how long the cache lives
metadata:
  type: project
  project: VibeMemory
  status: stale
  agent: claude-code
  created: 2026-09-03T10:00:00Z
  updated: 2026-09-03T11:00:00Z
  version: e2
---
```

```markdown
- [Prompt cache TTL](cache-ttl.md) — **stale**, how long the cache lives
```

`metadata.version` — не украшение: по нему правка файла узнаёт, из какой версии она сделана.
Если модель перепишет файл и потеряет это поле, движок возьмёт текущую версию записи — правка не
потеряется, но станет неотличима от сделанной «поверх свежего».

## Правила, которые стоит знать

- **Две версии от одного родителя — обе живут.** Проецируется первая по `(updatedAt, uuid)`,
  вторая ложится рядом файлом `<id>.rival-<версия>.md`, а индекс просит их свести. Победителя по
  часам движок не выбирает: память — единственное, что обе машины правят каждую сессию.
- **Статус ставит человек или агент, никогда не движок.** Устарел факт или нет — знает только
  тот, кто это заметил; автоматика тут может лишь соврать. Пометить можно правкой файла
  (`status: stale` в `metadata`) — тик прочитает это как новую версию. Запись при этом **не
  удаляется**: она объясняет, почему когда-то было сделано так, а `delete` эту причину потерял бы.
  Обратно в `active` возвращают тем же способом.
- **Значений всего два, и это осознанно.** «Перекрыта новой версией» — это `parent`, «забыта» —
  это `delete`, «две машины разошлись» — это rival-версии. Заводить для них ещё и статус значило
  бы дать одному факту два источника правды.
- **Неизвестный статус отвергается** (`unknownStatus`), а не считается `active`: догадка тихо
  вернула бы доверие к факту, который кто-то пометил как ненадёжный.
- **Удаление — явный акт.** Пропавший файл проекции удалением не считается: он мог исчезнуть по
  десятку невинных причин. Забывает только строка `delete` — и если после увиденной ею версии
  кто-то писал запись, значит она ещё нужна, и она остаётся.
- **Чтение нетронутой проекции ничего не пишет.** Тик идёт каждые две минуты; версия появляется,
  только когда файл действительно изменился.
- **Неразобранная строка журнала не выбрасывается**, а считается: её мог написать движок новее.
- **Чужие файлы в каталоге памяти** (не проекции) отклоняются с кодом и остаются на месте.

Коды ошибок: `invalidId`, `unknownKind`, `unknownStatus`, `invalidTitle`, `invalidDescription`, `emptyBody`,
`unserializable`, `missingFrontmatter`, `missingField`.

## Фикстуры

Сценарии — `fixtures/memory/memoryScenarios.json`, драйвер — `crates/vibememory-core/tests/memory_fixtures.rs`.
Кейс: `journal` (строки журнала как есть) + `expect` с ожидаемым состоянием (`records`,
`forgotten`, `unreadable`), точным текстом отдельных файлов проекции (`files`), набором имён
(`fileNames`), ссылками (`links`) и разделом `import` (`documents` или `useProjection`, ожидаемые
`events` и `rejected`). Ожидания пишутся руками по этой спеке — не из кода.
