# Как добавить кейс в `fixtures/secrets/`

Память, правило и навык общие и остаются в истории стора навсегда, поэтому текст, в котором есть ключ, не
пишется: `vibememory_core::secrets::find` узнаёт вид ключа по форме и возвращает его название, но не значение.
Какие виды и пороги длины — [memoryRecordsSpec.md](memoryRecordsSpec.md), раздел о записи с ключом.

Тип — `crates/vibememory-core/src/secrets.rs`, ожидания — `fixtures/secrets/secretsScenarios.json`,
драйвер — `crates/vibememory-core/tests/secrets_fixtures.rs`.

## Главное: целого ключа в фикстуре нет

Ключ по виду настоящий — для сканера секретов на GitHub и для гейта приватности `fixture_hygiene`, который ищет в
фикстурах `ghp_`, `sk-ant-` и `-----BEGIN`. Поэтому кейс хранит не значение, а рецепт: голову ключа кусками,
заполнитель и длину. Строку собирает тест.

```json
{
  "id": "githubFineGrained",
  "provenance": "computed",
  "note": "Фраза о том, что кейс проверяет.",
  "text": "GH={key}",
  "key": { "head": ["github", "_pat_"], "fill": "A1_", "length": 71 },
  "expect": { "kind": "githubToken" }
}
```

- `text` — проверяемый текст; `{key}` стоит там, куда тест подставит собранное значение. Кейс без `key` — текст как есть.
- `key.head` — голова ключа кусками: тест склеивает их, а в файле ни один кусок не похож на префикс.
  Режьте так, чтобы ни `ghp_`, ни `sk-ant-`, ни `-----BEGIN` не стояли в файле целыми, и в `note` тоже.
- `key.fill` — заполнитель; тест повторяет его по кругу до `key.length` знаков после головы. Для вида с цифрой в
  теле (`sk-`) в заполнителе нужна цифра.
- `key.length` — сколько знаков заполнителя идёт после головы; у закрытого ключа PEM — 0, заголовка достаточно.
- `expect.kind` — код вида ключа (`SecretKind::code`): `openAiKey`, `anthropicKey`, `awsAccessKey`, `githubToken`,
  `slackToken`, `googleApiKey`, `stripeKey`, `privateKey`, `vibeMemoryToken`; `null` — текст ключа не содержит.
- Токен агента `vmt_…` пишется в `text` как есть: его секрет — один повторённый символ, как требует гейт приватности.

Каждый вид должен иметь хотя бы один кейс с ключом, а ложные тревоги — свои кейсы (`sk-learn`, `AKIA` внутри длинного
слова, короткий префикс GitHub, `AIza` с хвостом длиннее 35 знаков, открытый ключ PEM): тест проверяет и то, и другое.

## Порядок добавления

1. Кейс в JSON, ожидание — руками из формы ключа вендора, не из вывода `find`.
2. `cargo test --test secrets_fixtures` — падение до правки сканера и есть смысл кейса.
3. Новый вид ключа — вариант в `SecretKind` (название и код), константы длины в `secrets.rs`, кейс с ключом и
   кейсы ложных тревог, строка в списке видов в [memoryRecordsSpec.md](memoryRecordsSpec.md).
