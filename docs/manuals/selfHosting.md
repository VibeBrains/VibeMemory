# Свой сервер VibeMemory: установка и управление

> Мануал «как сделать». Как поднять VibeMemory на своём сервере и управлять командами, участниками,
> агентами и машинами из терминала — без веб-кабинета.

Веб-кабинет — часть облачной версии на [vibememory.ru](https://vibememory.ru) и платного внедрения:
в открытый код он не входит.
На своём сервере то же самое делает консоль хоста — `vibememory-mcp admin`.
Она пишет тот же снимок прав, что и кабинет, и перед записью проверяет его так же, как хост: записать то, что хост
отвергнет, консоль не может.

Нужен веб-кабинет на своём сервере — с участниками, приглашениями и токенами в браузере — это платное
внедрение: напишите на i@borodatych.ru.

## 1. Что нужно

- Сервер с Linux (Debian или Ubuntu) и доступом по ssh с sudo
- Домен, направленный на сервер: агенты ходят на `https://<домен>/mcp`, машины — по ssh на `<домен>`
- Домашняя машина с macOS или Linux, откуда запускаются скрипты `infra/`
- Клон этого репозитория на домашней машине и собранный под Linux `vibememory-mcp`
  (`cargo build --release --target x86_64-unknown-linux-gnu` или архив выпуска)

## 2. Поднять хост

Скрипты запускаются на домашней машине, из корня репозитория.
Подробности каждого шага — в [hostSetup.md](hostSetup.md).

```bash
./infra/seedKey.sh --user <учётка> --host <домен>
./infra/hostBootstrap.sh
./infra/hostMcp.sh --binary <vibememory-mcp под Linux> --owner <ваш ник>
```

На чистом сервере `hostBootstrap.sh` сам ставит git, а `hostMcp.sh` собирает первый снимок прав: личный стор с вами
владельцем и без токенов — их выдаёт консоль.
Переезд со старого однотокенного сервера сохраняет его токен строкой `tk_legacy`.

После `hostMcp.sh` на хосте работают сервер памяти, приём push от машин, применение прав и Caddy с сертификатом.

**fail2ban** ставится до `hostMcp.sh`, по шагу 3 [serverHardeningPrompt.md](serverHardeningPrompt.md): там джейл sshd с
бэкендом systemd и проверка, что баны доходят до firewall.
Без него `hostMcp.sh` пропускает джейл для `/mcp` и говорит об этом.
Сам скрипт fail2ban не ставит: пакет Debian сразу включает джейл sshd, а без настройки бэкенда тот на Debian 13 не
стартует и роняет все джейлы.
Ник владельца — строчные латинские буквы, цифры и дефис: им вы будете в каждой команде.

## 3. Включить консоль

Дальше всё делается на сервере, по ssh, через `sudo`.
Первая команда записывает домен, который консоль назовёт машинам и агентам:

```bash
sudo /srv/vibememory/bin/vibememory-mcp admin init --domain <домен>
```

Короче — псевдоним в `~/.bashrc` на сервере:

```bash
alias vm-admin='sudo /srv/vibememory/bin/vibememory-mcp admin'
```

Ниже команды даны с ним.
Список всех команд — `vm-admin help`, текущее состояние — `vm-admin show`.

## 4. Команды

**Команда — это общий стор: память и, если включены, сессии.**
Сессии выключены — команда делит только память, у участников нет клона, список проектов ведёт консоль.
Сессии включены — у каждой машины участника клон стора с транскриптами, проекты — то, что лежит в сторе.

```bash
vm-admin team add acme --owner alice                   # команда acme, владелец alice, сессии выключены
vm-admin team add acme --owner alice --sessions        # то же с сессиями
vm-admin team add acme --owner alice --quota-mb 2048   # своё место; по умолчанию 10 ГБ
vm-admin team sessions acme on                         # включить сессии
vm-admin team sessions acme off                        # выключить: сессии удаляются с сервера, память остаётся
vm-admin team quota acme 4096                          # место команды, МБ
vm-admin team remove acme --confirm                    # удалить команду
```

**Удаление** — стор не стирается: хост переименовывает его в `teams/acme.deleted-<дата>.git` и хранит.
Токены и ключи команды уходят сразу.
Имя удалённой команды не освобождается никогда: новая команда с тем же именем получила бы чужую историю.

**Выключение сессий** удаляет транскрипты с сервера безвозвратно: хост переписывает стор до памяти и служебных
файлов. Машины выходят из стора на следующем тике, у участников сессии остаются локально.

## 5. Проекты

Только у команды с выключенными сессиями: запись в проект вне списка сервер отвергает.
У команды с сессиями проекты — то, что машины положили в стор.

```bash
vm-admin project add acme Promed       # имя — как каталог проекта у агентов
vm-admin project remove acme Promed    # из списка; записи в сторе остаются
```

## 6. Участники

```bash
vm-admin member add acme bob             # участник
vm-admin member add acme carol --admin   # админ: ему доступен поиск по прошлым сессиям
vm-admin member role acme bob admin      # сменить роль: admin или member
vm-admin member remove acme bob          # исключить
```

Исключённый теряет все свои токены этой команды, а его машины больше её не открывают.
Владельца исключить нельзя, и сменить ему роль тоже: у команды ровно один владелец.
Админ, ставший участником, теряет поиск по прошлым сессиям во всех своих токенах этой команды.

## 7. Агенты: токены

Токен — доступ одного агента одного участника к памяти команды.
Сам токен хранится только на машине участника, в снимке — его отпечаток.

**На сервере:**

```bash
vm-admin token issue acme bob claude-code
vm-admin token issue acme bob codex --reader                        # только чтение
vm-admin token issue acme carol claude-code --history               # с поиском по прошлым сессиям, только owner и admin
vm-admin token issue acme bob cursor --projects Promed,Web          # только эти проекты
vm-admin token issue acme bob vibeide --expires 2027-01-01T00:00:00Z
vm-admin token revoke tk_8mtcwarp                                   # отозвать
```

`token issue` печатает **грант** — одну строку JSON.
Передайте её участнику личным сообщением: в ней токен, и больше его нигде нет.

**На машине участника:**

```bash
vibememory connect --grant
```

Вставить строку гранта и нажать Enter.
`connect` кладёт токен в `~/.vibememory/tokens/<команда>/<агент>` с доступом только владельцу и печатает команду
регистрации сервера в агенте. Дальше — как в [teamSetup.md](teamSetup.md), с шага 4.

Имя агента — то, под которым он подключит сервер памяти: `claude-code`, `codex`, `cursor`, `vibeide`, `vibeidea`,
`dsh-desktop`.
`vibememory mcp-config` показывает имена всех известных агентов.

## 8. Машины: ключи

Ключ машины нужен только команде с сессиями: с ним машина клонирует стор и отправляет сессии.
Это три шага, и первый — на машине: ключ делает она сама, закрытая половина её не покидает.

**1. На машине участника:**

```bash
vibememory connect --key-request
```

Печатает строку `ssh-ed25519 …` — открытую половину ключа, её можно пересылать как угодно.
Повторный запуск печатает тот же ключ.

**2. На сервере** — та строка на вход консоли:

```bash
echo 'ssh-ed25519 AAAA…' | vm-admin key add bob laptop acme
vm-admin key add bob laptop acme,research < bob.pub        # ключ на несколько команд
vm-admin key revoke mk_kx89znzy                              # отозвать
```

`bob laptop` — ник участника и имя его машины.
Команды через запятую, первая — та, стор которой машина клонирует сейчас.
Консоль печатает грант ключа.

**3. Снова на машине:**

```bash
vibememory connect --grant
```

Вставить грант.
Машина кладёт ключ к стору команды, проверяет ключ хоста по гранту и клонирует стор.
Если движок на машине ещё не настроен — у участника нет своего личного стора, — `connect` настраивает его сам:
пишет `config.json` с именем машины и ставит хуки и расписание тика.
Имя — сетевое имя машины, своё задаётся флагом: `vibememory connect --grant --machine-id <имя>`.

Не удалось — ключ на машине выбрасывается: отзовите его (`key revoke`) и начните с первого шага.

**Личный стор владельца.** Ваша вторая машина подключается к вашему личному стору так же:
`connect --key-request` на ней, `vm-admin key add <ваш ник> <машина> personal` на сервере, `connect --grant` на ней.

## 9. Как это применяется

Консоль пишет `/srv/vibememory/access/access.json` и ничего больше.
Хост применяет снимок сам, как только файл изменился: заводит сторы команд, обновляет ключи `vmgit`, переименовывает
удалённые команды.
Сервер памяти перечитывает файл без перезапуска.
Проверить, что снимок цел: `sudo /srv/vibememory/bin/vibememory-mcp access check /srv/vibememory/access/access.json`.

Каждое изменение увеличивает номер снимка (`serial`): хост не применяет снимок старше того, что уже применил.
Поэтому старую копию файла поверх новой положить нельзя — это не откат, а отказ.

На хосте с кабинетом консоль не работает: там снимок пишет кабинет, а второй писатель терял бы свои изменения при его
следующей публикации.

## 10. Проверить

- **На сервере:** `vm-admin show` — команды, участники, проекты, токены и ключи
- **На машине участника:** `vibememory doctor` — подключённые команды, токены, сервер памяти

Формат файла прав, если нужно разобраться глубже, — [accessSnapshotSpec.md](accessSnapshotSpec.md).
