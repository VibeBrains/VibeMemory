# Участник команды: агент с памятью команды

> Для участника команды в режиме `memory`: как поставить программы, подключить агента, проверить и
> отключить. Команда в режиме `sync`, где машины обмениваются транскриптами, описывается здесь же, когда
> она появится; сейчас её в кабинете не завести.

## Что это даёт

Команда держит общую память на хосте VibeMemory: записи — решения, соглашения, заметки о проектах —
которые агент каждого участника читает и пишет через сервер памяти по HTTPS. Транскрипты сессий
команда не получает: они остаются у каждого на его машине. Без сети памяти команды нет — сервер на
хосте, а копии на машине участника не хранится.

Каждому агенту нужен свой токен: он называет команду, участника и агента и подписывает каждую запись.
Токен выдаёт кабинет, но показывает его не человеку, а машине: на странице команды делается
одноразовый код, и программа `vibememory` на машине меняет его на токен. Токен ложится в файл, который
читает только владелец учётки; в чат, терминал и историю оболочки он не попадает.

## 1. Учётка

Участника приглашает владелец или админ команды — ссылкой. По ссылке заводится учётка кабинета
(адрес, пароль, хэндл) или используется существующая. Хэндл подписывает каждую запись участника и не
меняется никогда.

## 2. Программы

Одна пара программ на систему, в одном архиве: `vibememory` и `vibememory-mcp`. Строки установки —
на странице «Download» кабинета, под каждую систему свои: они скачивают архив и его сумму, проверяют
сумму и распаковывают архив в новый каталог. Ставить из терминала: скачанное браузером macOS
остановит Gatekeeper, `curl` — нет. На Windows — в Git Bash.

Затем из распакованного каталога:

```bash
./vibememory install
```

Без настроенного движка (`~/.vibememory/config.json`) `install` только кладёт обе программы в
`~/.vibememory/bin`: машине участника `memory`-команды больше ничего не нужно. Этот каталог стоит
добавить в `PATH`.

## 3. Подключить агента

1. В кабинете: страница команды → «Connect an agent». Выбрать агента (`claude-code`, `codex`, `cursor`,
   `zed`, `cline`, `vibeide`, `vibeidea` или своё имя: строчные латинские буквы, цифры и дефис), права («Read and write» или «Read only»), при желании
   — только некоторые проекты. Поиск по прошлым сессиям доступен только владельцу и админам.
2. «Make a code» — кабинет покажет одноразовый код на несколько минут и строку вида

   ```bash
   vibememory connect --cabinet https://app.vibememory.ru --agent claude-code
   ```

3. Выполнить строку на машине агента и ввести код, когда программа его спросит. Код не пишут в
   аргументах: список процессов виден каждому пользователю машины, и `connect` откажется.

`connect` кладёт в `~/.vibememory/tokens/<команда>/<агент>`:

- сам токен — файл, доступный только владельцу учётки (на Windows права сужает `icacls`);
- сайдкар `<агент>.json` без токена — откуда токен, его публичный id и адрес сервера памяти;
- фрагмент `<агент>.mcp.json` — конфигурация сервера для агентов, которые читают список MCP-серверов из
  JSON; в нём токен, права у файла те же.

И печатает, куда он всё положил, и строку регистрации для Claude Code.

Каталог — `tokens` внутри каталога движка: `~/.vibememory` или то, что задано в `VIBEMEMORY_DIR`.
Клиент, который ищет команды сам, должен учитывать эту переменную так же, как `connect` и `mcp-headers`.

### Сайдкар — контракт для клиентов

Сайдкар — единственное место, откуда клиент без фрагмента `.mcp.json` узнаёт, куда подключаться.
Секрета в нём нет, читать его можно свободно.
Поля:

| Поле | Что значит |
| --- | --- |
| `cabinet` | адрес кабинета, выдавшего токен |
| `team` | короткое имя команды — совпадает с именем папки |
| `member` | ник участника, которому выдан токен |
| `agent` | имя агента — совпадает с именем файла |
| `tokenId` | публичный id токена (`tk_…`); новый `connect` меняет его, и по нему клиент видит, что токен переоформлен |
| `mcpUrl` | адрес сервера памяти команды — туда клиент шлёт MCP по HTTP; `https://` на хосте кабинета или его родительском домене, `http://` — только адрес этой машины (проверка с локальным `vibememory-mcp --http`) |

Сервер регистрируется под именем `vibememory-<команда>`.
Заголовок `Authorization` клиент получает у `vibememory mcp-headers <команда> <агент>` при каждом подключении,
а файл токена сам не открывает.
Новых полей сайдкар может получить сколько угодно; перечисленные не переименовываются и не меняют смысла.

## 4. Зарегистрировать агента

**Claude Code** — строкой, которую напечатал `connect`:

```bash
claude mcp add-json --scope user vibememory-<команда> '{"headersHelper":"…/vibememory mcp-headers <команда> <агент>","type":"http","url":"…"}'
```

Claude Code при каждом соединении сам спрашивает заголовок у `vibememory mcp-headers`, и токен не
лежит ни в его конфигурации, ни в аргументах процессов. Регистрация — только в `~/.claude.json`
(`--scope user`), не в `settings.json`: копию `settings.json` движок VibeMemory возит между машинами,
и токена там быть не должно.

**Другие агенты**, которые читают список MCP-серверов из JSON, — фрагментом
`~/.vibememory/tokens/<команда>/<агент>.mcp.json`: сослаться на него или перенести из него сервер в
конфигурацию агента, которая лежит у владельца учётки и никуда не синхронизируется. Не в конфигурацию
проекта: она уезжает с репозиторием.

Токен не показывают агенту и не вставляют в чат: всё, что попало в сессию, остаётся в её транскрипте.

## 5. Как агент работает с памятью команды

- Сервер на хосте не видит каталога агента, поэтому запись называет проект сама: `memory_save`,
  `memory_update` и `memory_delete` требуют `project`. `project_resolve` отвечает списком проектов,
  которые токену можно.
- Токен «Read only» только читает. Токен с выбранными проектами видит и пишет только их.
- У команды с истёкшим сроком чтение работает, а запись отвечает отказом с адресом кабинета, где срок
  продлевают.
- Запись с токеном агента внутри не пишется — ни этого токена, ни чужого.
- Всё, что участник записал, видят все участники команды. Удаление участника отзывает его токены.

## 6. Проверить

```bash
vibememory doctor
```

На машине без движка `doctor` начинает строкой `engine   not installed` и перечисляет программы и
токены: `token    <команда>/<агент> tk_… from <кабинет>`. Файл токена, доступный кому-то кроме
владельца, или пропавший файл — ошибка с объяснением и код выхода не 0.

## 7. Отключить

```bash
vibememory disconnect <команда>
```

Снимает с машины токены команды — сами токены, сайдкары и фрагменты — и печатает:

- какие файлы удалены;
- какие токены отозвать и в каком кабинете: до отзыва токен всё ещё открывает команду тому, у кого
  он окажется;
- строку, которая снимает регистрацию Claude Code: `claude mcp remove --scope user
  vibememory-<команда>` — в `~/.claude.json` VibeMemory не пишет, это делает сам человек.

Файл, который положил в каталог команды не `connect`, а человек, `disconnect` не трогает и называет:
откуда он и где его отзывать, программа не знает. Повторный `disconnect` ничего не делает и выходит
с кодом 0.

## 8. Сессии команды

Сессии — полные разговоры с агентом — команда хранит, только когда их включили на её странице в
кабинете: переключатель «Сессии», владелец или админ. Сессии тяжёлые, место у них общее с памятью.

Для сессий на машине нужен движок, а не только программа подключения:

```bash
vibememory install
```

Потом код машины — на странице подключения команды, раздел «Подключить машину», и та же команда:

```bash
vibememory connect --cabinet https://app.vibememory.ru
```

`connect` сам создаёт ключ машины, получает клон команды в `~/.vibememory/stores/<команда>/` и
ставит в нём драйверы слияния. Ваш `~/.ssh/config` он не трогает.

Какие проекты — команды, решаете вы, одной командой на каталог:

```bash
vibememory route add ~/work/acme --to acme
```

`route add` записывает маршрут в раздел `stores` вашего `~/.vibememory/config.json` — путь в том
регистре, как он записан на диске, с `/**`: маршрут берёт и сам каталог, и всё под ним. Остальной файл
не меняется ни на байт. Каталог, уже отданный другой команде, не переотдаётся молча: сначала
`vibememory route remove <каталог>`. `vibememory route list` показывает маршруты,
`vibememory route which [каталог]` — куда уйдёт сессия, открытая в этом каталоге.

- маршрут можно вписать и руками (`"stores": { "acme": { "cwd": ["/Users/me/work/acme/**"] } }`);
  регистр на macOS и Windows неважен, на Linux — важен, а `vibememory doctor` скажет, если каталога
  маски нет, он записан в другом регистре или под маской лежит проект личного стора;
- новые сессии этих проектов уходят в команду;
- старые остаются на машине: `claude --resume` их открывает, в команду они не уходят;
- отдать старую сессию команде — `vibememory session share <id>`;
- перенести проект из личного стора — `vibememory project move <каталог> --to <команда>`: маршрут
  он пишет сам. Обратно — `--to personal`: маршрут снимается, назад возвращается только ваше;
- пока в проекте открыта сессия, перенос отказывает и называет её: сессию на этой машине движок
  узнаёт по процессу агента — закрыли, и перенос проходит сразу. Отметку потерянной машины снимает
  `vibememory session release <машина> <сессия> --confirm`.

Если хост отказал — кончилось место, истекла оплата, вас исключили — отправка встаёт на паузу, чтение
продолжается, и через час движок спрашивает снова. `vibememory doctor` показывает причину и куда идти.
Отказ из-за файла, которого стору команды нельзя, лечится так:

```bash
vibememory store reclone <команда>
```

Когда сессии команды выключили, машина сама выходит из стора на следующем тике: ваши перенесённые
проекты возвращаются в личный стор, клон уходит в архив `~/.vibememory/stores/<команда>.disconnected-…`.
Тем же кончается `vibememory disconnect <команда>`; ключ машины после этого отзовите в кабинете.
