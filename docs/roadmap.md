# Roadmap — VibeMemory

План и хроника. Один чекбокс — одна итерация; по завершении — `[x]` с датой, веткой и сутью.
Архитектура — [spec/architecture.md](spec/architecture.md), концепт — [idea.md](../idea.md).

  живого транскрипта режется по `snapshot_boundary` и уходит в базу объектов через
  `hash-object -w --stdin`; живой файл не индексируется никогда, `git add -A` не используется,
  «грязно» меряется индексом против HEAD (неизменная сессия коммита не создаёт). `live.json` и
  `tails.json` (`lastUuid`, число строк, лист возобновления) пишутся целиком через временный файл;
  битый файл-удобство не роняет хук. Push с дебаунсом 20 с, неудача push'а сессии не сообщается.
  **Замер по ходу:** при ходе, кончившемся ошибкой, `Stop` не срабатывает вовсе — приходит только
  `SessionEnd`, поэтому оба события делают одну работу, иначе сессии с ошибкой не уехали бы
  никогда ([knowledge](knowledge/claudeCode/resumeAndRelocation.md)). 11 тестов, три подделки
  роняют их; проверено вживую: сессия CLI 2.1.258 → ссылка, коммит в сторе, пустой `live.json`
  после конца, `tails.json` с листом.
- [x] **`UserPromptSubmit` — гейт свежести** — ✅ (2026-09-05, next) единственный хук, способный
  остановить человека, поэтому решение чистое (`prompt_gate::decide`) и построено на правиле
  «любое сомнение — пропускать». Блокирует ровно одно: другая машина по своему `tails.json`
  держит **больше** записей этой сессии, чем есть здесь; называет самую дальнюю машину и
  насколько она впереди. Не блокируют: равное число записей (ждать нечего), машина позади,
  нечитаемый или битый `tails.json`, отсутствие конфига, **и своя же машина** — сравнение с самим
  собой блокировало бы каждый промпт живой сессии. Дефект найден на живой проверке по несходящемуся
  числу («99 записей впереди» при 10 локальных): нечитаемый локальный транскрипт считался пустым и
  давал блок — теперь он пропускает. 6 тестов решения плюс живая проверка всех трёх исходов.
- [x] **Relocation транскрипта при смене cwd — измерено** — ✅ (2026-09-04, next) на 2.1.258 в
  изолированном конфиге: `--resume` из другого каталога файл **не переносит** — транскрипт
  остаётся под `enc` исходного cwd, поздние строки несут новый cwd (один файл = два рабочих
  каталога), строки `relocated` нет, а каталог нового cwd создаётся пустым. Значит «сессия
  принадлежит одному cwd» — ложь, и реконсилер обязан это учитывать. `cd` **внутри** живой

- [x] **CRLF: где он оказывается и что ломал** — ✅ (2026-09-10, next) пункт был сформулирован
  неверно («на Mac не проверяется»): Windows — не механизм, механизм — конвертация концов строк
  самим git, и она воспроизводится на Mac одной строкой `.gitattributes`. Замер на git 2.50.1:
  драйверу отдаётся **индекс-форма**, в `%O`/`%A`/`%B` нет ни одного `\r` даже при
  `* text eol=crlf` — то есть `-text` защищает рабочее дерево, а не драйвер, и сквозной гейт
  «драйвер + CRLF» не может упасть (был написан и удалён). Зато конвертируется рабочее дерево, а
  движок читает именно его: личность строки без `uuid` — её байты, поэтому один `\r` давал 16
  строк вместо 12 с двойными `bridge-session`, `queue-operation` и `last-prompt`, а журнал памяти
  (ни одного `uuid` на 16 строк) удвоился бы целиком — молча, без конфликта и счётчика. Правило
  «терминатор — один `\n`» вынесено в `vibememory_core::jsonl`: личность и все сравнения идут по
  строке без `\r`, а в файл отдаются байты как пришли — нормализовать выход нельзя, это уронил
  чужой закон `merge(x,x,x) = x`, и правильно: переписанный в LF checkout остался бы вечно
  «изменённым» против git. Попутно нашлись две фикстуры (`crlfLineKept`,
  `crlfStateLineDuplicated`), которые с `provenance: unverified` записывали дефект как ожидаемое
  поведение и исправно его охраняли — переписаны. Два закона в `merge_properties.rs`, сквозной
  гейт в `migrate_archive.rs`, шесть подделок. Правка `dest_is_union_of` намеренно не сделана:
  её подделка выживает, путь недостижим.
  [knowledge](knowledge/git/lineEndings.md).
