# СЖАТИЕ СЕССИЙ

Решения владельца 26.09.2026: сессии — 99 % объёма команды, память — доли процента.
Сжатие убирает из сессий бессмысленное и экономит место тарифа.
Место в плане — после фазы 5: механическая часть первой, голосование агентов — второй.

---

## 1. Два слоя

Механическое сжатие — правилом, без голосования: повторы и мусор, который узнаётся без смысла.
- повторное чтение того же файла внутри сессии, когда между чтениями файл не менялся
- вывод инструмента сверх порога — остаются начало, конец и отметка «вырезано N КБ»
- файлы `tool-results/`, на которые не ссылается ни одна запись сессии
- сессия, целиком вошедшая в свой форк (`--fork-session` копирует начало в новый файл): записи родителя есть в форке

Обычное продолжение дублей не даёт: `claude --resume` дописывает тот же файл ([knowledge/claudeCode/resumeAndRelocation.md](../knowledge/claudeCode/resumeAndRelocation.md)).

Смысловое сжатие — агентами команды с голосованием: тупиковые ветки разговора и шум, которые узнаются только по смыслу.
Ценные выводы остаются, лишнее вырезается или заменяется кратким пересказом.

## 2. Голосование

1. Владелец или админ запускает сжатие сессии или всех сессий старше N дней кнопкой в кабинете
2. Задача раздаётся подключённым агентам команды через сервер памяти — инструментом MCP
3. Каждый агент читает сессию и присылает предложение: какие записи убрать, какие заменить пересказом
4. Сервер сводит предложения и рассылает их всем агентам на голосование
5. Запись, за удаление которой большинство, уходит; против — остаётся
6. Спорные записи — письмо владельцу и админам, решение кнопками в кабинете
7. Не решили за 7 дней — спорное остаётся как есть

Голосуют агенты, люди только разрешают споры.
Случайного выбора нет: сжатие необратимо, и в споре безопасна потеря места, а не потеря работы.

## 3. Перед применением

Архив исходной сессии уходит владельцу команды письмом, как при отключении команды.
Сжатая сессия обязана оставаться рабочей: Claude Code продолжает её, `claude --resume` открывает её — это гейт.
Живую сессию не сжимают: правило то же, что у `relink` и `project move` — ни одного живого sid на машинах.

## 4. Главная ловушка — слияние возвращает вырезанное

Слияние сессий между машинами — объединение записей по `uuid` ([knowledge/design/jsonlMergeInvariants.md](../knowledge/design/jsonlMergeInvariants.md)).
Запись, вырезанная в одном клоне, вернётся со следующим слиянием любой машины, у которой она осталась.
Поэтому сжатие пишет надгробный список сессии — по образцу `forgotten.json`:
- вырезанные `uuid` — драйвер слияния и тик их не возвращают
- заменённые пересказом `uuid` с хешем новой строки — побеждает сжатая версия, а не исходная
- строки без `uuid` (блок состояния) механическое сжатие не трогает: их кратность — максимум сторон, а не удаление

Слияние с надгробием — новые кейсы `fixtures/merge/`, закон идемпотентности в property-тестах сохраняется.

## 5. Порядок работ

1. Надгробный список сжатия и его уважение драйвером слияния и тиком — фикстуры и property-тесты
2. Механическое сжатие в движке: команда `vibememory compact <sid>`, отчёт «было — стало», гейт `--resume`
3. Кнопка в кабинете для сжатия сессий команды механическими правилами
4. Инструменты MCP для предложений и голосов, сводка на сервере, письма и решение споров в кабинете
5. Документы: спека формата надгробия, мануал «как сжать», каталог возможностей
