# VibeMemory — концепт

## Проблема

Разработчик работает с AI-агентом на нескольких машинах. Сессия, память проекта и история
живут в локальном каталоге агента, ключуются по абсолютному пути и не переезжают. Хочется
закрыть крышку на одной машине, открыть другую и продолжить тот же разговор с той же памятью;
хочется, чтобы память, накопленную Claude Code, видели и другие агенты.

Что есть сегодня (проверено 2026-09-02, [knowledge](docs/knowledge/README.md)):

- **Anthropic нативно этого не даёт.** Remote Control — окно в живой процесс на исходной
  машине; «Continue in Web» — новая облачная сессия из сводки, односторонняя; `/desktop` —
  та же машина; auto memory официально machine-local.
- **Облачные папки (OneDrive и подобные) — не транспорт.** Дегидрация (932 из 1751 файлов
  стора cloud-only), конфликт-копии вместо слияния, ссылки уезжают текстовыми файлами,
  `+R` ломает `mkdir`, ленивый синк при закрытой крышке. Desktop, не найдя транскрипт, навсегда
  стирает привязку к сессии — 20 из 165 дескрипторов уже испорчены.
- **GAIM** (gaim.tech) — MCP-SaaS с командной памятью: только факты, не сессии; без
  self-hosting; приватные факты уезжают третьей стороне.

## Продукт

**Память и сессии, которые ходят за вами между машинами и агентами.** Три слоя, один стор:

1. **Движок `vibememory`** — один бинарь (Rust) под macOS/Windows. Хуки Claude Code
   (`SessionStart` / `UserPromptSubmit` / `Stop` / `SessionEnd`) + фоновый тик. Транспорт — git с
   приватным remote: детерминированное слияние транскриптов по `uuid`, полная история
   (ничего не теряется тихо), никаких reparse-точек и дегидрации. Ссылки
   `projects/<путь>` → стор создаются автоматически, ритуалов нет: `bootstrap` один раз на
   машину.
2. **MCP-сервер памяти** — `memory_search / get / save / update` поверх того же стора. Любой
   MCP-клиент (Claude, Claude Code, Codex, Gemini CLI, Cursor, Zed, Cline) читает и пишет одну
   память. Транскрипты остаются форматом своего агента, но доступны как поиск по истории.
3. **SaaS для команд** — кабинет, команды, роли, биллинг (start0). Несколько людей на одном
   проекте не отличаются от одного человека на двух машинах — фундамент тот же.

## Принципы

- **Локально-first, self-hosted.** Данные на своём хосте; облачный сервис — опция, не условие.
- **Ничего не теряется тихо.** Git-история как второй слой; конфликт памяти — keep-both в
  карантин с подсказкой «сведи», никогда «новее побеждает»; удаление файлов движком — только явной
  командой (удаление записи внутри транскрипта самим Claude Code — воля писателя, слияние его
  уважает, кроме записей, на которых держится ветвь другой машины).
- **Память — это записи**, а не файлы: `id`, тип, время, автор-агент, проект. Markdown-файлы
  Claude Code — проекция записей, а не первоисточник. Иначе командный и мультиагентный режимы
  не собираются.
- **Сессии — формат конкретного агента.** Продолжить сессию может тот же агент; остальным —
  поиск.
- **Горячее per-machine остаётся на машине.** `.claude.json`, ключи, pid-реестр, кэши не
  покидают машину — у них нет переносимого содержимого, а история порчи есть.
- **Одновременная работа на двух машинах — норма**, не исключение: межмашинный heartbeat,
  гейт свежести перед промптом, union-слияние как штатный режим.
- **Никаких ритуалов.** Перенос репозитория по новому пути, новая машина, новый агент — всё
  либо автоматически, либо одной командой.
- **Заменяемость.** Когда Anthropic даст нативную кросс-девайс сессию, движок должен
  сниматься одной командой без потери данных.

## Не-цели первой версии

- Слияние транскриптов разных агентов в один разговор.
- Шифрование стора на стороне клиента (приватность = приватность remote).
- Мобильный клиент.

## Происхождение

Родился 2026-09-02 из задачи «сделать `~/.claude` общим между машинами» в сессии VibeSweep:
исследование 17 агентов (нативные возможности, раскладка каталога, стор Desktop, практика
сообщества → три независимых дизайна → девять судей → синтез). Сырые отчёты —
[docs/knowledge/research/](docs/knowledge/research/).
